# AgentLite 双任务对照实验设计

## 一、设计目的

本实验用于回答一个面向多智能体运行时的核心问题：

> 在不修改业务程序主要协作逻辑的前提下，AgentLite 能否通过结构化状态引用、
> 受治理共享记忆和接收方视图，减少重复上下文传输，同时保持连续任务的交付质量、
> 事实一致性与可追溯性？

实验不是比较两个业务应用，而是用两个语义结构明显不同的连续任务，检验同一套
通用运行时机制。任务组 A 关注偏好、约束与方案的连续修订；任务组 B 关注证据、
来源与结论的连续修订。生产代码不识别任务编号、固定角色或业务领域。

## 二、问题设计原则

### 1. 连续任务而非孤立问答

每个任务组由十个前后依赖的阶段组成。后续阶段会引用、补充或推翻早期事实，
用于观察上下文增长、历史复用、过期信息处理和最终成果完整性。

### 2. 双领域互补

| 设计维度 | 任务组 A：旅行规划 | 任务组 B：合成安全审计 |
|---|---|---|
| 核心对象 | 用户偏好、预算、行程方案 | 告警线索、证据来源、审计结论 |
| 主要变化 | 新增约束、预算收紧、天气变化 | 线索补充、来源修订、证据失效 |
| 关键风险 | 忘记偏好、使用旧预算、交付不完整 | 证据链断裂、使用过期线索、结论不可追溯 |
| 最终成果 | 可执行旅行手册与修订说明 | 可审计报告、证据链与决策日志 |
| 运行时能力 | MemoryView、约束修订、最终交付守卫 | StateRef、来源跨度、冲突消解、生命周期治理 |

这种组合避免只在单一领域验证系统，也避免将旅游词汇或安全实体写入运行时规则。

### 3. 可冻结、可复现

任务输入、角色配置、执行顺序、模型参数、预注册阈值和本地合成资料在运行前固定。
所有运行使用独立实验编号、记忆作用域和输出目录，防止历史结果污染新实验。

### 4. 成本与质量同时评价

实验不以缩短回答或减少任务轮次换取 Token 下降。通信成本、Provider 用量、
交付质量、记忆正确性和可靠性分别记录，不能用某一项替代其他门禁。

## 三、任务组设计

### 任务组 A：约束持续变化的个性化旅行规划

用户在十轮协作中逐步提出旅行偏好、目的地筛选、行程编排、预算核算、同行人
健康限制、天气变化、预算收紧和饮食需求。系统最终需要交付一份可执行的旅行手册，
并说明关键修订如何影响原方案。

该问题重点检验：

- 长任务链中的偏好与硬约束是否被稳定保留；
- 新约束是否能精确替代旧事实，而不是与旧方案并存；
- Planner、Writer、Reviewer 是否只接收各自需要的上下文；
- 最终交付是否完整覆盖路线、预算、风险和备选方案。

详细展示版见[任务组 A 问题设计](../problems/A.md)，逐轮实验输入见
`experiments/ordinary-developer-autogen/question_A.md`。

### 任务组 B：证据持续修订的合成安全审计

系统从一条本地合成告警出发，经过网络观测、载荷备注、账本路径、实体聚类和
合规规则等多跳资料，逐步形成审计结论。中途会引入被污染或被废弃的线索，要求
系统修订证据关系并在最终报告中给出可追溯来源。

该问题重点检验：

- 多跳证据能否以状态引用传递，避免重复搬运长日志；
- 事实、来源、关系和结论是否保持分离；
- 被修订或废弃的线索是否停止影响后续判断；
- 最终结论是否能追溯到有效证据和对应处理阶段。

详细展示版见[任务组 B 问题设计](../problems/B.md)，逐轮实验输入见
`experiments/ordinary-developer-autogen/question_B.md`。

## 四、对照组设置

| 运行组 | 启动方式 | 数据面行为 | 实验用途 |
|---|---|---|---|
| Native | 直接运行 AutoGen | 保持原生消息传递 | 主基线 |
| Observed | AgentLite 观察模式 | 记录指标但不改写消息 | 分离模型波动与接管钩子影响 |
| Managed | AgentLite 托管模式 | 启用状态引用、视图和共享记忆 | 被测方法 |

三组保持以下条件一致：

- 相同任务输入和本地资料；
- 相同模型、温度、最大轮次和重试策略；
- 相同 Agent 角色、系统提示和执行顺序；
- 相同最终交付要求和盲评量表；
- 不设置有利于某一组的输出长度上限。

每个任务组、运行组和独立重复使用新的目录及不可变运行绑定。A、B 两个领域的
共享记忆相互隔离。

## 五、评价指标

### 1. 成本指标

- Provider Prompt、Completion 与总 Token；
- Agent 间直接消息 Token；
- Prompt View 与 MemoryView Token；
- 控制模型、重试与回退成本；
- 端到端协作 Token 和任务时延。

Provider 计费 Token 与运行时通信 Token 分开报告，评审模型成本也单独记录。

### 2. 质量指标

- 任务完成度；
- 当前约束与事实保持；
- 正确性和内部一致性；
- 清晰度、可执行性和最终成果完整性；
- 任务组 A 的方案修订正确性；
- 任务组 B 的证据链完整性与来源可追溯性。

候选答案先匿名冻结，再由质量评审和技术评审分别打分。综合分采用更保守的结果，
避免单一评审掩盖约束错误。

### 3. 状态与记忆指标

- StateRef 和结构化状态的真实产生与消费；
- 记忆查询、命中、注入和有效采用；
- 错误记忆命中与过期事实使用次数；
- 冲突、修订和废弃关系的处理结果；
- 最终输出中的有效事实覆盖与来源跨度。

### 4. 可靠性指标

- 改写失败和安全回退；
- 当前任务保真失败；
- 协议标记或路由元数据泄漏；
- 完整交付数量；
- 实验绑定、报告、归档和 SHA256 完整性。

## 六、公平性与验收

实验阈值在 Provider 调用前写入预注册文件，不根据结果回调门槛。正式规模实验覆盖
A1-A10 与 B1-B10，并要求至少进行独立重复后再讨论运行间波动。

验收遵循以下原则：

1. 成本下降与质量非劣必须分别成立；
2. 中间审查意见不能冒充最终交付；
3. 题目中出现某类状态名称，不等于运行时已经生成该状态；
4. 失败运行保留证据，但不包装成通过结果；
5. 固定任务结果只证明相应实验边界，不外推为所有领域的普遍结论。

## 七、能力映射

| 实验挑战 | AgentLite 机制 |
|---|---|
| 完整历史反复进入消息 | StatePool、StateRef、接收方 Prompt View |
| 长任务中的高价值事实复用 | 候选池、记忆准入、任务级 MemoryView |
| 新事实替代旧事实 | CanonicalClaimCandidate、修订关系、Conflict Resolver |
| 来源和结论混淆 | 精确 source span、Schema Registry、Semantic Validator |
| 评审意见截断最终成果 | 类型化评审事件、Final Delivery Guard |
| 改写异常影响原程序 | 契约校验、安全回退、不可变实验绑定 |
| 成本口径不完整 | 通信、检索、控制、重试、Provider 与评审分账 |
