# AgentLite 质量整改记录

## 记录范围

本文记录真实模型重复对照中暴露的质量风险，以及随后完成的通用机制整改。
历史实验结果保持原样；本文件不把未重新运行的 Provider 结果写成通过，也不把
单次诊断外推成跨领域结论。

## 已确认的历史质量缺口

`v5.15z` 正式重复基准的两次完整重复显示：

- Managed 的端到端通信 Token 减少，但 Provider Token、质量和完整交付没有同时
  达到预注册门禁；
- 任务组 A 的托管组质量和交付低于 Native，任务组 B 的托管组 Provider 用量
  反而增加，质量和交付也下降；
- 记忆命中后仍有大量记录处于“未评估”状态，不能把“被检索”当作“被有效采用”；
- 第三次重复在技术评审阶段中断，缺少完整 B 组证据，不能用于证明生产根因；
- 评审器格式重试、Provider/网络和编排中断必须与 AgentLite 产品质量分开记录。

因此，当前公开结果只能说明两次完整重复范围内的通信统计，不能声称真实模型下
质量非劣或 Provider 成本下降。

## 本轮已完成的通用修复

### 1. 作用域与语义相关性分离

此前记忆检索把“同一组标签”计入较高相关性分数，可能使正文与当前任务没有
语义重叠的历史记录进入上下文，增加无效记忆和未评估记忆。现在：

- 必需作用域只作为安全边界，不再单独构成相关性；
- 普通严格检索必须与当前查询存在词项重叠；
- 空查询不会自动注入整组历史；
- 只有运行时识别到明确的连续任务依赖，才显式开启作用域历史复用；
- 检索报告记录被语义过滤拒绝的数量和是否使用作用域专用路径。

该修复位于通用 `MemoryStoreLite`、协作内核和 AutoGen 接管路径，不包含任务组、
角色或业务领域词表。

### 2. 安装自检与真实 Token 计数对齐

此前 `agentlite doctor` 只检查 `tiktoken` 能否导入，不能发现编码表首次加载
需要本地缓存或网络资源的情况。现在 `doctor` 还会实际初始化 TokenCounter；如果
编码资源不可用，会明确报告失败。正式基准仍禁止把估算 Token 当作真实 Provider
或通信 Token。

## 当前验证状态

- 记忆、候选与 AutoGen 相关定向回归：已通过；
- Python 3.11 AutoGen 环境完整测试：607 项中 604 项通过，3 项因当前环境无法
  下载 `tiktoken` 编码资源而阻塞；这是环境资源缺口，不是业务断言通过；
- 编译检查：已通过；
- Provider 重复基准：本轮未重新启动，历史失败门禁仍保留；
- 质量整改尚未获得新的真实模型 A/B 因果证据。

## 下一项证据

待具备可复现的 tokenizer 缓存和安全 Provider 凭据后，使用新的隔离实验目录，
只复验共享记忆开关和跨任务记忆相关性；需要同时报告 Provider Token、通信 Token、
质量、交付完整率、有效/错误/未评估记忆以及重复间方差。只有消融、重复结果和
事实旅程共同支持通用因果，才继续修改生产代码。
