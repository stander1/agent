# v5.15w Package Release Hardening

## Evidence boundary

The v5.15v post-commit holdout passed the generic semantic bridge, but that
does not prove the same implementation is present in an independently
installed distribution. The first v5.15w package preflight built and inspected
the wheel successfully, then failed both installed AutoGen smokes because the
release gate still assumed every Team input must be rewritten.

The runtime correctly kept the native Team message when the candidate Prompt
Views were larger than the native broadcast. Requiring mutation in that case
would violate the cost guard and current-task fidelity contracts.

## General repair

v5.15w changes the release contract rather than the runtime:

- classify Team takeover as either `applied_rewrite` or
  `cost_guarded_fallback`;
- accept a rewrite only when it mutates the internal message and reduces both
  task and broadcast token cost;
- accept a fallback only when `token_not_reduced` is recorded, no real message
  mutation occurs, and the native caller-visible message remains free of
  internal protocol markers;
- apply the same contract to the installed mixed Team/Core smoke while still
  requiring Core request and reply Prompt Views;
- require the wheel to contain the semantic bridge, claim extraction,
  conflict resolution, schema registry, controlled disambiguation, typed
  event, and final-delivery modules;
- require `pyproject.toml`, `agent_runtime.__version__`, and wheel metadata to
  agree on `0.5.15.dev0`.

This does not add domain vocabulary, task-specific parsing, fixed role
behavior, or a path that bypasses the normal runtime guards.

## Acceptance

The openEuler gate builds and installs the wheel outside the source tree, runs
both installed AutoGen smokes, runs the complete source release gate and unit
suite, verifies package contents and version identity, records the system
fingerprint, and archives the complete evidence with SHA256.
