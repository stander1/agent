# v5.15w 软件包发行加固

## 证据边界

v5.15v 提交后的 holdout 验收证明了通用语义桥通过，但这不能证明同一实现
已经进入独立安装的发行包。首次 v5.15w 软件包预检成功构建并检查了 wheel，
随后两个已安装 AutoGen 冒烟测试均失败，原因是当时发行门禁仍假设所有 Team
输入都必须发生改写。

当候选 Prompt View 大于原生广播时，运行时正确保留了原生 Team 消息。在这种
情况下强制改写会违反成本保护和当前任务保真契约。

## 通用修复

v5.15w 修改发行契约，不修改运行时：

- 将 Team 接管结果分类为 `applied_rewrite` 或 `cost_guarded_fallback`；
- 仅当改写改变内部消息，并同时降低任务和广播 Token 成本时接受改写；
- 仅当记录 `token_not_reduced`、未发生真实消息变更，并且调用方可见的原生
  消息中不含内部协议标记时接受回退；
- 对已安装的 Team/Core 混合冒烟测试应用相同契约，同时仍要求 Core 请求和
  回复 Prompt View；
- 要求 wheel 包含语义桥、claim 提取、冲突消解、Schema Registry、受控消歧、
  类型化事件和最终交付模块；
- 要求 `pyproject.toml`、`agent_runtime.__version__` 与 wheel 元数据中的
  版本统一为 `0.5.15.dev0`。

该变更不增加领域词表、任务专用解析、固定角色行为，也不增加绕过常规运行时
保护机制的路径。

## 验收

openEuler 门禁在源码目录之外构建并安装 wheel，运行两个已安装 AutoGen
冒烟测试，执行完整源码发行门禁和单元测试，校验软件包内容与版本一致性，
记录系统指纹，并将完整证据连同 SHA256 一并归档。
