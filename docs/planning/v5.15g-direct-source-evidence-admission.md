# v5.15g Direct Source Evidence Admission

## Failure evidence

The first v5.15f integrated AutoGen preflight observed twelve successful
state-to-memory bridge attempts but zero active memories and zero injections.
The semantic proposals were evidence-valid. They remained pending because all
business-agent messages were intermediate outputs with conservative admission
scores, while the team result intentionally exposed no textual final-delivery
marker and therefore remained unvalidated.

Raising every intermediate output above the admission threshold would also
admit later unsupported model statements. Removing the final-delivery guard
would regress the existing protection against review text being treated as a
final artifact. Neither is acceptable.

## Generic repair

v5.15g adds a separate path for direct evidence supplied by a framework:

```text
framework source
  -> source_evidence_state
  -> required controlled disambiguation
  -> exact SourceSpan validation
  -> Schema Registry
  -> Conflict Resolver
  -> normal Memory Admission
```

AutoGen supplies the current user task through this path after retrieval for
the current team call. The newly admitted fact can therefore support agents in
that call and later calls without changing the already-frozen retrieval view
for the team boundary.

The runtime does not infer authority from an Agent name or domain vocabulary.
The framework adapter explicitly identifies the native user-task boundary.
Other adapters can use the framework-neutral kernel entry point for equivalent
direct sources.

## Required control mode

User tasks frequently mix quoted evidence, constraints, and commands.
Deterministic extraction can produce a coarse candidate spanning the entire
instruction. The new `control_required` policy:

- discards coarse deterministic candidates for that mixed source;
- requires the bounded semantic proposer even when deterministic extraction
  returned a candidate;
- accepts only strict JSON proposals with exact unique source quotes;
- sends every proposal through the existing local semantic validator, dynamic
  Schema Registry, conflict resolver, and admission policy;
- fails closed when the control provider is unavailable, invalid, or over
  budget.

The control model still cannot write memory directly.

## Preserved safeguards

- Intermediate Agent output scores are unchanged.
- A team result without typed delivery or the exact final marker still cannot
  enter long-term memory through the final-output path.
- Review text does not gain delivery authority.
- Group isolation, current-task fidelity, memory adoption checks, and token
  accounting remain active.
- Rejected source evidence remains available in audit state but produces no
  prompt-visible memory.

## Acceptance

Targeted tests cover:

- precise controlled extraction replacing a coarse deterministic candidate;
- failed control extraction not falling back to the coarse candidate;
- direct source evidence being absent from the already-prepared current team
  retrieval, admitted through normal memory governance, and available to the
  next team task;
- all existing AutoGen shared-memory and semantic-disambiguation regressions.

The next real-provider integrated run must additionally observe active source
memory, cross-task injection, supported output, no wrong-memory attribution,
and complete disjoint Provider/control/transport accounting.
