# v5.15c Real Provider Semantic Preflight

## Purpose

v5.15b proved the controlled semantic proposal mechanism with scripted
responses. v5.15c adds the first real-Provider gate without returning to a
frozen Question A/B workload.

## Evidence model

An external scenario file is authored after the implementation commit and
bound to that exact hash. It contains at least five unrelated domains. The
Provider proposes open semantic candidates; local code remains authoritative
for exact quote location, source hash, schema resolution, conflict handling,
and memory admission.

The complete Provider response is retained for audit. Prompts, headers, and
credentials are excluded from the record. Provider usage and control usage
refer to the same call and therefore enter end-to-end cost exactly once.

## Cost model

```text
end_to_end_tokens
  = provider/control tokens
  + communication tokens
  + retrieved-memory tokens
  + retry tokens
```

For this isolated preflight, communication, retrieval, and retry-generation
tokens are zero. Provider retry count and latency remain separately visible.
The stage establishes a measured control-path baseline, not a Token-reduction
claim.

## Quality model

A case is a strict success only when:

1. the real control path is called exactly once;
2. the response passes strict JSON and exact-source validation;
3. the candidate passes normal semantic, schema, conflict, and admission
   gates;
4. the admitted Claim matches preregistered predicate aliases, operator,
   value, unit, and temporal status.

At least 80% of the cross-domain cases must be strict successes, all Provider
usage fields must be available, no locally invalid candidate may enter memory,
and the accepted preflight must have no Provider retry whose failed-attempt
Token usage is unobservable.

## Boundary

This stage does not modify production parsing rules, does not add domain
vocabulary, and does not compare Native/Observed/Managed groups. Passing it
allows a subsequent integrated AutoGen preflight; it does not by itself prove
formal quality noninferiority or Token savings.
