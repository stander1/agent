# v5.15a Generic Semantic Bridge

## Scope

This stage replaces benchmark-shaped semantic patches with an evidence-first
bridge that is independent of AutoGen role names and application domains.
It does not claim that arbitrary prose can be understood deterministically.
Ambiguous prose remains unresolved or audit-only.

The production path is:

```text
framework state or artifact
  -> CanonicalClaimCandidate
  -> exact SourceSpan validation
  -> layered Schema Registry
  -> generic Conflict Resolver
  -> ClaimCard / MemoryView
```

The reliability path is:

```text
artifact metadata
  -> ArtifactRef(scope, task, version, hash)
  -> ReviewDecisionEvent
  -> DeliveryEvent
  -> exact validated artifact resolution
```

## Claim Boundary

`CanonicalClaimCandidate` is an open assertion. Its predicate is preserved
instead of being guessed into a known business slot. The deterministic
extractor accepts only cross-domain structures:

- JSON scalar fields;
- explicit key-value fields;
- Markdown table cells;
- generic number, unit, comparison, negation, date, temporal, and revision
  forms.

Every candidate carries an exact source offset, quote, and hash. A candidate
cannot reach dynamic schema registration until its source span, value, unit,
operator, and revision target have been revalidated.

Legacy domain extractors are compatibility candidate providers only. They are
disabled by default in `MemoryPromotionCompiler` and cannot bypass semantic
validation or memory admission.

## Schema Layers

1. Core slots are stable AgentLite concepts.
2. Developer slots are optional declarations supplied by an integration.
3. Dynamic slots preserve validated open predicates as `slot.open.*`.

Dynamic registration means "this exact predicate has validated evidence". It
does not mean that AgentLite inferred a business meaning for the predicate.
Unstructured or invalid assertions remain unresolved.

## Conflict Rules

The generic resolver does not select a winner by confidence or recency for
`ccf.v3` claims.

- Equivalent claims merge their evidence.
- Historical and future claims are not active.
- Explicit supersession can replace an exact prior value or identity.
- Compatible numeric constraints coexist.
- Incompatible assertions remain `unresolved`; they are not prompt-safe.

## Typed Reliability Events

The reserved AutoGen message metadata namespace is
`metadata.agentlite_reliability`. Visible prose is never parsed as a typed
event.

```json
{
  "agentlite_reliability": {
    "schema_version": "agentlite.reliability.v1",
    "artifacts": [
      {
        "artifact_id": "artifact-17",
        "version": 2,
        "content_hash": "sha256:...",
        "source_id": "author-node",
        "scope_id": "team-scope",
        "task_id": "task-42"
      }
    ],
    "review_events": [
      {
        "event_id": "review-9",
        "target": {
          "artifact_id": "artifact-17",
          "version": 2,
          "content_hash": "sha256:...",
          "source_id": "author-node",
          "scope_id": "team-scope",
          "task_id": "task-42"
        },
        "decision": "approve",
        "sequence": 1,
        "actor_id": "quality-node"
      }
    ],
    "delivery_events": [
      {
        "event_id": "delivery-4",
        "artifact": {
          "artifact_id": "artifact-17",
          "version": 2,
          "content_hash": "sha256:...",
          "source_id": "author-node",
          "scope_id": "team-scope",
          "task_id": "task-42"
        },
        "status": "validated",
        "sequence": 1,
        "actor_id": "quality-node",
        "approved_by_event_id": "review-9"
      }
    ]
  }
}
```

Authority comes from the runtime capability profile for the actual actor, not
from names such as planner, writer, or reviewer. Hash, version, scope, task,
evidence spans, event order, and explicit supersession are validated before an
event can mutate memory or select a final artifact.

Legacy review-text inference remains observable for diagnostics, but it is
mutation-disabled by default. The compatibility environment variable
`AGENTLITE_AUTOGEN_LEGACY_TEXT_REVIEW_MUTATION=1` is an explicit opt-in and is
not used by the v5.15a acceptance.

## Acceptance Boundary

The v5.15a gate uses deterministic cross-domain and semantic-transformation
checks plus a post-implementation external holdout. It verifies:

- exact source fidelity and tamper rejection;
- arbitrary actor names and runtime capability authority;
- wrong hash, cross-scope replay, cross-task replay, and out-of-order rejection;
- explicit conflict resolution and unresolved unsafe conflicts;
- validated delivery of the exact approved artifact;
- default-off legacy mutation;
- zero hidden Provider or control-LLM calls in this deterministic gate.

Passing v5.15a proves these mechanisms and their openEuler compatibility. It
does not by itself prove end-to-end quality or token reduction for every
application domain.
