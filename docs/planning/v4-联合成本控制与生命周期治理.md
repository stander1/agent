# v4：联合成本控制与生命周期治理

## 1. 版本定位

v4 的目标是避免“成本转移”。

如果系统只是把长文本消息换成 memory_id 或 state_id，但下游 Agent 仍然频繁读取完整 raw content，就不是真正低开销。

本版本重点是：

```text
控制发什么；
控制存什么；
控制读什么；
控制何时升级访问；
控制控制模块自身的 LLM/规则开销。
```

## 2. CMJCC-v4

新增：

```text
LLM Budget Controller
Access Escalation Governor-lite
Typed Artifact Digest 增强
Context-Pruned Retry Budget
Readiness Barrier-lite
Cold Archive 简化版
Raw Access Metrics
```

访问层级：

```text
metadata
summary
key_points
evidence_snippets
compressed_view
raw_span
full_raw
```

默认不允许直接 full_raw。

Context-Pruned Retry 在 v4 进入预算控制：

```text
max_format_retry_per_output = 1
max_retry_input_tokens = 800
retry_context_allowed_fields =
  broken_control_header
  schema_errors
  task_id
  agent_role
  action_completed
  artifact_digest
  target_schema
```

禁止把完整 Artifact 放入 retry 输入，避免格式修复成本被长正文放大。

## 3. SHP-State-v4

新增：

```text
State Admission Control 增强；
Read Lease-lite；
State GC 简化版；
Retry-Carried State 简化版；
failure_state 压缩；
state_tombstone；
state_reuse_score。
```

大 payload backend 增强：

```text
file_ref:
  默认稳定实现。

mmap_ref:
  v4 推荐实现，用于大日志、embedding array、工具产物片段。

shared_memory_ref:
  可作为 v5 演示或 v6 完整实现。
```

GC 原则：

```text
有下游依赖的状态不删；
已晋升为记忆的状态保留 lineage；
大 artifact 转 cold；
失败重试状态保留短窗口；
删除时留下 tombstone。
```

Read Lease-lite 必须与 State GC 同步实现：

```text
1. Agent 读取状态必须通过 State Access API；
2. read_state 开始时在内存 LeaseRegistry 中 active_readers += 1；
3. read_state 结束或异常退出时 active_readers -= 1；
4. GC 发现 active_readers > 0 时，只能标记为 COOLING 或 EVICT_PENDING；
5. 只有 active_readers = 0 且超过 grace period，才允许物理删除 payload；
6. 删除后保留 tombstone，避免 state_ref 直接变成静默 404。
```

Read Lease-lite 的工程约束：

```text
active_readers 属于高频运行时计数，比赛版默认不把每次加减都写入 SQLite；
AgentRuntime 进程内使用 threading.Lock / RLock 保护 LeaseRegistry；
SQLite 只记录 lease 事件日志、状态 tombstone 和阶段性快照；
如果后续需要多进程 Runtime，共享 lease 表必须启用 WAL、busy_timeout 和短事务。
```

v4 不必实现完整 fencing token，但必须避免“Agent 正在读取，GC 刚好删除”的 TOCTOU 竞态，也要避免读租约本身把 SQLite 写锁打爆。

## 4. TLC-Memory-v4

新增：

```text
Lifecycle Status
Lifecycle-Aware Retrieval
Versioned MemoryRef
Read-Set Validation 简化版
Preflight Validation-lite
Superseded 保守触发
Deprecated 不进入普通 Prompt View
```

生命周期状态：

```text
provisional_active
active
dormant
superseded
deprecated
deleted
```

Preflight Validation-lite 在高成本生成前执行：

```json
{
  "agent_id": "writer",
  "task_id": "task_001",
  "estimated_generation_cost": {
    "tokens": 4000,
    "latency_sec": 30
  },
  "read_set": [
    {
      "memory_id": "mem_001",
      "version_id": 3,
      "status": "active"
    }
  ]
}
```

校验规则：

```text
memory_ref 必须仍然存在；
version_id 未变化；
status 允许进入 Prompt View；
不能是 deprecated / deleted / unresolved_conflict；
不能处于 pending_lifecycle_update；
失败时先 refresh memory view，而不是让 WriterAgent 生成完整报告后再整段回滚。
```

v4 只实现生成前校验，不实现完整 Section-Level Dependency Map 和 Patch Regeneration；这些放到 v6。

## 5. 指标

端到端协作总成本必须作为核心指标，而不是附加说明：

```text
end_to_end_collaboration_cost =
  direct_message_tokens
+ prompt_view_tokens
+ retrieved_memory_tokens
+ control_llm_tokens
+ retry_tokens
```

报告中需要同时展示总成本和拆分项，避免只展示“Agent 间通信 token 降低”而被质疑 cost shifting。

```text
raw_access_count
summary_access_count
evidence_snippet_access_count
access_escalation_count
direct_message_tokens
prompt_view_tokens
retrieved_memory_tokens
control_llm_calls
control_llm_tokens
context_pruned_retry_count
retry_input_tokens
retry_tokens
end_to_end_collaboration_cost
state_gc_count
read_lease_acquire_count
read_lease_blocked_gc_count
sqlite_lock_retry_count
state_tombstone_count
memory_status_transition_count
stale_read_detected_count
preflight_validation_count
preflight_block_count
```

## 6. 验收标准

```text
1. 指标能区分消息成本、状态读取成本、记忆读取成本和控制成本；
2. 下游 Agent 默认读取 summary / Prompt View，而不是 full raw；
3. raw access 次数可统计、可解释；
4. 记忆状态会影响检索和 Prompt View；
5. deprecated / superseded 记忆不会被普通 Agent 当成当前事实使用；
6. State GC 不会物理删除 active_readers > 0 的状态；
7. WriterAgent 高成本生成前必须执行 Preflight Validation-lite；
8. 格式重试受 token 和次数预算限制，不能继承完整 Artifact；
9. Read Lease-lite 的热路径不依赖 SQLite 高频写锁；
10. 实验报告必须展示 end_to_end_collaboration_cost，而不是只展示直接消息 token。
```
