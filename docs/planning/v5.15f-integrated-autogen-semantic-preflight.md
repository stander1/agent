# v5.15f Integrated AutoGen Semantic Preflight

## Purpose

v5.15c proved the closed semantic proposal contract against a real Provider.
v5.15f checks the same control path inside a real AutoGen collaboration rather
than another isolated Claim example.

## Generic boundary

The production runtime does not know the test domain or require named roles.
The task chain and team capability descriptions are external, post-commit
inputs. The acceptance gate explicitly rejects the historical
Planner/Writer/Reviewer test names so the evidence exercises dynamic capability
profiles.

The test runner resets native AutoGen state between tasks while preserving the
same team object and AgentLite memory scope. Continuity must therefore be
visible through the AgentLite state-memory bridge, retrieval, injection, and
downstream adoption records. The external task requirements check output
grounding without adding production vocabulary.

## Evidence and cost

The integrated archive retains every business-agent output and its Provider
usage. Semantic control responses remain represented by evidence-bound
ClaimCandidates in the AgentLite trace; the preceding v5.15c archive retains
their complete raw Provider responses.

The cost ledger keeps disjoint categories:

```text
provider_total
  = team_provider_tokens + control_provider_tokens

transport_without_control
  = collaboration_runtime_tokens - control_provider_tokens

accounted_end_to_end
  = provider_total + transport_without_control
```

This prevents the same control call from being counted once as Provider work
and again inside collaboration runtime cost.

## Gate

Passing requires:

- external inputs bound to the exact implementation commit;
- arbitrary capability names and active AutoGen hooks;
- all tasks and complete Agent outputs preserved;
- required semantics retained after native team resets;
- an observed, accepted, and costed semantic control call;
- state-memory promotion and real memory injection;
- downstream memory-supported output;
- no wrong-memory attribution, task-fidelity failure, protocol leak, or
  unmetered retry;
- complete disjoint Provider and transport accounting.

Passing permits a small comparative Native/Observed/Managed preflight. It does
not itself prove quality noninferiority or Token savings.
