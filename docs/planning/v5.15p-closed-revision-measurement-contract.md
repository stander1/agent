# v5.15p Closed Revision Relation and Measurement Contract

## Evidence

The post-commit v5.15o holdout `20260728-225101` failed before memory
admission in a previously unseen cryogenic instrumentation scenario. The
archived trace established two protocol-level causes:

- the control producer emitted an undeclared nested relation field and the
  strict parser rejected the revision candidate with
  `relation_has_unknown_fields`;
- an exact numeric measurement such as a signed number followed by a unit was
  proposed as one string, so the admitted predecessor was not represented as a
  typed number plus unit.

These observations are frozen evidence from one scenario. They are not treated
as proof about every domain and no scenario vocabulary is added to production
code.

## Generic repair

`ControlledSemanticDisambiguator` now publishes the complete nested relation
object contract. A relation may contain only `relation_type`, `target_value`,
and `target_candidate_id`; a Provider proposal must leave the internal ID
empty. Unknown nested fields remain fail-closed, while diagnostics expose only
bounded, sanitized field names.

The same producer contract now requires numeric measurements to separate the
signed numeric literal from the adjacent unit. Deterministic structure parsing
and controlled proposals share one complete-measurement grammar; that grammar
captures the sign as part of the value and no longer accepts a numeric prefix
while silently discarding trailing descriptive text. Local validation may
repair a Provider formatting error only when all of these conditions hold:

1. the proposed value is a complete single numeric-literal-plus-unit form;
2. that exact combined value occurs exactly once in the validated source span;
3. a separately proposed unit is empty or exactly agrees with the parsed unit;
4. the form is not a range, comparison, descriptive string, date, or boolean.

The repair removes numeric comma separators, preserves sign and exponent, and
records `locally_normalized_candidate_count` plus a distinct candidate schema
status. Unit disagreement fails closed. Descriptions and ranges remain strings.

## Authority boundary

The control model remains a proposal component. It cannot choose internal
candidate IDs, admit memory, resolve conflicts, or create source evidence.
Exact source-span validation, schema registration, predecessor binding,
Conflict Resolver, ClaimCard, and MemoryView remain local authorities.

No Question A/B identifiers, Agent role names, known benchmark entities,
domain vocabulary, or domain-specific regular expressions are introduced.

## Acceptance

The release gate requires:

- strict protocol and measurement normalization unit tests;
- a real-shaped revision chain that creates one typed active claim, one typed
  historical predecessor, a bound `supersedes_value` relation, and a MemoryView;
- local regression and openEuler regression;
- a new post-commit external holdout in a domain not present in the
  implementation or tests, with immutable archive and SHA256 verification.
