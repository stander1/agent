# v5.15u Semantic Output Boundary

## Failure evidence

The post-commit v5.15t holdout completed and archived successfully, but passed
only 37 of 38 checks. Its open candidate extractor received audit-rendered
text in the form `source: content`, so an otherwise exact open predicate became
part of an outer transport predicate. Delivery, memory continuity, zero-retry
provider execution, and legacy-parser isolation all passed.

## General repair

Memory attribution now projects semantic output from decoded AutoGen message
objects:

- `content_text` is the semantic payload;
- `source` remains transport and audit metadata;
- trace rendering may still include `source: content`;
- no agent name, predicate, domain, unit, or value is stripped by a text rule;
- undecodable values retain the existing routing-metadata-sanitized fallback.

The projection prefers content from the current agent source, then non-user
model content, then the last decoded content. Memory guard rewrites continue to
operate on the native result content and are not weakened.

## Acceptance boundary

The v5.15u mechanism gate inherits every v5.15t check and additionally requires
all observed memory-attribution events to declare
`attribution_surface=decoded_model_content_v1`. A post-commit external holdout
must still show:

- at least one `open_candidate_exact` match;
- zero legacy-domain attribution candidates;
- preserved revision, typed-context, cost, retry, and delivery gates.

Passing this gate proves the transport/semantic boundary for the tested
holdout. It does not claim universal cross-domain coverage.
