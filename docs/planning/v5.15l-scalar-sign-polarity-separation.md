# v5.15l Scalar Sign and Logical Polarity Separation

## Evidence

The post-v5.15k spectrograph holdout completed all three tasks with exact
signed measurements and correct current-versus-archived status. Shared memory
was retrieved and injected six times, but downstream adoption remained
unassessed.

The admitted claim stored value `-18.7` with `operator=eq` and
`polarity=negative`. Adoption then treated the numeric sign as a negated
assertion and excluded the exact value observed in every downstream output.

## Generic Invariant

Canonical Claim polarity is logical assertion polarity:

- `operator=ne` maps to `polarity=negative`;
- every other canonical comparison operator maps to `polarity=positive`;
- numeric signs remain part of the scalar value;
- boolean `false` remains a scalar value and is not a negated assertion.

The invariant is shared by deterministic extraction, controlled semantic
proposals, explicit Claim promotion, revision guards, and structured adoption
matching. It does not depend on a domain, predicate, unit, task value, or
Agent role.

## Compatibility

Revision guards now carry the canonical comparison operator. For older stored
facts without that field, adoption preserves the previous polarity as a
fallback. For older facts that contain an operator, the operator repairs a
previously conflated scalar-sign polarity during matching without rewriting
the immutable evidence.

## Acceptance Boundary

Tests cover a signed numeric scalar, boolean `false`, and an explicit
not-equal assertion. A new post-commit external holdout is required before the
integrated gate can pass.
