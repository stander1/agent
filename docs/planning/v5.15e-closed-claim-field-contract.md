# v5.15e Closed Claim Field Contract

## Failure evidence

After v5.15d published the canonical enum values, the second real Provider
preflight returned canonical enums in all five responses. Every response also
added a `subject` field that the strict local parser intentionally does not
allow, so no proposal reached memory admission. One response additionally
encoded the literal adjective in the evidence as a boolean.

## Generic repair

The control prompt now publishes the complete per-claim field allowlist and
explicitly forbids subject, scope, task/source identifiers, and memory
instructions. It also requires the value and unit to preserve the literal
semantic value in the exact evidence quote, rather than changing a descriptive
value into a boolean.

The local parser is not relaxed. Unknown fields and rewritten unsupported
values continue to fail closed. No output cleanup, domain synonym table, or
benchmark-specific alias is added to production.

## Acceptance

The failed v5.15c evidence remains immutable. A new implementation commit must
pass local and openEuler protocol tests, a post-commit mechanism holdout, and a
different post-commit real-Provider scenario set.
