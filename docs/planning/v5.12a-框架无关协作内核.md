# v5.12a：框架无关协作内核

## 1. 版本目标

把三线治理能力从当前自研 Agent 调度循环中分离出来，为 AutoGen、LangGraph、CrewAI 等 Driver 提供统一调用边界。

本版本不接入任何外部 Agent 框架，也不实现全局 Patch。

## 2. 责任边界

```text
宿主框架 / Custom Runtime:
  Agent 定义；
  模型和工具；
  发言和调度顺序；
  终止条件；
  最终交付流程。

CollaborationKernel:
  会话命名空间；
  MemoryContext 准备；
  接收前角色化状态视图；
  Agent 输出契约处理；
  状态写入；
  SHP 交接；
  通信门控和成本记录。
```

## 3. 公开对象

```text
AgentDescriptor
KernelSession
MemoryContext
PreparedAgentInput
ProcessedAgentOutput
CollaborationKernel
FrameworkAdapter
```

## 4. Kernel 事件入口

```python
kernel.open_session(...)
kernel.prepare_memory_context(...)
kernel.before_agent_receive(...)
kernel.validate_agent_output(...)
kernel.after_agent_output(...)
kernel.write_agent_state(...)
kernel.build_handoff(...)
kernel.finalize_task(...)
kernel.close_session(...)
```

`after_agent_output()` 是未来框架 Adapter 的组合入口：

```text
输出契约处理
→ 状态提取与写入
→ ProcessedAgentOutput
```

当前 `V0Runtime` 为保持原有 Final Schema 修复和异步 Memory Admission 时序，分别调用输出校验和状态写入入口。

## 5. 兼容策略

现有代码仍然可以访问：

```text
runtime.state_pool
runtime.memory_store
runtime.communication_gate
runtime.control_budget
```

这些属性已经是 `runtime.kernel` 所有组件的兼容别名，不再由 `V0Runtime` 重复创建。

## 6. 验收条件

```text
1. Kernel 不导入 DeterministicAgent；
2. Kernel 不导入任何外部 Agent 框架；
3. Fake Framework Adapter 能独立调用完整接收、输出、状态和交接链；
4. V0Runtime 与 Kernel 共用同一 StatePool / MemoryStore；
5. 原有核心测试保持通过；
6. 不改变现有 AB 实验口径和最终输出。
```
