# v5.15i Model-Visible Protocol Boundary

## Evidence

The post-v5.15h integrated holdout completed all three grounded tasks and
recorded supported memory adoption without a wrong-memory event. Its only
failed gate reported model-visible protocol markers.

The trace separated two generic causes:

- receiver hydration included runtime labels and the compact SHP envelope in
  the text sent to the model;
- team output accounting inspected the internal rewritten transcript before
  restoring the original user task for the caller.

Neither cause depends on a benchmark domain, task vocabulary, or fixed role.

## Change

- Runtime receiver identity, capability metadata, semantic action, state
  references, memory references, and SHP envelopes remain available in trace
  and audit records.
- The model-visible receiver text contains only the current task, evidence
  requirements, the selected capability prompt view, admitted memory, and
  relevant upstream content.
- Streamed and non-streamed team results are restored before output
  accounting, state extraction, and caller delivery.

## Boundary

This change does not weaken the protocol-marker gate and does not hide a
positive count in reporting. It removes transport metadata from the
model-visible and caller-visible surfaces while preserving it in auditable
non-text state.
