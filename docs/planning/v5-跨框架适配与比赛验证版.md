# v5：跨框架适配与比赛验证版

## 1. 版本定位

v5 是比赛主交付版本。

本版本目标：

```text
把三线机制整合成可运行、可复现、可评测的跨框架多 Agent 运行时工具层；
在 openEuler 24.03-LTS-SP3 上完成部署和实验；
用数据证明相对纯文本协作降低通信开销、任务时延和重复计算。
```

## 2. 运行时结构

```text
AutoGen / Custom Agents / Future LangGraph
  ↓
Adapter Layer
  ↓
Multi-Agent Collaboration Runtime
  ├── CMJCC
  ├── SHP-State
  ├── TLC-Memory
  └── Evaluation Harness
```

## 3. 跨框架范围

比赛版必须实现：

```text
CustomAgentAdapter:
  用于稳定实验和无外部框架演示。

AutoGenAdapter:
  用于证明可接入主流 Agent 框架。
```

系统技术展示要求：

```text
IPC / Socket:
  至少展示 Adapter 与 Runtime 的 Transport 边界；
  推荐提供一个本地 Socket Gateway 或 AgentWorker demo。

向量检索:
  TLC-Memory 必须使用语义检索后端或明确的轻量向量索引。

非文本状态传递:
  StatePool 至少展示 file-ref；
  推荐展示 mmap_ref 大 payload 传递。

CodeAct:
  如时间允许，提供 Python 沙箱执行 demo，输出 artifact_state 和 failure_state。
```

文档预留：

```text
LangGraphAdapter
OpenAI Agents SDK Adapter
CrewAI Adapter
```

不建议比赛版强行全部实现。

## 4. 双模式对比

### baseline_text_mode

```text
Agent 直接传自然语言长文本；
完整中间结果进入下游 prompt；
无 state_refs；
无 MemoryView 复用。
```

### runtime_optimized_mode

```text
Agent 输出 Control Header + Artifact Body；
Agent 间传 SHP；
控制头异常时使用 Context-Pruned Retry-lite 做一次短上下文修复；
中间结果进入 State Pool；
SHP 携带 state_refs；
下游通过 State Access API 获取 Prompt View；
State GC 通过 Read Lease-lite 避免读取中删除；
高价值结论进入 TLC-Memory；
WriterAgent 长生成前执行 Preflight Validation-lite；
后续任务复用 MemoryView。
```

## 5. 必须完成的比赛要求映射

```text
不少于 3 个 Agent:
  Planner / Retriever / Writer / Reviewer。

结构化通信:
  CMJCC Output Contract + SHP。

非文本状态传递:
  Runtime State Pool + state_refs + Prompt View；
  至少展示 embedding_state、retrieval_state、artifact_state 三类状态。

共享记忆:
  Claim Card + MemoryView + lifecycle retrieval。

2 组连续任务:
  机制分析任务组 + 代码执行报告任务组。

10 轮稳定运行:
  benchmark_runner 自动执行并导出 trace。

性能数据:
token/字符、消息数、状态传递次数、记忆命中率、耗时。
  必须包含 end_to_end_collaboration_cost 和 useful_memory_hit_rate。

鲁棒性守卫:
  Context-Pruned Retry-lite、Read Lease-lite、Preflight Validation-lite 必须在比赛版启用。
```

## 6. 报告导出

必须自动生成：

```text
metrics.json
metrics.csv
trace.jsonl
experiment_report.md
cost_breakdown_chart.png 或 cost_breakdown.html
```

报告包含：

```text
系统架构；
运行环境；
任务集；
baseline 与 optimized 对比；
通信开销；
状态复用；
记忆命中；
成本拆解堆叠图；
格式重试、读租约、Preflight 拦截统计；
10 轮稳定性；
局限性和未来工作。
```

成本拆解图必须至少区分：

```text
baseline_text_mode:
  direct_text_tokens

runtime_optimized_mode:
  handoff_packet_tokens
  prompt_view_tokens
  retrieved_memory_tokens
  control_llm_tokens
  retry_tokens
```

报告中需要同时展示：

```text
end_to_end_collaboration_cost
end_to_end_cost_reduction_rate
total_cost_reduction_rate
direct_message_reduction_rate
retrieved_memory_tokens
control_overhead_tokens
raw_access_count
useful_memory_hit_rate
wrong_memory_hit_count
memory_supported_output_count
```

这样可以证明系统不是只把 Agent 间文本成本转移到共享记忆读取，而是在端到端协作成本上真正下降。

## 7. openEuler 要求

```text
Python 3.11；
依赖写入 requirements.txt 或 pyproject.toml；
路径不能写死 Windows；
脚本支持 bash；
SQLite / JSONL / local files 可配置；
README 写清 openEuler 24.03-LTS-SP3 部署流程。
```

## 8. 验收标准

```text
1. openEuler 上可安装、运行、测试；
2. baseline_text_mode 与 runtime_optimized_mode 同任务对比；
3. 至少 3 个 Agent 协作；
4. 结构化通信、状态池、共享记忆都真实参与；
5. 至少 2 组关联连续任务；
6. 不少于 10 轮稳定运行；
7. AutoGenAdapter 能跑最小示例；
8. 实验报告能证明通信开销、重复计算和记忆复用改善；
9. 10 轮运行中结构化输出异常不会直接中断流水线；
10. State GC 不会删除正在读取的状态；
11. 高成本长生成前有 Preflight Validation-lite，避免提交后整段回滚；
12. 报告包含成本拆解堆叠图，显式展示没有 cost shifting；
13. 报告包含“非文本状态传递机制实现说明”，覆盖生成、传递、接收、使用四步；
14. 记忆复用指标必须包含 useful_memory_hit_rate 和 wrong_memory_hit_count。
```
