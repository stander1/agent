# v5.15d Control Protocol Contract

## Failure evidence

The first real Provider preflight reached all five control calls and recorded
complete usage with no retries. Four valid JSON responses used natural-language
schema values such as `state`, `is`, `equals`, `numeric`, `factual`, and
`present`. The local validator rejected all of them before memory admission.
One separate call returned a sanitized Provider error.

The failure was not domain extraction. The control prompt named fields but did
not state the canonical enum values those fields must use.

## Generic repair

The production prompt now derives its protocol contract from the same enum
sets enforced by the local parser:

- assertion type;
- comparison operator;
- value type;
- polarity;
- modality;
- temporal status;
- relation type.

It also requires an open `lower_snake_case` predicate, the response schema
version, and an exact unique source quote. The local parser remains strict:
there is no silent synonym conversion, domain dictionary, or direct memory
write.

## Why this is not a benchmark patch

The repair does not mention any evaluation question, role, domain, entity,
expected answer, or scenario value. It closes a producer-consumer protocol
mismatch by making the existing machine contract visible to every control
Provider.

## Acceptance

The change must pass local protocol tests, the openEuler mechanism gate, and a
new post-commit external real-Provider preflight. The failed preflight remains
archived and is not overwritten.
