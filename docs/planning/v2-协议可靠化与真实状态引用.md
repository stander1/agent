# v2：协议可靠化与真实状态引用

## 1. 版本定位

v2 在 v1 完整闭环上增强可靠性。

本版本重点是：

```text
让结构化通信可校验、可修复；
让 state_refs 指向真实状态对象；
让 memory_refs 有版本和检索语义；
避免系统只是“传 ID 的 demo”。
```

## 2. CMJCC-v2

新增：

```text
Agent Output Contract
Control Header + Artifact Body
Output Contract Guard
Typed Artifact Digest 简化版
Capability Router 简化版
```

Agent 输出格式：

```text
<CMJCC_CONTROL>
{ short JSON control header }
</CMJCC_CONTROL>

<ARTIFACT>
long result / code / table / log
</ARTIFACT>
```

Contract Guard 处理：

```text
提取控制头；
规则修复 JSON；
Schema 校验；
默认值补全；
失败时 fallback wrapper；
记录 schema_valid_rate 和 repair_success_count。
```

fallback wrapper 不能掩盖协议错误。它只能生成 degraded message，不能把坏输出标记为 schema_valid。

fallback 输出必须类似：

```json
{
  "schema_valid": false,
  "contract_status": "degraded_fallback",
  "action": "unknown_or_untrusted",
  "artifact_ref": "artifact_019",
  "allowed_next_step": "review_or_retry_only"
}
```

系统可以继续保存 Artifact，避免流水线直接崩溃，但不能把该控制头当作可信协议继续自动传播。

## 3. SHP-State-v2

StatePool 从简单 dict 升级为 SQLite + 文件 payload：

```text
states
state_payloads
state_artifacts
state_access_logs
```

SQLite 使用约束：

```text
必须沿用 v1 的 WAL + busy_timeout 配置；
状态 payload 不直接塞入 SQLite 大字段，优先存本地文件并保存 payload_ref；
state_access_logs 可以批量写入；
active_readers 这类高频读租约计数暂不进入 SQLite 热路径，后续 v4 由内存 LeaseRegistry 管理。
```

Payload backend 预留：

```text
file_ref:
  v2 默认实现。

mmap_ref:
  v4 起用于大 artifact / embedding payload。

shared_memory_ref:
  v5/v6 可作为系统技术亮点演示。
```

StateRef 必须包含：

```json
{
  "state_id": "state_001",
  "state_type": "retrieval_state",
  "version": 1,
  "payload_kind": "structured_non_text",
  "contains_embedding_refs": false,
  "usage_hint": "summary_context_selection"
}
```

v2 起必须明确展示真实非文本或半结构化状态，而不是只把文本存库后传 ID。

至少实现三类状态对象：

```text
embedding_state:
  query_embedding_id
  chunk_embedding_ids
  vector_dim
  similarity_scores

retrieval_state:
  chunk_ids
  source_ids
  score_map
  evidence_rank

artifact_state:
  code_artifact_id
  stdout_ref
  stderr_ref
  file_path
  sha256
```

非文本状态传递实现说明必须写入系统报告：

```text
生成:
  Retriever / Executor 生成 embedding、chunk score、artifact metadata。

传递:
  SHP 只携带 state_ref，不携带完整文本和大 payload。

接收:
  下游 Agent 通过 State Access API 读取状态。

使用:
  Prompt View Renderer 按 Writer / Reviewer / Planner 角色裁剪视图。
```

Prompt View Renderer 需要按角色裁剪：

```text
WriterAgent:
  少量证据片段 + 结论摘要。

ReviewerAgent:
  更多 source pointer + score。

PlannerAgent:
  任务完成状态 + 缺口摘要。
```

## 4. TLC-Memory-v2

MemoryRef 加入版本：

```json
{
  "memory_id": "mem_001",
  "version_id": 1,
  "status": "active"
}
```

记忆检索支持：

```text
关键词；
标签；
简化语义相似度。
```

记忆写入从自由文本升级为 Claim-lite：

```json
{
  "claim_id": "claim_001",
  "summary": "SHP 可以降低直接文本传递。",
  "subject": "multi_agent_communication",
  "slot_id": "slot.system.optimization_claim",
  "confidence": 0.86,
  "status": "provisional_active"
}
```

## 6. 验收标准

```text
1. Agent 输出被拆成控制头和正文；
2. 控制头错误不会导致系统崩溃；
3. state_ref 能解析到真实 payload；
4. Prompt View 明显小于完整 state payload；
5. memory_ref 能检索、解析和进入 Prompt View；
6. baseline_text_mode 与 runtime_mode 指标可对比；
7. 至少展示 embedding_state、retrieval_state、artifact_state 三类真实非文本/半结构化状态；
8. fallback wrapper 产生 degraded message，不能计入 schema_valid。
```
