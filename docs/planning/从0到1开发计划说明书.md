# 跨框架多 Agent 低开销运行时：从 0 到 1 开发计划说明书

## 1. 文档目标

本文档用于指导项目从空目录开始，逐步搭建出一套符合第九题要求的跨框架多 Agent 低开销协作运行时系统。

最终系统定位：

```text
一个面向多 Agent 协作的跨框架运行时工具层。
它不替代 AutoGen、LangGraph 等 Agent 框架，而是在这些框架之下提供统一的结构化通信、非文本状态传递、共享记忆复用和评测能力。
```

最终比赛交付目标：

```text
1. 在 openEuler 24.03-LTS-SP3 上可安装、运行、测试；
2. 支持不少于 3 个 Agent 协作；
3. 同时支持纯文本协作模式和运行时优化模式；
4. 实现结构化通信、非文本状态传递、共享记忆复用；
5. 至少 2 组关联连续任务；
6. 稳定运行不少于 10 轮；
7. 输出通信开销、状态传递、记忆命中、耗时和成本拆解实验报告；
8. 提供完整源码、系统设计文档、部署文档、实验报告和演示视频。
```

## 2. 总体建设路线

项目采用“三线并行加深”的迭代方式，而不是先做完一个方案再接下一个方案。

从第一版最小完整系统开始，就同时具备：

```text
CMJCC-lite:
  最小结构化通信和成本观测。

SHP-State-lite:
  最小状态池、state_refs 和 Prompt View。

TLC-Memory-lite:
  最小记忆写入、检索和复用。
```

后续每个版本都同时增强三条线：

```text
v0: 评测地基和接口预埋
v1: 三线 Lite 最小完整闭环
v2: 协议可靠化和真实状态引用
v3: 记忆复用和连续任务收益
v4: 联合成本控制和生命周期治理
v5: 跨框架适配和比赛验证
v6: 研究增强和系统技术扩展
```

## 4. 基础技术选型

### 4.1 主线技术

```text
语言:
  Python 3.11

结构化数据:
  Pydantic / dataclasses

元数据存储:
  SQLite

运行日志:
  JSONL

大 payload:
  本地文件 file-ref

Token 统计:
  TokenCounter，优先真实 tokenizer

向量检索:
  本地 cosine index / FAISS / Chroma 任选轻量方案

跨框架接入:
  Adapter + Transport 抽象
```

### 4.2 SQLite 要求

从 v1 开始启用：

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;
PRAGMA busy_timeout=30000;
```

工程约束：

```text
1. Python sqlite3 连接 timeout=30.0；
2. 每线程/任务使用独立连接；
3. 事务保持短小；
4. 大 payload 不进 SQLite，只保存 payload_ref；
5. active_readers 等高频运行时计数放内存 LeaseRegistry，不走 SQLite 热路径。
```

### 4.3 赛题鼓励技术映射

```text
IPC / Socket:
  Runtime 与 AgentWorker / Adapter 的接入边界。

共享内存 / mmap:
  StatePool 大 payload backend，可作为 v4/v5 亮点。

向量数据库 / 向量索引:
  TLC-Memory 语义检索和跨任务复用。

WASM / 容器沙箱:
  CodeAct Executor 的可选安全执行环境。

eBPF:
  v6 可选观测增强，不进入核心控制链路。
```

## 6. 开发阶段 1：v0 基线评测与三线接口预埋

### 6.1 目标

先建立可信评测系统，不急着做优化。

v0 要回答：

```text
纯文本多 Agent 协作到底消耗多少 token、多少消息、多少时间？
后续每个版本的收益如何在同一口径下比较？
```

### 6.2 关键模块

```text
eval/token_counter.py
eval/metrics.py
eval/trace_logger.py
eval/benchmark_runner.py
core/runtime.py 的最小 stub
adapters/custom_adapter.py 的最小 stub
```

### 6.3 TokenCounter 实现

优先级：

```text
1. 目标模型官方 tokenizer；
2. HuggingFace AutoTokenizer；
3. tiktoken 兼容 tokenizer；
4. 中英混合估算兜底。
```

每条 token 指标必须记录：

```text
token_count

tokenizer_name
tokenizer_version
```

### 6.4 v0 消息结构预埋

即使 v0 不实际使用状态和记忆，消息指标也要预留：

```json
{
  "state_refs": [],
  "memory_refs": [],
  "cost_report": {
    "direct_text_tokens": 0,
    "prompt_view_tokens": 0,
    "prompt_tokens": 0,
    "retrieved_memory_tokens": 0,
    "control_llm_tokens": 0,
    "retry_tokens": 0,
    "end_to_end_collaboration_tokens": 0
  }
}
```

### 6.5 任务集

任务组 A：

```text
A1: 分析低开销通信；
A2: 分析非文本状态传递；
A3: 分析共享记忆复用。
```

任务组 B：

```text
B1: 检索材料；
B2: 执行简单分析；
B3: 生成报告并审查。
```

### 6.6 验收标准

```text
1. baseline_text_mode 能跑至少 10 轮；
2. 输出 trace.jsonl、metrics.csv、metrics.json；
3. token 统计使用 TokenCounter；

```

## 7. 开发阶段 2：v1 三线 Lite 最小完整闭环

### 7.1 目标

从 v1 开始，系统必须是完整运行时，而不是脚本 demo。

v1 要实现：

```text
CMJCC-lite:
  SHP-lite 和简单路由。

SHP-State-lite:
  StatePool-lite、state_refs、Prompt View。

TLC-Memory-lite:
  MemoryStore-lite、记忆写入和检索。
```

### 7.2 Runtime Kernel

实现：

```python
runtime.register_agent(agent_profile, adapter)
runtime.run_task(task_spec, mode)
runtime.emit_event(event)
runtime.collect_metrics()
```

### 7.3 Adapter 与 Transport

v1 默认使用 in-process transport，但接口预留 IPC / Socket：

```text
Transport.send(packet)
Transport.receive()
Transport.close()
```

实现：

```text
InProcessTransport:
  默认稳定版本。

SocketTransport:
  只预留接口，v5 可演示。
```

### 7.4 CMJCC-lite

实现最小 SHP：

```json
{
  "shp_id": "shp_001",
  "from": "retriever",
  "to": "writer",
  "task_id": "task_001",
  "action": "write_summary",
  "summary": "已完成检索。",
  "parameters": {},
  "state_refs": ["state_001"],
  "memory_refs": []
}
```

### 7.5 SHP-State-lite

支持状态：

```text
retrieval_state
artifact_state
failure_state
```

API：

```python
write_state(payload, state_type, task_id, source_agent) -> StateRef
read_prompt_view(state_ref, agent_role, budget_tokens) -> PromptView
```

大 payload 先保存为 file-ref。

### 7.6 TLC-Memory-lite

API：

```python
write_memory(summary, tags, source_agent, task_topic) -> MemoryRef
search_memory(query, tags=None, top_k=3) -> list[MemoryRef]
render_memory_prompt_view(memory_ref) -> str
```

### 7.7 验收标准

```text
1. 至少 3 个 Agent 通过 Runtime 调度；
2. Agent 间主消息是 SHP-lite；
3. Retriever 写 retrieval_state，Writer 通过 state_ref 读 Prompt View；
4. 第一轮任务写记忆，第二轮任务能检索记忆；
5. baseline_text_mode 与 runtime_lite_mode 可对比；
6. 10 轮连续任务稳定完成。
```

## 8. 开发阶段 3：v2 协议可靠化与真实状态引用

### 8.1 目标

让 v1 的 lite 系统从“能跑”变成“结构可靠”。

### 8.2 CMJCC-v2

实现：

```text
Agent Output Contract
Control Header + Artifact Body
Output Contract Guard
Typed Artifact Digest 简化版
Capability Router 简化版
```

输出格式：

```text
<CMJCC_CONTROL>
{ short JSON control header }
</CMJCC_CONTROL>

<ARTIFACT>
long body
</ARTIFACT>
```

Contract Guard 流程：

```text
1. 提取控制头；
2. 提取 JSON；
3. 去 Markdown 包裹；
4. 修复尾逗号、单引号、布尔值等轻微错误；
5. Schema 校验；
6. 默认值补全；
7. 失败进入 fallback wrapper；
8. 记录 contract_violation。
```

fallback wrapper 只能生成 degraded message，不能把协议错误伪装成合法控制头：

```json
{
  "schema_valid": false,
  "contract_status": "degraded_fallback",
  "action": "unknown_or_untrusted",
  "artifact_ref": "artifact_019",
  "allowed_next_step": "review_or_retry_only"
}
```

### 8.3 StatePool-v2

升级为：

```text
SQLite metadata + file payload ref
```

表：

```text
states
state_payloads
state_artifacts
state_access_logs
```

预留 backend：

```text
file_ref
mmap_ref
shared_memory_ref
```

v2 必须至少展示三类真实非文本/半结构化状态，避免 StateRef 只是文本 ID 包装：

```text
embedding_state:
  query_embedding_id、chunk_embedding_ids、vector_dim、similarity_scores。

retrieval_state:
  chunk_ids、source_ids、score_map、evidence_rank。

artifact_state:
  code_artifact_id、stdout_ref、stderr_ref、file_path、sha256。
```

StateRef 需要包含 payload 语义：

```json
{
  "state_id": "state_001",
  "state_type": "retrieval_state",
  "version": 1,
  "payload_kind": "structured_non_text",
  "contains_embedding_refs": true,
  "usage_hint": "summary_context_selection"
}
```

### 8.4 TLC-Memory-v2

实现：

```text
Versioned MemoryRef
Claim-lite
关键词检索
标签检索
简化语义检索
```

### 8.5 验收标准

```text
1. 控制头错误不会导致系统崩溃；
2. state_ref 能解析到真实 payload；
3. Prompt View 明显小于完整 state payload；
4. memory_ref 可检索、解析、进入 Prompt View；
5. 指标包含 schema_valid_rate、repair_success_count、prompt_view_reduction_rate；
6. 至少展示 embedding_state、retrieval_state、artifact_state 三类真实状态；
7. fallback wrapper 只能进入 review_or_retry_only 路径。
```

## 9. 开发阶段 4：v3 记忆复用与连续任务收益

### 9.1 目标

证明系统不只是单轮少传文本，还能在连续任务中复用状态和记忆。

### 9.2 CMJCC-v3

实现：

```text
Communication Gate
Memory Admission Gate
Memory Access Controller-lite
Context-Pruned Retry-lite
```

Context-Pruned Retry-lite 规则：

```text
只修复控制头；
不重写 Artifact；
不继承完整长正文；
每个输出最多重试 1 次；
失败后 fallback。
```

### 9.3 SHP-State-v3

实现 State-to-Memory 简化桥：

```text
Runtime State
  ↓
Promotion View
  ↓
Claim Card
  ↓
MemoryView
```

### 9.4 TLC-Memory-v3

实现：

```text
Claim Card
Schema Registry 简化版
Alias Mapping Dict
MemoryView
Batch Compaction 简化版
Prompt View / Audit View 分离
```

Slot 对齐优先规则：

```text
1. 标准 slot_id 精确匹配；
2. alias 字典匹配；
3. 字符串归一化；
4. 编辑距离或 token overlap；
5. unresolved_slot。
```

初始 slot 层级必须避免误合并：

```text
slot.user.preference.programming_language
slot.project.implementation_language
slot.runtime.execution_language
slot.system.design_decision
slot.system.failure_pattern
slot.system.reuse_strategy
slot.paper.evidence
slot.project.requirement
```

例如 `coding_lang` 应映射到 `slot.runtime.execution_language`，不能粗暴映射到 `slot.system.design_decision`。

### 9.5 向量检索

v3 开始引入语义检索后端：

```text
本地 cosine index；
或 FAISS；
或 Chroma。
```

如果不用向量库，必须在报告中标记 `retrieval_backend`。

### 9.6 验收标准

```text
1. 后续任务能命中 MemoryView；
2. memory_hit_rate 可统计；
3. 与无记忆模式相比，重复检索或重复总结下降；
4. Audit View 可展开来源；
5. Alias Mapping 能合并同义 slot；
6. 控制头坏格式可通过短上下文 retry 恢复至少一类错误；
7. 能区分 memory_hit、useful_memory_hit 和 wrong_memory_hit。
```

## 10. 开发阶段 5：v4 联合成本控制与生命周期治理

### 10.1 目标

避免系统只是把成本从消息传递转移到状态读取或记忆读取。

### 10.2 CMJCC-v4

实现：

```text
LLM Budget Controller
Access Escalation Governor-lite
Typed Artifact Digest 增强
Context-Pruned Retry Budget
Readiness Barrier-lite
Raw Access Metrics
```

访问层级：

```text
metadata
summary
key_points
evidence_snippets
compressed_view
raw_span
full_raw
```

默认禁止直接 full_raw。

端到端协作总成本公式：

```text
end_to_end_collaboration_cost =
  direct_message_tokens
+ prompt_view_tokens
+ retrieved_memory_tokens
+ control_llm_tokens
+ retry_tokens
```

实验报告必须展示总成本，而不能只展示直接消息 token。

### 10.3 SHP-State-v4

实现：

```text
Read Lease-lite
State GC 简化版
Retry-Carried State 简化版
failure_state 压缩
state_tombstone
```

Read Lease-lite 关键要求：

```text
1. active_readers 放内存 LeaseRegistry；
2. read_state 开始 active_readers += 1；
3. read_state 结束 active_readers -= 1；
4. GC 发现 active_readers > 0 只能标记 COOLING；
5. 不让读租约高频写 SQLite。
```

### 10.4 payload backend

v4 推荐实现：

```text
file_ref:
  默认稳定实现。

mmap_ref:
  用于大日志、embedding array、工具产物。
```

shared_memory_ref 可作为 v5 演示或 v6 完整实现。

### 10.5 TLC-Memory-v4

实现：

```text
Lifecycle Status
Lifecycle-Aware Retrieval
Versioned MemoryRef
Read-Set Validation 简化版
Preflight Validation-lite
Superseded 保守触发
Deprecated 不进普通 Prompt View
```

Preflight Validation-lite 在 WriterAgent 长生成前执行，避免生成后整段回滚。

### 10.6 验收标准

```text
1. 成本指标能区分消息、状态读取、记忆读取、控制开销；
2. raw_access_count 可统计；
3. GC 不删除 active_readers > 0 的状态；
4. WriterAgent 长生成前执行 Preflight；
5. deprecated / superseded 记忆不会进入普通 Prompt View。
6. useful_memory_hit_rate、wrong_memory_hit_count 和 memory_supported_output_count 可统计。
```

## 14. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Token 统计口径不一致 | 实验数据被质疑 | v0 接 TokenCounter，记录 tokenizer 信息 |
| SQLite 写锁 | 运行时中断 | WAL、busy_timeout、短事务、高频计数进内存 |
| LLM 输出 JSON 损坏 | 流水线中断 | Contract Guard + Context-Pruned Retry-lite |
| 只传 ID 但下游读 raw | cost shifting | 访问层级、raw_access_count、成本拆解图 |
| 非文本状态像文本 ID 包装 | 创新性被质疑 | v2 起展示 embedding_state、retrieval_state、artifact_state |
| 状态读取中被 GC 删除 | TOCTOU 崩溃 | Read Lease-lite + tombstone |
| 记忆版本过期导致重写 | token 成本飙升 | Preflight Validation-lite |
| Schema slot 膨胀 | 记忆无法合并 | Alias Mapping Dict + unresolved_slot |
| Slot 误合并 | 记忆污染 | 区分用户偏好、项目事实、运行时语言和设计决策 |
| 记忆命中无效 | 复用收益虚高 | 统计 useful_memory_hit_rate、wrong_memory_hit_count |
| 适配框架过多 | 工程失控 | 比赛版只做 Custom + AutoGen |
| openEuler 环境差异 | 最终无法复现 | 从 v0 起避免 Windows 专属路径，v5 专门验证 |
