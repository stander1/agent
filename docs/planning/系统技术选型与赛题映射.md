# 系统技术选型与赛题要求映射

## 1. 目的

第九题鼓励结合以下系统技术提升实现质量：

```text
IPC
共享内存
Socket
向量数据库
WASM / 容器沙箱
eBPF
CodeAct
```

这些技术不应作为堆砌项，而应服务于本项目的三个核心目标：

```text
低开销通信；
非文本状态传递；
共享记忆复用。
```

## 2. 技术到模块的映射

| 技术 | 是否进入比赛主线 | 对应模块 | 作用 |
| --- | --- | --- | --- |
| IPC | 是 | AgentRuntime / AgentWorker | 隔离 Runtime 与 Agent 执行进程，传递 SHP、状态引用和执行结果 |
| Socket | 是 | Adapter Layer / Framework Gateway | 为 AutoGen、自研 Agent、未来 LangGraph 提供统一接入通道 |
| 向量数据库 / 向量索引 | 是 | TLC-Memory / SHP-State | 记忆语义检索、状态相似度检索、跨任务复用 |
| 共享内存 / mmap | 亮点项 | Runtime State Pool / Artifact Store | 大 payload、embedding、工具产物通过引用传递，避免长文本和重复拷贝 |
| 容器沙箱 / WASM | 亮点项 | CodeAct Executor | 安全执行 LLM 生成的 Python 代码，回传 artifact_state / failure_state |
| eBPF | 答辩增强 | Evaluation Monitor | 采集系统调用、I/O、进程、Socket 等观测指标，不进入核心控制链路 |

## 3. 推荐落地顺序

### v0

```text
不引入复杂系统技术；
只保证路径、配置、日志格式从一开始可迁移到 Linux / openEuler；
建立 tokenizer 和 metrics 口径。
```

### v1

```text
引入 Transport 抽象：
  in_process transport 作为默认实现；
  预留 socket / ipc transport 接口。

引入 SQLite + JSONL + 文件系统：
  SQLite 保存 metadata；
  JSONL 保存 trace；
  文件系统保存 artifact payload。
```

### v2

```text
StatePool 使用 SQLite metadata + file payload ref；
为大状态 payload 预留 mmap / shared memory backend；
Memory 检索先使用轻量 embedding index 或本地向量索引。
```

### v3

```text
TLC-Memory 引入向量检索能力；
支持关键词、标签、语义相似度三种记忆检索方式；
可用 FAISS / Chroma / 简化 cosine index 作为后端。
```

### v4

```text
Runtime State Pool 支持大 payload backend：
  file-ref；
  mmap；
  可选 shared memory。

Read Lease-lite 与 State GC 配合，保证大 payload 读取安全。
```

### v5

```text
比赛交付版至少展示：
  IPC / Socket 接入边界；
  向量检索；
  file-ref 或 mmap 的非文本状态传递；
  CodeAct Executor 的轻量沙箱方案或最小演示。

AutoGenAdapter 优先通过 Adapter API 接入；
如时间允许，提供本地 socket gateway 演示跨框架接入。
```

### v6

```text
增强 eBPF 观测；
增强共享内存 backend；
增强容器 / WASM 沙箱；
增强多进程 IPC 和 Socket Gateway；
不影响 v5 主链路稳定性。
```

## 4. 主线必做与可选增强

### 比赛主线必做

```text
openEuler 24.03-LTS-SP3 可运行；
SQLite / JSONL / 文件系统；
Transport 抽象；
IPC / Socket 接入边界；
向量检索；
file-ref 非文本状态传递；
双模式 benchmark；
自动报告导出。
```

### 比赛亮点建议

```text
mmap 或 shared memory backend；
CodeAct Python 沙箱；
AutoGenAdapter 最小可运行示例；
成本拆解可视化。
```

### 答辩增强

```text
eBPF 观测；
WASM 沙箱；
多进程 AgentWorker；
Socket Gateway；
共享内存大 payload demo。
```

## 5. 不建议的方向

```text
不要把 eBPF 放进核心控制链路；
不要为了共享内存而强行改所有 state payload；
不要承诺 hidden state / KV cache 跨 Agent 传递；
不要把 CodeAct 沙箱做成比赛主链路的硬依赖；
不要引入过重分布式数据库作为比赛版必需组件。
```

## 6. 答辩表述

可以这样解释系统技术路线：

```text
本系统不是只在应用层缩短 prompt，而是将多 Agent 协作拆成运行时基础设施问题。Agent 通过 Adapter 和 IPC/Socket 接入 Runtime；中间状态通过 StatePool 以 file-ref、mmap 或 shared memory backend 管理；共享记忆通过向量索引实现跨任务检索复用；CodeAct 任务通过轻量沙箱隔离执行；运行时指标通过 JSONL、SQLite 和可选 eBPF 观测采集。由此，系统在 openEuler 上形成可运行、可复现、可评测的低开销多 Agent 协作运行时。
```
