# v5.12c：AutoGen Driver 导入钩子

## 1. 版本目标

在 `v5.12b` 已经完成托管启动和 Driver 自动加载的基础上，`v5.12c` 开始实现 AutoGen Python 代码端的透明接入。

本版本不要求用户脚本显式导入 AgentLite，也不要求替换 AutoGen 的 Agent 类。启动方式仍然是：

```powershell
agentlite run --framework autogen -- python app.py
```

如果当前 shell 尚未刷新 editable install，可以使用：

```powershell
python -m agent_runtime.cli run --framework autogen -- python app.py
```

## 2. 接入方式

Driver 在 `sitecustomize` 阶段被加载，早于用户脚本执行。

加载后执行三件事：

```text
1. 安装 AutoGen import hook；
2. 等待用户脚本正常 import autogen_agentchat / autogen_core；
3. AutoGen 目标模块加载完成后，对关键生命周期方法进行透明 wrapper。
```

这里的 wrapper 是“外层包装器”的意思：它记录调用前后事件，但不改变原函数的入参和返回值。

## 3. v5.12c 钩子范围

当前覆盖：

```text
autogen_agentchat.agents:
  on_messages
  on_messages_stream

autogen_agentchat.teams:
  run
  run_stream

autogen_core Runtime 类:
  send_message
  publish_message
```

这些入口对应 AutoGen 中 Agent 接收消息、团队执行、Runtime 传输消息三个层面。

## 4. 与 CollaborationKernel 的关系

AutoGen Driver 不直接写自己的状态池逻辑，而是调用 `CollaborationKernel`：

```text
AutoGen 原生调用
→ Driver wrapper 观测输入
→ CollaborationKernel.before_agent_receive()
→ AutoGen 原函数继续执行
→ Driver wrapper 观测输出
→ CollaborationKernel.write_agent_state()
→ session-local StatePool 写入 artifact_state
→ autogen_driver/trace.jsonl 记录证据
```

这保证 AutoGen 接入不会绕过 SHP-State、状态池和后续三线治理边界。

## 5. 当前边界

可以说：

```text
AgentLite 已经能够在托管 Python 进程中，于用户脚本导入 AutoGen 前安装 AutoGen Driver 钩子；
AutoGen AgentChat / Core 的关键生命周期事件可以被透明桥接到 CollaborationKernel；
Driver 不改变 AutoGen 原生消息对象和返回值。
```

不能说：

```text
已经完成真实 AutoGen 包的端到端最小样例；
已经接管 AutoGen Studio 网页端；
已经替换 AutoGen 的团队广播策略；
已经对所有 AutoGen 版本完成兼容性验证；
已经把 AutoGen 原生消息全部转换成 SHP 控制头。
```

## 6. 下一步

`v5.12d` 应安装真实 AutoGen 依赖后运行最小原生样例，验证：

```text
1. 用户代码不导入 AgentLite；
2. AutoGen 原生返回值不变；
3. bootstrap_status.json 显示 hooks_active=true；
4. autogen_driver/trace.jsonl 出现 receive/output 事件；
5. session-local StatePool 出现 artifact_state；
6. 后续再决定是否将 Team 广播策略替换为 SHP handoff。
```
