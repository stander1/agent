# v5.12b：托管启动与 Driver 加载

## 1. 版本目标

实现以下产品入口所依赖的启动链：

```powershell
agentlite run --framework autogen -- python app.py
```

用户脚本不需要显式导入 AgentLite。目标 Python 解释器在执行 `app.py` 前，自动加载对应 Framework Driver。

本版本只实现 Launcher 和 Driver Loader，不实现 AutoGen 消息 Patch。

## 2. 启动流程

```text
agentlite run
  ↓
校验 framework、cwd、command
  ↓
生成 launch session
  ↓
写入 launch.json
  ↓
构造隔离的子进程环境变量
  ↓
PYTHONPATH 前置 agent_runtime/bootstrap
  ↓
目标 Python 启动
  ↓
自动导入 sitecustomize.py
  ↓
Driver Loader 根据 framework 加载驱动
  ↓
写入 bootstrap_status.json
  ↓
执行用户 app.py
```

## 3. 环境协议

Launcher 向目标进程提供：

```text
AGENTLITE_ENABLED
AGENTLITE_FRAMEWORK
AGENTLITE_SESSION_ID
AGENTLITE_DATA_DIR
AGENTLITE_STATUS_FILE
AGENTLITE_TARGET_CWD
AGENTLITE_RUNTIME_ENDPOINT
AGENTLITE_DRIVER
AGENTLITE_BOOTSTRAP_STRICT
AGENTLITE_BOOTSTRAP_METADATA
```

这些变量属于 Launcher 与 Driver 的内部协议，不要求用户脚本读取。

## 4. Driver 状态语义

```text
active:
  Driver 已经激活真实钩子。

awaiting_v5.12c_adapter:
  Driver 入口已经加载，但框架消息钩子尚未实现。

failed:
  Driver 导入或激活失败，严格模式阻止用户脚本执行。
```

`autogen` 当前返回：

```text
driver=autogen
status=awaiting_v5.12c_adapter
hooks_active=false
```

`probe` 是内部验证 Driver，返回：

```text
driver=probe
status=active
hooks_active=true
```

## 5. 为什么使用 sitecustomize

Python 在正常启动时会自动尝试导入 `sitecustomize`。Launcher 只对其创建的子进程前置专用 bootstrap 路径，因此：

- 不修改系统级 Python；
- 不修改用户源文件；
- 不污染其他终端进程；
- 普通 `python app.py` 仍完全不受影响；
- 代码端和 Python 网页后端可以复用同一启动机制。

如果目标环境原本存在自己的 `sitecustomize.py`，AgentLite 会在 Bootstrap 完成后链式加载它，避免覆盖用户原有 Python 启动配置。

使用 `-S`、`-I`、`-E` 会禁用或绕过该机制，因此 Launcher 会提前拒绝这些参数。

## 6. 失败安全

严格模式下，如果 Driver 不存在、返回类型错误或 Bootstrap 异常：

```text
写入失败状态文件
→ 输出错误原因
→ 退出码 78
→ 用户 app.py 不执行
```

这样可以避免“应用运行成功，但 AgentLite 实际没有接管”的静默失效。
