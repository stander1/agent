# v6：研究增强与系统技术扩展

## 1. 版本定位

v6 是可选增强版本，不是比赛主线必需。

它用于增强系统论文味、答辩深度和后续开源价值。

## 5. 系统技术扩展

可选技术：

```text
Unix Domain Socket / IPC:
  Runtime 与 Agent worker 进程隔离。

共享内存:
  大状态 payload 或 artifact 低拷贝引用。

WASM / 容器沙箱:
  CodeAct 执行隔离。

eBPF:
  只作为观测和统计增强，不作为主控制机制。

FAISS / Chroma / LanceDB:
  替代简化语义检索。
```

v6 的系统技术目标是增强实现质量，而不是改变核心机制：

```text
IPC / Socket:
  从预留接口升级为多 AgentWorker 进程。

shared memory:
  从演示 backend 升级为 StatePool 大 payload backend。

WASM / container:
  从 CodeAct demo 升级为可配置执行沙箱。

eBPF:
  只接入 Evaluation Monitor，采集系统层指标。
```

## 6. 不建议承诺

```text
hidden state / KV cache 跨 Agent 传递:
  API-only 场景不可控，比赛版不应承诺。

完整分布式强一致:
  超出原型范围。

全局冲突扫描:
  成本高，可能抵消低开销目标。

实时全量硬回滚:
  容易导致级联失效。

Linux 内核级改造:
  第九题要求在 openEuler 上运行，不要求改内核。
```
