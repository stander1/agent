# v0：基线评测与三线接口预埋

## 1. 版本定位

v0 不是正式优化版本，而是实验地基。

本版本的重点是：

```text
建立纯文本多 Agent 协作基线；
建立统一指标系统；
在消息结构中预埋 state_ref、memory_ref 和 cost_report 字段；
为后续三条创新线同时演进留出接口。
```

## 2. 最小 Agent 流程

```text
User Task
  ↓
PlannerAgent
  ↓
RetrieverAgent
  ↓
WriterAgent
  ↓
ReviewerAgent / SummarizerAgent
```

至少 3 个 Agent，建议先实现 4 个，便于覆盖规划、检索、生成、审查。

## 3. 三线在 v0 中的形态

### 3.1 CMJCC-v0

只做成本观测，不做控制。

```text
message_count
direct_text_chars
estimated_direct_tokens
prompt_chars
estimated_prompt_tokens
task_latency_ms
agent_call_count
```

v0 必须直接接入 TokenCounter，而不是只靠字符估算。因为 v0 是后续所有版本的评测基线，如果 token 口径一开始就漂移，后续优化数据会很难解释。

TokenCounter 优先级：

```text
1. 目标模型官方 tokenizer；
2. HuggingFace AutoTokenizer 对应开源模型 tokenizer；
3. tiktoken 中与目标 API 模型最接近的 tokenizer；
4. 中英混合估算公式兜底。
```

每条指标必须记录：

```text
token_count
token_count_method = actual | compatible | estimated
tokenizer_name
tokenizer_version
```

如果比赛实验使用 Qwen、Llama、DeepSeek、OpenAI 等不同模型，不能把某一个 tokenizer 的结果伪装成所有模型的真实 token，只能标记为 `compatible` 或 `estimated`。

临时估算规则：

```text
如果文本主要是英文：
  estimated_tokens = ceil(chars / 4)

如果检测到中文字符：
  estimated_tokens = ceil(chars * 1.5)

如果中英混合：
  estimated_tokens = ceil(ascii_chars / 4 + cjk_chars * 1.5 + other_chars / 2)
```

只有在 tokenizer 不可安装、模型 tokenizer 不公开或离线环境不可用时，才允许回退到上述估算公式，并在指标中标记 `token_count_method = estimated`。

### 3.2 SHP-State-v0

只预埋字段，不实际传状态。

```json
{
  "state_refs": [],
  "state_payload_bytes": 0,
  "prompt_view_tokens": 0
}
```

### 3.3 TLC-Memory-v0

只预埋字段，不实际复用记忆。

```json
{
  "memory_refs": [],
  "memory_hit_count": 0,
  "memory_hit_rate": 0.0
}
```

## 4. 两种模式

### plain_text_mode

Agent 间直接传自然语言长文本。

### runtime_stub_mode

结构与后续 runtime 一致，但 state_refs 和 memory_refs 暂为空。

这个模式用于验证后续改动不会破坏 benchmark runner。

## 5. 任务集

至少准备两组连续任务：

```text
任务组 A：多 Agent 机制分析
  A1 低开销通信
  A2 非文本状态传递
  A3 共享记忆复用

任务组 B：代码执行与报告生成
  B1 检索材料
  B2 执行分析
  B3 生成报告并审查
```

## 7. 验收标准

```text
1. 能运行不少于 10 轮任务；
2. 能输出 JSONL trace 和 CSV 指标；
3. 能统计纯文本协作的通信开销；
4. 消息结构已经预留 state_refs、memory_refs、cost_report；
5. v0 就接入 TokenCounter，真实 tokenizer 优先，估算公式只作兜底；
6. 后续 v1 不需要重写评测框架。
```
