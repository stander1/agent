# v5.15s Cross-Source Predecessor Binding

## Frozen evidence

v5.15r proved that typed current/history requests can reach the zero-cost
structured dependency path, but its external holdout failed before the revised
claim entered memory. The control proposal carried a supersession relation whose
old literal was not part of the new claim source span. The bridge rejected that
target before MemoryStore could bind the already admitted predecessor.

A separate audit gap was observed on the team receiver hydration path: applied
rewrites lacked both the common response boundary and the real task sequence
index, so final receiver evidence could not be selected reliably.

## General repair

1. Keep exact source validation for the new claim value, unit, and source span.
2. Reject all externally supplied internal candidate identifiers.
3. Keep non-supersession relation targets source-bound.
4. For supersession only, erase a target value that is absent from the current
   source span and defer identity binding to MemoryStore.
5. Bind only a unique active predecessor with the same semantic key. A missing
   or ambiguous predecessor remains unresolved and cannot win compaction.
6. Apply the response boundary and task sequence audit fields to the team
   receiver hydration path.

This is a validation and ownership-order change, not a vocabulary change. It
adds no question, role, domain, unit, or metric-specific parser.

## Acceptance

The next post-commit holdout must use an implementation-time unseen domain and a
revision sentence that omits the old literal. It passes only when:

- active and historical typed claims have the expected values and unit;
- both claims share a semantic identity;
- the active claim source span does not contain the historical value;
- one supersession relation is bound to the historical claim by local ID;
- one MemoryView contains the active/historical pair;
- all inherited v5.15r context, delivery, cost, protocol, and Provider gates
  pass.
