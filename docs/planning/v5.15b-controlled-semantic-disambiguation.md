# v5.15b Controlled Semantic Disambiguation

## Purpose

v5.15a admits deterministic claims only when JSON scalars, explicit key-value
fields, Markdown tables, or another evidence-preserving structure is present.
That boundary is intentionally conservative. v5.15b adds an optional,
budgeted semantic disambiguation path for unstructured text without making an
LLM response authoritative by itself.

The path is:

```text
unresolved local source
  -> bounded evidence window
  -> controlled LLM JSON proposal
  -> unique quote resolution
  -> exact SourceSpan synthesis
  -> CanonicalClaimSemanticValidator
  -> layered Schema Registry
  -> Conflict Resolver
  -> Memory Admission
```

## Authority Boundary

The control LLM proposes open assertions. It cannot:

- write directly to MemoryStore;
- register a schema slot before source validation;
- select a conflict winner;
- declare a review or delivery event;
- widen scope or task identity;
- cite text outside the supplied evidence window.

Every accepted proposal must contain a quote that appears exactly once in the
original source. AgentLite derives offsets and hashes locally. The candidate
then passes the same value, unit, operator, temporal, relation, schema, and
admission checks as a deterministic candidate.

Malformed JSON, missing or repeated quotes, unsupported operators, invalid
relations, provider errors, exhausted budgets, and source windows above the
configured bound fail closed. The original artifact remains available for
audit.

## Invocation Boundary

Disambiguation is:

- disabled by default;
- invoked only when deterministic extraction produced no usable candidate;
- limited by scope, task, call count, input characters, candidate count, and
  total control tokens;
- configured explicitly by an integration or managed launcher;
- isolated from visible Agent prompts and ordinary Agent completion accounting.

No application vocabulary, benchmark identifier, fixed role name, business
entity, or known numeric threshold is part of the implementation.

## Cost Evidence

The runtime records, per task:

- control LLM call count;
- control prompt, completion, and total tokens;
- provider latency and retry count when available;
- accepted and rejected proposal counts;
- rejection reasons and whether deterministic extraction was attempted first.

Control tokens remain a separate term in end-to-end collaboration cost:

```text
direct communication
+ prompt views
+ retrieved memory
+ control LLM
+ retries
```

## Acceptance

Before any new formal benchmark run, v5.15b must pass:

1. local unit tests with a fake completion client;
2. malformed, tampered, repeated-quote, cross-task, budget, and replay cases;
3. semantic transformations over multiple unrelated domains;
4. a post-implementation holdout not present in production code or tests;
5. openEuler mechanism acceptance;
6. a small real-Provider preflight that reports control cost and output
   quality without changing the frozen historical A/B evidence.

Passing the mechanism gate proves bounded proposal and validation behavior. It
does not prove universal natural-language understanding.
