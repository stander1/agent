# v5.15q Explicit Typed Context Retention

## Frozen failure evidence

The post-commit v5.15p archive `20260728-233810` admitted the correct typed
state but failed the final delivery. Its MemoryView contained an active numeric
fact, one typed superseded predecessor, and a separate active boolean fact.
The final task explicitly requested the current and immediately preceding
states plus the boolean flag without restating any value.

Trace inspection established a runtime boundary failure rather than a domain
parser failure:

- historical expansion ran and was charged in the session report;
- two MemoryRefs were retained for the team rewrite;
- the role view selected only the current numeric fact and its revision guard;
- the historical fact and related boolean fact were absent from every final
  receiver's model-visible context;
- the Provider therefore returned unresolved fields.

The archived output remains unchanged. Re-running its verifier only corrects a
metric-name compatibility error and does not convert the failed run into a
pass.

## Generic repair

`build_minimal_context_view` now treats explicit typed evidence as an atomic
semantic requirement when the current query requests it. Identifier terms are
split on structural separators for relevance matching, so an open slot such as
`slot.open.some_predicate` can match natural task terms without a domain
vocabulary. A paired current/history request preserves each semantically relevant
`historical_fact` and the corresponding active fact by typed slot identity.
Other active facts cross the normal budget only when their open identifiers or
structured fields overlap the current task.

This is a bounded exception to compaction, not a return to full transcript
broadcast. Unrelated memories continue through capability scoring and the
normal token budget. Explicitly requested typed facts may make the role view
exceed its nominal budget, which is recorded by the existing view metrics.

The supersession protocol is also centralized as one shared relation set:
`supersedes_value`, `supersedes_claim`, and `supersedes_candidate`. Controlled
proposals, local predecessor binding, revision classification, conflict
resolution, and acceptance verification consume the same set. Provider-created
internal IDs remain forbidden; local evidence and the admitted semantic
identity remain authoritative.

## Evidence gate

The v5.15q verifier extends v5.15p with trace-level evidence. External inputs
must declare at least one additional typed fact beyond the revision pair. For
every configured receiver in the final task, the verifier accepts only
structured `active_fact` and `historical_fact` records from an applied
`autogen_agent_input_real_rewrite` audit event and checks typed value, unit,
status, and fact kind. Output text and pre-rewrite receive events are not proof
that injection reached the model.

The openEuler gate requires:

- generic relation, context selection, AutoGen memory, and verifier regressions;
- a clean tracked worktree and post-commit external scenario/team binding;
- zero Provider transport retries for the accepted holdout;
- complete output semantics, typed MemoryView state, bound predecessor relation,
  model-visible typed context for every receiver, and field-fetch cost;
- immutable archive creation and SHA256 verification.

## Boundary

No Question A/B identifier, fixed role name, benchmark entity, domain term,
value, unit, or domain regular expression is added to production code. Existing
compatibility parsers remain outside this evidence claim. A passing v5.15q
archive demonstrates one unseen typed-context chain, not universal semantic
coverage or formal cost-quality noninferiority.
