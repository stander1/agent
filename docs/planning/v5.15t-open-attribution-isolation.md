# v5.15t Open Attribution Isolation

## Problem

Memory admission already uses open canonical candidates by default, while output-quality attribution still called the legacy domain extractor. That left useful/wrong memory evidence dependent on frozen vocabularies and allowed equal values from unrelated fields to be misattributed.

## Change

- Parse current-task and output evidence with `extract_canonical_claim_candidates`.
- Bind evidence by open predicate, normalized value, unit, and logical polarity.
- Accept exact predicate matches and structurally prefixed predicate matches without naming any domain.
- Suppress value-only fallback when the same value and unit are structurally assigned to another predicate.
- Keep literal fallback only when no structured candidate owns the value.
- Emit `ccf_v3_open_candidate_evidence`, open candidate counts, and an explicit zero legacy-candidate count.
- Let the adoption guard repair both v3 evidence and archived v2 evidence.
- Keep the legacy domain extractor disabled in the default promotion compiler.

## Non-goals

This revision does not add vocabularies for budget, destination, latency, capacity, roles, or the frozen A/B questions. It does not treat a passing frozen scenario as cross-domain proof. It does not alter admitted ClaimCard identities or conflict resolution policy.

## Acceptance

1. Unknown predicates are attributed while a patched legacy extractor raises on every call.
2. Equal values and units assigned to different predicates do not create stale-memory hits.
3. Negative structured evidence does not fall through to positive literal attribution.
4. Default promotion remains independent of the legacy extractor across unrelated sample domains.
5. Current v3 evidence is repairable by the adoption guard and archived v2 evidence remains readable.
6. The full local and openEuler suites pass, followed by a post-commit holdout in an unseen domain.
