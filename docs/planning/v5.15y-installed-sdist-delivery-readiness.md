# v5.15y Installed sdist and Delivery Readiness

## Evidence-driven scope

The immutable v0.5.15rc1 gate passed wheel installation, complete source
release checks, full unit tests, wheel/sdist content inspection, and artifact
hash verification. A follow-up audit found two release-surface gaps:

1. the sdist was inspected but not installed by the formal gate;
2. the current competition delivery guide still described an early
   pre-AutoGen and pre-openEuler implementation.

## Generic repair

The artifact builder now installs the generated sdist into an isolated target
without dependencies or build isolation. A probe running outside the checkout:

- imports `agent_runtime` from the target;
- compares runtime, distribution, and project versions;
- invokes the installed `agentlite version` entry point;
- verifies all required wheel-contract members in the installed tree.

This is a distribution-level contract. It does not contain task identifiers,
fixed role names, domain vocabulary, value patterns, or semantic admission
logic.

## Delivery surface

The current delivery guide records installation, verification, evidence
boundaries, credential handling, and the unresolved repository-license
decision. Package metadata adds source and issue URLs plus non-legal
classifiers. No license classifier or license text is inferred.

## Acceptance

The openEuler gate must pass the inherited RC checks and explicit installed
sdist checks. Technical readiness and public open-source publication readiness
remain separate results.
