# v5.9 MiMo 跨任务正式 A/B 实验结果

日期：2026-06-22

## 1. 实验目的

本轮不再把 A、B 两组分别运行，而是在同一个 runtime 中按 A -> B 顺序连续执行。目的是验证：当上游任务产生的状态与记忆继续保留时，`runtime_lite` 是否仍能控制通信、记忆读取和 LLM 上下文成本。

对照组说明：

- `baseline_text`：Agent 之间传递完整文本历史。
- `runtime_lite`：使用 SHP 状态引用、Prompt View、Memory View、读租约和通信治理机制。

## 2. 实验命令

```powershell
F:\software\anaconda\envs\multi-agent-demo\python.exe -u examples\run_cross_task_eval.py --suite A --suite B --rounds 1 --mode both --config configs\llm.mimo.example.json --max-retries 4 --retry-backoff-seconds 3 --output-dir runs\v5.9-mimo-cross-task-20260622-final2
```

输出目录：`runs/v5.9-mimo-cross-task-20260622-final2`

## 5. 与 v5.8 独立 A/B 的差异

| 指标 | v5.8 baseline | v5.9 baseline | v5.8 runtime | v5.9 runtime |
|---|---:|---:|---:|---:|
| latency_ms | 1,879,557 | 2,155,834 | 1,506,463 | 1,751,797 |
| llm_total_tokens | 4,270,231 | 9,126,251 | 241,722 | 251,228 |
| end_to_end_collaboration_tokens | 5,927,488 | 13,285,501 | 139,536 | 148,501 |
| retrieved_memory_tokens | 0 | 0 | 12,294 | 14,399 |
| memory_hit_count | 0 | 0 | 42 | 44 |

相对 v5.8：

1. 全文基线 LLM token 增加 113.71%，端到端协作 token 增加 124.14%。
2. `runtime_lite` LLM token 只增加 3.93%，端到端协作 token 只增加 6.42%。
3. 新实验的差异来自 A、B 共用同一运行时和连续历史，不应把 v5.8 与 v5.9 的绝对延迟直接视为代码性能回归。
4. v5.9 更能模拟长期运行的多 Agent 系统，也更直接证明运行时抑制上下文累积的作用。

## 6. 治理与质量证据

`runtime_lite` 本轮还记录了：

- 19 次记忆查询全部命中。
- 44 次记忆使用均记录为有效，错误命中为 0。
- 60 个记忆候选中 59 个进入记忆，1 个保持 pending。
- 100 次 Contract Guard 校验全部通过。
- A10 最终字段 16/16，B10 最终字段 12/12，两个最终交付 schema 均完整。
- `fallback_count=0`，没有进入降级兜底。
- `raw_access_count=0`，没有依赖读取冷层原始大正文来维持结果。

## 7. 证据边界

本轮已经证明：任务成功率不下降、最终字段完整、协议校验通过、通信与 LLM token 显著下降。

但 `run_cross_task_eval.py` 当前没有持久化 `baseline_text` 的最终正文，因此无法在实验结束后对 baseline 与 runtime 的最终答案执行独立 LLM 语义裁判。本轮不能据此宣称“语义质量已经由独立裁判证明完全持平”。后续应先补最终交付正文持久化，再运行质量裁判，避免重新实验后仍缺少可审计正文。

## 8. 结论

v5.9 正式 MiMo 实验补齐了 R-04 的真实跨任务成本证据：连续历史使全文基线成本快速膨胀，而运行时优化组的成本基本稳定；端到端协作 token 下降 98.88%，LLM token 下降 97.25%，延迟下降 18.74%，且成功率、字段完整度和协议稳定性没有下降。
