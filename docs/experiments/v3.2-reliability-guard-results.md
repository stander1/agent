# v3.2 Runtime Output Reliability Guard 实验记录

## 版本定位

v3.2 严格按照创新方案中的 Output Contract Guard 思路补齐运行时可靠性地基。

本版本不追求扩大 MemoryView 或进入 v4 成本治理，而是先解决：

```text
LLM 输出不稳定时，系统不能直接崩溃；
也不能一遇到 JSON 结构异常就调用 LLM 重试；
必须先规则恢复，恢复不了再短上下文重试，最后才 degraded fallback。
```

## 实现内容

### Provider Response Guard

新增：

```text
agent_runtime/reliability/provider_guard.py
```

处理边界：

```text
Provider API response
  ↓
JSON parse
  ↓
deterministic envelope normalization / repair
  ↓
extract content / usage / finish_reason
  ↓
失败才 provider-level retry
```

当前支持的低成本规则恢复：

- 单元素 list 包 object：自动 unwrap。
- OpenAI-compatible `choices[0].message.content`。
- top-level `content` 简化格式。
- Anthropic-style content list 的 text 拼接。
- usage 缺失或使用 `input_tokens` / `output_tokens` 时归一化。

不可恢复情况：

- 空 list。
- 无可用 content。
- choices 为空。
- content 为空。

这些情况才进入 provider-level retry。

### Agent Output Contract Guard

新增：

```text
agent_runtime/reliability/contract_guard.py
```

实现方案中的分层修复：

```text
Control Header Extractor
→ JSON Extractor
→ Deterministic Repair
→ Schema Validator
→ Default Filler
→ Context-Pruned Same-Agent Format Retry
→ Fallback Wrapper
```

当前支持：

- 提取 `<CMJCC_CONTROL>...</CMJCC_CONTROL>`。
- 提取 `<ARTIFACT>...</ARTIFACT>`。
- 从 Markdown fenced JSON 或裸 JSON 中提取控制头。
- 删除尾逗号。
- 去除 JSON 前后 Markdown 代码块。
- 去除 `//` 和 `/* */` 注释。
- 规范 `True` / `False` / `None`。
- 用 `ast.literal_eval` 兜底单引号字典。
- 补齐非关键字段默认值。
- 校验 `msg_type`、`task_id`、`from`、`memory_card`、`claim_cards`、`handoff_suggestion`、`cost_report`。
- 失败时生成 `degraded_fallback`，且 `schema_valid=false`。

### Runtime 接入

只在以下路径启用：

```text
runtime_lite + LLM Agent
```

原因：

- 不影响 `baseline_text` 对照组。
- 不影响 v0/v1 deterministic baseline。
- v3.2 的新增开销只计入优化组 runtime 机制本身。

Agent 输出格式：

```text
<CMJCC_CONTROL>
{ short JSON control header }
</CMJCC_CONTROL>

<ARTIFACT>
中文正文结果
</ARTIFACT>
```

Guard 通过后：

- ARTIFACT 作为后续状态/记忆正文。
- CONTROL 进入 metadata 和指标。
- 如果控制头失败但短上下文修复成功，最终算 `schema_valid=true`。
- 如果仍失败，写入 `failure_state`，下游只允许 `review_or_retry_only`。

## 当前结论

v3.2 证明：

```text
输出可靠性守卫可以按“规则优先、短上下文兜底、失败降级隔离”的方案落地，
并且不会破坏已有 runtime_lite 主流程。
```

当前仍然是 lite 版本：

- Provider retry 次数还没有从 client 回传到指标。
- Contract retry 已接入 runtime，但 smoke 中未触发。
- 还没有做 A/B 全量重跑。
- 还没有把 Contract Guard 生成的 memory_card / claim_cards 直接替代现有 MemoryStore 写入逻辑。

下一步建议：

```text
v3.3 或 v4 前置：
把 Contract Guard 产出的 memory_card / claim_cards 接入 MemoryStore，
减少 runtime 对 Artifact 二次摘要的依赖。
```

然后再进入：

```text
v4：Retry Budget / Preflight Validation / Read Lease / GC
```
