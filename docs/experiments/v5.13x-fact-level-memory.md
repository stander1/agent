# v5.13x 事实级 TLC-Memory 工程结果

## 目标

本阶段修复 v5.13w 将整篇交付物作为一个 Claim 所导致的历史污染误报，并把记忆链路校准到最终创新方案定义的 ClaimCard、CCF、Batch Compaction 和 MemoryView。

## 已实现

- 结构化 Claim 优先，规则只提取显式、高置信通用事实；
- 无结构化事实时保留候选审计，不再把整篇摘要写成正式 Claim；
- MemoryView 使用 `subject + slot_id + scope + temporal_scope`；
- 同值合并证据，新值替代旧值，无法裁决的冲突阻断 Prompt；
- Prompt 只提供 active value，历史和证据按字段展开；
- 事实级采用判定按语义键、规范化值和极性工作；
- 旧整篇交付 Claim 加载后转为审计兼容对象；
- 新增 Claim、Slot 映射、冲突和 active value 选择指标。

## 结论边界

这些结果证明事实级机制与工程回归已通过，不证明真实 LLM 下已经降低总 Token 或保持最终质量。下一阶段必须重新运行 Native、Observed、Managed，分别统计 Provider Token、端到端协作 Token、延迟、重试和匿名质量分。
