# v5.14q 当前候选充分证据与任务身份

## 真实失败证据

v5.14p 的 A10 managed 组中，Reviewer 原生输入为 4740 Token，重写后为
1559 Token。重写降低了通信成本，但角色视图把当前 Writer 预算表裁掉了。
Reviewer 随后引用了候选正文中不存在的金额并连续拒绝三份本来内部加总
一致的交付物。

B9 managed 组还出现了当前任务身份漂移：Planner 把本轮称为 B10，
Writer 又继续推进到后续轮次，导致 B9 与 B10 的风险结论同时被污染。

## 通用修复

1. 根据动态能力画像和语义动作判断接收者是否承担审查、验证、格式检查
   或失败诊断职责。
2. 对这些职责保留最近一份当前候选交付物的完整正文；旧历史和长期记忆
   仍使用最小角色视图。
3. 记录候选原始/选中字符与 Token、候选来源、完整性和视图模式。
4. 在每轮上下文中加入当前用户请求原文和协作序号身份锚点。
5. 只有当前请求中至少出现两个同一标签族的历史引用，且能结合协作序号
   唯一推导当前标签时，才拦截输出中的未来轮次自我标注。
6. 无法可靠推导时保持原生透传，避免把通用运行时变成特定题目的规则库。

## 边界

- 不按 Agent 名称判断职责；
- 不识别 Question A/B、旅游或安全业务词；
- 不向所有 Agent 重复注入完整历史；
- 不把审查所需的当前候选正文当作长期记忆；
- 不允许成本门禁覆盖语义必需证据；
- 正式成本仍按通信、Prompt View、记忆读取、控制和重试的端到端口径核算。
