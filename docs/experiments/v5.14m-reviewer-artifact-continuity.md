# v5.14m Reviewer 成果所有权与结论连续性

## 1. 阶段目标

v5.14m 针对 v5.14l 已归档的真实质量失败，修复三项通用机制：

1. 终稿守卫以正文闭环为准，拒绝藏在最终标题下的修订清单；
2. Reviewer 明确验收前序成果时，运行时晋升原成果，不交付审查报告；
3. 明确结论进入类型化决策槽位，供同一任务链的后续角色最小化读取。

## 2. 成果所有权协议

Reviewer 的权限是通过或否决，不是重新创作。新实验配置采用：

```text
Writer 输出完整业务成果；
Reviewer 发现问题 -> 返回修订清单，不输出完成标记；
Reviewer 验收通过 -> 明确批准上一份 Writer 成果并输出完成标记；
ReviewerFinalTextTermination 校验原成果后按引用晋升。
```

该协议减少重复正文传输，也避免 Reviewer 在重写时改变数字、状态或结论。
运行时仍允许其他团队直接提交 Reviewer 完整成果；只有显式引用批准时才晋升
前序成果，因此不会强制所有框架使用固定角色语义。

## 3. 决策声明提取

声明提取器新增独立标签识别：

```text
最终结论 / 当前判断 / 综合风险判断 / 状态
final outcome / current status / verdict / decision
```

提取结果写入 `slot.system.design_decision`，按风险、状态、选择和结果分配
scope。标签必须是独立字段，`reviewer_result=completed` 等标识符内部后缀
不会被提升为全局决策。

## 4. 公平性与历史证据

- v5.14l 原 A/B Agent 配置不修改，原预注册哈希继续可复验；
- v5.14m 的改进配置单独保存在本阶段目录；
- 下一轮正式实验三组使用同一份新配置、同一模型、温度、轮次和评分口径；
- 不限制 Writer 输出长度，不增加隐藏 LLM 修复调用；
- 机制验收不调用 Provider，不作为最终质量结论。

## 5. 验收门禁

openEuler 验收必须同时证明：

- 完整单元测试通过；
- 最终标题下的修订清单被拒绝；
- 任意命名业务 Agent 的成果可被长篇验收引用正确晋升；
- 明确结论被提取并实际进入正式共享记忆；
- 普通赋值字段不被误判为全局结论；
- 新 A/B Reviewer 配置只验收、不重写；
- v5.14l 两份历史 Agent 配置哈希未变化；
- 归档和 SHA-256 校验通过。
