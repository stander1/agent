# v5.14c 语义去重、最小能力视图与协议隔离

## 1. 阶段目标

v5.14b 的真实 AutoGen 预检证明质量没有下降，但 Provider Token 增加
17.06%，端到端协作 Token 只降低 10.60%，未达到预注册的 15% 目标。
本阶段只修复证据已经定位出的通用运行时问题：

1. 相同业务正文因实例 ID、文件路径和 artifact ID 不同而重复写入状态池；
2. 等价事实只在一次抽取内部去重，跨候选仍重复创建 ClaimCard 和 MemoryObject；
3. 完整历史和协议包进入模型正文，导致 Prompt Token 膨胀；
4. AutoGen 的 `DefaultTopicId`、`AgentId` 等路由元数据被误当成业务状态；
5. `AGENTLITE_REAL_REWRITE`、`shp_wire` 等协议字段可能被模型引用并进入交付物。

本阶段不修改业务 Agent 角色，不认识 Question A/B，不限制模型输出长度，也不减少
AutoGen 的最大协作轮次。

## 2. 实现内容

### 2.1 StatePool 语义身份和并发安全

`StatePoolLite` 新增稳定的 `semantic_identity_hash`。artifact 状态使用业务正文哈希、
Prompt-safe summary、状态类型和访问策略计算身份，忽略 artifact ID、文件路径和审计
文件引用等易变字段。

等价状态复用已有 `StateRef`，并记录：

- `dedup_reuse_count`
- `reuse_task_ids`
- `reuse_source_agents`

复用只增加逻辑谱系，不重复写 payload/audit 文件，也不重复计入物理状态写入指标。
身份索引和文件写入位于同一个 `RLock` 临界区，避免并发 Hook 同时写出两份等价状态。

### 2.2 路由元数据过滤

AutoGen Hook 在状态准入前识别只包含 `DefaultTopicId(...)`、`AgentId(...)`、UUID 和
路由字段的消息。这类消息仍保留在框架 trace 中，但不再进入 StatePool。

过滤规则仅针对结构化路由表示；只要消息还包含业务文本、工具调用或工具结果，就继续
按正常业务状态处理。

### 2.3 TLC-Memory 跨候选事实去重

已准入 ClaimCandidate 在创建新 ClaimCard 前，按以下通用身份查找现有有效事实：

```text
subject + slot_id + scope + temporal_scope
+ normalized(value, value_type, unit)
+ polarity
```

等价事实复用已有 ClaimCard、MemoryObject 和 MemoryView，新来源只合并到
`supported_by` 和引用图。`current_task` 等短期事实只有 `valid_from` 相同时才能复用；
`cross_task`、`persistent`、`global` 才允许跨任务合并。

新增指标：

- `memory_admission_deduplicated_claim_count`
- `memory_admission_deduplicated_memory_count`
- `memory_evidence_reference_merge_count`

CCF v2 的 `prompt_summary` 改为当前 active value 的紧凑表达，完整原始摘要仍保留在
MemoryObject、ClaimCard 和审计视图中。

### 2.4 动态能力驱动的最小充分视图

AutoGen Agent 收到消息前，运行时根据 CapabilityProfile、当前语义动作和当前任务，从
完整 chronology 中选择最小充分字段。该逻辑使用动态能力画像，不依赖
Planner/Writer/Reviewer 名称。

完整原文进入冷层 audit payload；模型只看到 Prompt View。若最小视图比来源更长，则
保留原视图；若连续任务明确缺少字段，仍按字段执行受控原文补取。

Prompt View 不再包含 consumer ID、profile version、state ID、claim ID 等内部标签。
这些字段继续写入 trace，供监控和审计使用。

### 2.5 SHP 协议与模型正文隔离

SHP wire envelope、StateRef 和 MemoryRef 继续写入 trace 和运行时审计，但
`_build_real_rewrite_content()` 只返回接收者 Prompt View。

已改写消息通过进程内内容指纹识别，避免因为移除明文协议头而被重复改写。旧版本已产生
的 wrapper 在进入 chronology 前会被解包，以下内容不会进入模型正文：

```text
AGENTLITE_REAL_REWRITE
AGENTLITE_TEAM_REAL_REWRITE
shp_wire=
native_payload_moved_to_state_pool=
```

新增 `model_visible_protocol_marker_count`，正式验收目标为 0。

## 3. 指标口径

StatePool 报告新增：

- `state_count`：实际物理状态对象数；
- `logical_state_write_count`：物理状态数加复用次数；
- `state_dedup_reuse_count`：命中状态语义身份的复用次数；
- `unique_semantic_identity_count`：唯一语义身份数量；
- `routing_metadata_state_count`：仍误入池的 AutoGen 路由状态数。

这些指标与 Provider Token、端到端协作 Token、逐任务质量、完整交付数同时报告。
不能只以状态数下降代替真实 Token 下降，也不能以较短交付物制造成本优势。

## 5. 下一次真实实验的通过条件

继续使用 v5.14b 已冻结的相同任务、Team、Provider、temperature=0、max_turns=9 和
双盲质量评分，不修改预注册阈值。除原有 29 项检查外，增加：

1. `routing_metadata_state_count == 0`
2. `model_visible_protocol_marker_count == 0`
3. 相同语义身份不产生重复物理状态
4. 相同 active claim/value 不产生重复 MemoryObject
5. Managed 完整交付数不低于 Native
6. Managed 双盲质量均分不低于 Native
7. Provider Token 和端到端协作 Token 分别重新按原阈值判断

当前只能确认机制回归通过。Provider Token 是否由 `+17.06%` 转为下降、端到端协作
Token 是否从 `10.60%` 提升到至少 `15%`，必须等待 openEuler 真实 Provider 重跑。
