# v5.14p 紧凑审批准入正式回归

## 1. 实验目的

v5.14n 的真实运行暴露出一个通用协议解释缺陷：Reviewer 用“验收通过”或
“批准上一份成果”批准 Writer 成果时，运行时可能把审批短文当作最终业务正文。
v5.14o 已通过不调用 Provider 的确定性验收。v5.14p 负责验证修复在真实连续任务、
真实 Provider 和正式成本质量门禁下是否成立。

## 2. 冻结口径

v5.14p 不修改任务、Agent 提示词、模型、温度、最大轮次、匿名评分方法或阈值。
三组都使用 v5.14m 冻结的同一份 Agent 配置；实验任务与 v5.14n 完全一致。
预注册文件同时绑定 v5.14n 输入证据和 v5.14o 机制验收器的 SHA-256。

## 3. 新增证明

除继承 v5.14l 的全部正式门禁外，报告还必须证明：

1. 每个场景至少观察到一次前序业务成果引用晋升；
2. Reviewer 审批短文从不替代业务成果正文；
3. 被批准成果保留原业务 Agent 的所有权；
4. 明确结论进入类型化决策记忆；
5. v5.14n 的 Provider Token、端到端协作 Token、质量和交付阈值未放宽。

## 4. 解释边界

该修复只解释协作协议，不识别 Question A/B、旅游、安全审计等领域实体，
也不依赖 Planner、Writer、Reviewer 等固定名称。只有存在最近一份通过当前任务
守卫的业务成果，且当前短文是无修订要求的明确审批时，才允许引用晋升。

本阶段仍是单次正式回归，不能替代多次重复实验的方差和置信区间分析。
