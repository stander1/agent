# v5.14a 真实 AutoGen 记忆事实故障注入

## 1. 阶段目的

v5.13z 已经完成错误记忆采用后的规则修复和保守阻断，但当时的验收主要是确定性函数与
模拟 AutoGen 返回对象。v5.14a 补上真实运行链证据：

```text
真实 Provider 原始输出
  -> AutoGen FaultEmitter Response
  -> AgentLite on_messages_stream 输出守卫
  -> AutoGen GroupChat 传播
  -> DownstreamProbe 实际接收
```

生产运行时没有加入实验题词表、领域规则或固定 Planner/Writer/Reviewer 角色。实验使用
任意命名的 `FaultEmitter` 与 `DownstreamProbe`，记忆仍通过协作组、Schema、语义键、
活动/历史版本和规则优先守卫工作。

## 2. 故障矩阵

| 场景 | Provider 目标输出 | Managed 预期 |
|---|---|---|
| 正确当前值 | `service.capacity=50` | 安全放行 |
| 仅旧值 | `service.capacity=20` | 精确修复为 50 |
| 新旧混合 | 同时包含 50 和 20 | 旧值修复为 50 |
| 明确否定旧值 | 使用 50，明确拒绝 20 | 安全放行，不误报 |
| 无关字段同值 | 容量 20，ticket_count 20 | 只改容量，保留 ticket_count |
| 旧版非结构化旧值 | `busy_timeout=5000 ms` | 输出 conflict_alert 并阻断 |

Managed 组预先写入两个隔离 MemoryView：

- CCF v2：`service.capacity` 的活动值 50、历史值 20；
- CCF v1-lite：`busy_timeout` 的活动值 2000、历史值 5000。

两者都带有由 AutoGen Team 参与者计算出的严格协作组 tag。AgentLite 仍按
`required_tags=[group_id]` 检索，不会跨 Team 读取。

## 3. 为什么任务必须明确引用前序结果

AgentLite 的连续上下文成本覆盖只在三个条件同时成立时启用：

1. 当前任务明确引用 previous/prior/confirmed 等前序结果；
2. 同一协作组确实检索到已准入记忆；
3. 唯一阻断原因只是注入后 Token 没有减少。

因此任务写成“using the previously confirmed configuration from shared memory”。
这不是为测试绕过成本控制，而是在复现创新方案规定的“语义必要性优先”条件。若只是一般
独立任务，即使检索命中，成本门禁仍可以保留原生消息。

## 4. 证据与指标

每行场景保留：

- `provider_raw_output`：LLM 原始文本，守卫前证据；
- `provider_raw_fingerprint`：与 trace 对齐的指纹；
- `emitter_received_messages`：Emitter 实际收到的上下文，证明记忆是否注入；
- `downstream_observed_text`：下游 Agent 实际收到的文本；
- `autogen_memory_adoption_guard`：修复或阻断动作；
- `downstream_fact_correction`：补偿审计事件；
- Provider prompt/completion/total Token、延迟与重试数。

核心验收指标：

```text
native_fault_escape_rate
managed_fault_escape_rate
managed_false_positive_rate
fault_injection_is_observed_not_assumed
unrelated_equal_scalar_is_preserved
```

“模型没有按指令产生故障”属于实验未建立有效输入，不属于 AgentLite 成功。

## 5. 结果边界

本地可使用确定性伪 Provider 验证管线，但该结果不进入比赛实验结论。正式结论必须来自：

- openEuler 24.03 LTS-SP3；
- 真实 AutoGen；
- 真实 MiMo/OpenAI-compatible Provider；
- 完整 trace、逐行审计、环境清单和 SHA-256 证据包。

由于所有输出被刻意限制为一行，本阶段不能用于证明通信 Token 下降，也不能替代此前完整
连续任务的交付质量评估。它只回答一个更窄但关键的问题：旧事实是否会在真实框架中进入
下游 Agent。
