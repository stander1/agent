# v5.14u Continuity, Identity, and Memory Resolution

## Evidence that triggered this stage

The v5.14t formal run passed both cost targets and removed every numeric
constraint false rejection. Its remaining delivery failures exposed two
different continuity faults:

1. an agent could rename the current task when the current user message
   referenced only one historical task label;
2. a compact approval became the newest message while the approved artifact's
   explicit decision was truncated before semantic role-view selection and was
   not promoted into shared memory.

## Generic correction

The runtime now:

- infers a task-label family from the bounded user task history plus the current
  request;
- validates explicit current-interaction ordinals independently of task-label
  inference;
- does not interpret ordinary counts as interaction identities;
- sends the latest two upstream messages to semantic selection before
  compaction, so a decision in the middle of the prior artifact can survive;
- resolves a compact approval to the nearest preceding valid artifact;
- promotes and summarizes the resolved artifact, preserving explicit decisions
  and constraints through the rules-first claim extractor.

The complete history is not broadcast to every agent. Only two upstream
messages are considered, and the receiver's dynamic capability profile selects
the minimal relevant view.

## Safety boundary

The correction does not identify Question A/B, application entities, fixed
agent names, fixed conclusions, or fixed role order. Rejections do not promote
prior artifacts, schema and collaboration-group boundaries remain active, and
the final cost evaluation still includes communication, prompt views, memory
reads, control calls, and retries.

## Acceptance

`experiments/v5.14u-continuity-identity-memory-resolution/run_openeuler.sh`
runs the full unit suite and focused mechanism checks on openEuler, then
packages immutable evidence with a SHA256 checksum.
