# v5.13m openEuler 24.03 LTS-SP3 兼容性验收报告

## 1. 验收结论

本轮验收结论为：**通过代码端兼容性与接管链路验收，但不把本轮 A1-A2 冒烟实验表述为真实 Token 降低证据。**

已经由归档证据确认：

1. AgentLite `0.5.13.dev0` 可在 openEuler 24.03 LTS-SP3、Python 3.11.6 和 AutoGen 0.7.5 环境中安装、导入并运行；
2. CLI、环境诊断、AutoGen Team 接管、发行门禁、174 项单元测试、编译检查和 `git diff --check` 全部通过；
3. 确定性 AutoGen Team 基准中，调用方看到的任务语义保持不变，内部 Team 任务 Token 从 2,071 降至 1,069，三接收者广播成本从 6,213 降至 918；
4. 真实 MiMo A1-A2 连续任务 2/2 有效交付，无 Provider 重试，本地运行时开销约占总耗时 0.27%；
5. 真实任务第二次运行中的压缩候选均因成本门禁判定“不比原生更省”而回退，实际传输节省为 0。该结果证明安全回退有效，不证明本轮真实业务 Token 已下降。

### 6.2 成本门禁与真实传输结果

第二次运行中，8 次共享记忆查询全部命中，但没有记忆进入 Prompt View。原因不是记忆模块失效，而是当前用户消息较短、检索到的记忆视图较长，候选改写会增加输入 Token。

因此成本门禁执行了安全回退：

| 决策 | 次数 | 结果 |
|---|---:|---|
| Team 输入改写候选 | 2 | 2 次因 `token_not_reduced` 回退 |
| Agent 输入改写候选 | 6 | 6 次因 `token_not_reduced` 回退 |
| 实际成功改写 | 0 | 保留原生消息 |

正式口径为：

```text
actual_native_transport_tokens: 13108
actual_agentlite_transport_tokens: 13108
actual_transport_token_savings: 0
actual_transport_token_savings_ratio: 0.0
```

影子推演给出的 67.57% 是“若强制使用压缩候选”的理论值，不能写成实际收益。`actual_rewrite_event_count: 8` 在当前报告中表示进入真实改写审计的决策事件数，不等于成功修改消息的次数；判断是否真正改写必须同时查看每个事件的 `rewrite_applied`。

## 7. 两次运行的口径冲突

同一归档还保留了较早会话：

```text
launch_1d11aeee53cb41aea8dcec8cb073d093
```

目录中的原始 `agentlite-report.json` 对应这次较早运行，记录 26,367 个 Provider Token 和 4.41% 实际传输节省；随后第二次运行覆盖了 `sequence_result.json`、`llm_usage.jsonl` 和 `llm_usage_summary.json`，但没有重新生成 AgentLite 报告。因此原始报告不能与第二次 21,216 Token 的结果拼接使用。

本报告已按第二次 session 重新解析 trace，并显式指定第二次 `llm_usage_summary.json`。后续实验应为每次运行使用不可复用的输出目录，或在每次重跑后立即重新导出 AgentLite 报告。

## 8. 验收边界

本轮可以证明：

1. openEuler 上的安装、CLI、AutoGen 导入、Team 接管、状态与记忆持久化链路可运行；
2. AgentLite 能在固定长消息基准中真实改写并显著减少广播载荷；
3. 当压缩候选反而更贵时，运行时会保留原生消息，不会为追求压缩率破坏成本或语义；
4. A1-A2 真实模型调用的成功率、Provider Token 与耗时可以完整记录。

本轮不能证明：

1. 所有真实业务任务都能降低 Provider 总 Token；
2. 第二次 A1-A2 真实任务已经产生实际传输节省；
3. openEuler 与 Windows 的性能完全等价；
4. AutoGen Studio 页面交互已经被自动化测试覆盖；
5. 分布式、远程或跨进程 AutoGen Runtime 已经兼容。

## 9. 下一步

兼容性验收已经达到当前阶段要求。下一轮不需要继续重复安装测试，应该回到真实收益问题：

1. 将 Prompt View 与 AutoGen 原生历史做事实级去重，避免记忆视图比短消息更长；
2. 在报告中分开显示“审计事件数、成功改写数、成本门禁回退数”，消除 `actual_rewrite_event_count` 的歧义；
3. 修正归档流程，使 `system/`、`git-commit.txt`、当前 session 报告和 Provider usage 在同一个不可变运行目录中生成；
4. 完成后再做 A/B 连续任务的多次公平重复，分别报告实际传输成本、Provider 总 Token、质量和延迟。
