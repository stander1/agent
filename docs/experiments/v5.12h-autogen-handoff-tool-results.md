# v5.12h AutoGen Handoff / ToolCall 影子接管实验记录

## 版本定位

`v5.12h` 仍属于 `v5.12` AutoGen 透明托管接入链路，不进入真实广播替换。该版本目标是验证真实 AutoGen 消息类型中的 `HandoffMessage`、`ToolCallRequestEvent`、`ToolCallExecutionEvent` 和 `ToolCallSummaryMessage` 能否被 AgentLite 稳定识别、状态化并生成 SHP 影子交接包。

这一版补的是 `v5.12g` 的消息类型覆盖缺口：`v5.12g` 已证明长文本可以通过 `state_ref + Prompt View` 降低传输口径，但主要覆盖文本输出；`v5.12h` 进一步覆盖交接消息和工具调用中间状态。

## 实现内容

- 新增 `examples/autogen_handoff_tool_shadow_smoke.py`：目标脚本只导入 AutoGen，不显式导入 AgentLite。
- 新增 `examples/run_autogen_handoff_tool_shadow_smoke.py`：通过 `agentlite run --framework autogen -- python ...` 托管启动目标脚本。
- AutoGen Driver phase 更新为 `v5.12h`。
- Driver 在 `core_runtime` 接收到 `ToolCallRequestEvent` / `ToolCallExecutionEvent` 时，新增 `autogen_transport_input_state` 事件，并将工具调用参数或工具结果写入 StatePool `artifact_state`。
- runner 增加消息类型覆盖检查：handoff、tool_call、tool_result、tool_summary。
- runner 检查 Handoff 目标接收方是否进入 SHP 影子计划，避免全部退化为默认 `autogen_next`。

## 可表述结论

AgentLite 已经能够在 AutoGen Python 代码端的透明托管模式下，对真实 AutoGen 交接消息和工具调用消息进行稳定解码，并把长 Handoff 内容、工具调用参数、工具调用结果和工具摘要转化为 StatePool `artifact_state` 与 SHP 影子交接包。

在本次 smoke 中，原生输出文本口径为 `36948` tokens，`SHP wire + Prompt View` 口径为 `2764` tokens，下降约 `92.5%`。该结果证明低开销路线不只适用于普通文本消息，也能覆盖工具调用这类半结构化中间状态。

## 下一步建议

`v5.12i` 可以继续保持影子模式，进入“广播替换前策略模拟”：

```text
1. 记录 AutoGen Team 原生广播中每个接收方实际会看到的消息；
2. 在不改 AutoGen 返回值的前提下，生成 per-receiver SHP 替代传输计划；
3. 对比原生广播 token、SHP wire token、Prompt View token；
4. 检查不同接收方是否能拿到角色裁剪后的 Prompt View；
5. 为后续真实替换 GroupChat 广播策略提供可回滚证据。
```
