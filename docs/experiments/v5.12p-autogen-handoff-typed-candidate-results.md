# v5.12p AutoGen Handoff Typed Rewrite Candidate 实验记录

## 版本定位

`v5.12p` 是 HandoffMessage 真实改写前的候选验证版本。

typed rewrite candidate：类型化改写候选。意思是系统已经能构造“如果要改写 HandoffMessage，应当替换成什么内容”的候选包，并验证 AutoGen 原生控制字段不会丢失，但当前仍不真正修改原生消息。

## 实现内容

- AutoGen Driver phase 更新为 `v5.12p`。
- HandoffMessage 非文本分支新增 `typed_rewrite_candidate` 审计字段。
- 新增 Handoff candidate 合约：`autogen_handoff_typed_rewrite_candidate.v1`。
- candidate 会写入 StatePool、生成 SHP wire 和接收方 Prompt View。
- candidate 会克隆 HandoffMessage 并验证以下语义字段：
  - message type
  - source
  - target
  - id
  - metadata
  - context
  - content replaced only
- 当前仍保持 `mutation_applied=false`，即只验证候选，不真实替换。

## 可表述结论

AgentLite 现在已经具备 HandoffMessage typed rewrite candidate 能力：系统能够把 Handoff 的长正文状态化为 StatePool 引用，生成紧凑 SHP wire 和 Prompt View，并证明 target、source、id、metadata、context 等 AutoGen 控制字段在候选改写后仍可保持。

这仍然是候选验证，不是正式真实改写。

## 仍不能表述为

```text
已经真实改写 HandoffMessage；
已经支持 ToolCallSummaryMessage 真实改写；
已经真实替换 AutoGen Team 层广播策略；
已经接管 AutoGen Studio / 网页端。
```

## 下一步建议

下一步可以进入 `v5.12q`：在 Handoff candidate 已经语义安全的前提下，增加显式开关，例如 `AGENTLITE_AUTOGEN_HANDOFF_REWRITE=1`，只在开关打开、candidate_safe=true、token_reduced=true 时真实替换 HandoffMessage 的 content。

这个开关必须默认关闭，避免还没经过足够实验时影响用户的 AutoGen 原生程序。
