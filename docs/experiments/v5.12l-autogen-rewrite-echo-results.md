# v5.12l AutoGen Rewrite Echo 可观测性实验记录

## 版本定位

`v5.12l` 不是扩大真实改写范围的新功能版，而是对 `v5.12k` 的工程硬化。

```text
目标：证明 agent 实际读到的是 rewritten content，而不是只在 trace 里记录了改写计划。
范围：仍只覆盖简单 TextMessage 的 agent 输入层真实改写。
边界：不替换 AutoGen Team 层广播策略，不支持 ToolCall / HandoffMessage 真实改写。
```

本版本补齐三类证据：

```text
1. EchoAgent smoke：自定义 agent 直接记录 on_messages_stream 实际收到的 content；
2. 三模式对照：shadow-only / dry-run-rewrite / real-rewrite；
3. 改写指标：rewrite_attempt_count / rewrite_applied_count / rewrite_fallback_count。
```

## 实现内容

- 新增 `examples/autogen_rewrite_echo_smoke.py`。
- 新增 `examples/run_autogen_rewrite_echo_smoke.py`。
- AutoGen Driver phase 更新为 `v5.12l`。
- `autogen_agent_input_real_rewrite` 事件新增 `rewrite_attempt_count`、`rewrite_applied_count`、`rewrite_fallback_count`。
- EchoAgent 会记录实际收到的消息是否包含 `AGENTLITE_REAL_REWRITE v1`、`state_refs`、`prompt_view:` 和原生长文本标记 `NATIVE_LONG_CONTEXT_MARKER`。
- 报告检查不要求原生标记完全消失，因为 Prompt View 允许携带少量摘要；检查口径改为“原生标记数量显著减少，且总字符数显著减少”。

## 可表述结论

AgentLite 已经能在真实 AutoGen Python 代码端、托管启动且目标脚本不导入 AgentLite 的情况下，对简单 `TextMessage` 的 agent 输入进行真实改写。EchoAgent 直接证明：在 `real-rewrite` 模式下，agent 实际收到的是包含 SHP wire、`state_refs` 和 Prompt View 的紧凑内容，而不是原始长文本。

本次 smoke 中，agent 可见内容从 `8372` 字符降到 `1124` 字符；token 从 `4160` 降到 `338`。这说明 v5.12k 的真实改写不是单纯 trace 记录，而是已经进入 AutoGen agent 输入层。

## 仍不能表述为

```text
已经真实替换 AutoGen Team 层广播策略；
已经支持 HandoffMessage / ToolCall 的真实改写；
已经接管 AutoGen Studio / 网页端；
已经完成真实 LLM AutoGen 任务的质量、延迟、token 综合评估；
已经证明所有 AutoGen Team 类型都可以无修改替换。
```

## 下一步建议

`v5.12m` 可以开始做真实改写范围扩展前的安全补丁，而不是直接扩展消息类型：

```text
1. 给 real-rewrite 增加更细的失败分桶；
2. 固化三模式报告为后续每次改写扩展的回归基线；
3. 补充失败样例 smoke，验证自动 fallback 不会破坏 AutoGen 原生执行；
4. 再考虑 HandoffMessage / ToolCall 的真实改写。
```
