# v5.13n 上下文去重与改写结果口径校准

## 1. 本轮目标

openEuler 验收暴露出两个通用问题：

1. AutoGen 原生历史或最新上游成果可能已经包含共享记忆中的事实，旧版本仍会把完整 MemoryView 追加到 Prompt View，造成重复输入；
2. `actual_rewrite_event_count` 旧口径统计的是带成本数据的改写审计事件，容易被误解为真正修改消息的次数。

v5.13n 只修复运行时通用机制，不包含 Question A、旅游预算、目的地或其他实验领域规则。

## 2. 内容覆盖去重

### 2.1 执行顺序

真实 Agent 输入和 Team 广播候选现在按以下顺序构建：

```text
当前任务 + 用户请求历史 + 最新上游成果
  -> State Prompt View
  -> 检查每条 MemoryView 是否已被当前上下文覆盖
  -> 只保留仍提供新事实的 MemoryView 和 memory_ref
  -> 生成 SHP wire + Prompt View
  -> 执行 Token 成本门禁
```

如果某条记忆已被覆盖，它会同时从 Prompt View 和 SHP `memory_refs` 中移除，避免出现“正文删了但引用仍在”的假注入。

### 2.2 规则

去重完全由本地规则完成，不调用 LLM：

1. 去掉 MemoryView 的 `memory_view/slot/claim/tags` 元数据，只比较事实正文；
2. 统一大小写、空白、Markdown 和常见标点；
3. 先做正文包含检查，再按句子或事实片段计算字符三元组覆盖；
4. 至少 85% 的加权事实内容已被覆盖时，才判定整条记忆重复；
5. 近似匹配要求双方数字序列完全一致，避免把 2,600 元和 2,800 元误判为同一事实；
6. 未被覆盖的 MemoryView 保持原样，不做摘要改写或语义猜测。

该实现是保守去重：允许少量未识别的重复，也不静默删除带有不同数字或新事实的记忆。

### 2.3 新增 Trace 字段

Agent 与 Team 改写事件新增：

```text
memory_candidate_count
memory_retained_count
memory_candidate_deduplicated_count
memory_candidate_deduplicated_tokens
memory_deduplication_mode=fact_overlap_rules_v1
```

Team 事件额外记录 `memory_candidate_deduplicated_fanout_count`，用于表示多个接收者视角下被避免的重复注入次数。

## 3. 改写结果指标

Session 报告现在明确拆分：

| 指标 | 含义 |
|---|---|
| `rewrite_audit_event_count` | 所有进入真实改写审计的决策，包括无可改写字段的消息 |
| `rewrite_costed_event_count` | 具有原生与候选 Token、可进行成本比较的决策 |
| `rewrite_applied_event_count` | 真正修改了 AutoGen 消息的次数 |
| `rewrite_fallback_event_count` | 保留原生消息的次数 |
| `rewrite_cost_gate_fallback_count` | 因候选不比原生更省而回退的次数 |
| `rewrite_contract_fallback_count` | 因消息结构不受当前改写器支持而回退的次数 |
| `actual_rewrite_event_count` | 兼容字段，v5.13n 起等于成功改写次数 |

CSV、Markdown、JSON Session 报告均输出这些字段。`event_count` 暂时保留为有成本数据的事件数，兼容已有监控读取逻辑。

## 5. 自动化验证

新增测试覆盖：

1. 最新上游成果已经包含 MemoryView 时，记忆正文与 `memory_ref` 同时移除；
2. 当前任务和最新上游成果仍完整进入 Prompt View；
3. 事实不同的共享记忆继续保留并可走原有注入流程；
4. 2,600 元与 2,800 元等数值冲突不会被近似去重；
5. 审计、成功改写、全部回退、成本回退、结构回退分别统计；
6. 旧 Provider Token、真实传输成本与影子成本口径不受影响。

发行门禁继续验证 CLI、doctor、AutoGen Team benchmark、CLI takeover、完整单测、compileall 和 `git diff --check`。

## 6. 当前边界

本轮可以表述为：

```text
AgentLite 已能在构造候选 Prompt View 时，基于当前可见事实去除完全被覆盖的共享记忆，并准确区分改写审计、成功应用和安全回退。
```

仍不能表述为：

```text
任意语义相同的自然语言改写都能被识别；
记忆去重一定降低 Provider 总 Token；
被保留或注入的记忆已经被证明对最终答案有效；
旧 openEuler A1-A2 运行已经产生真实 Token 节省。
```

下一步应修复验收归档的不可变运行目录与 session/provider usage 自动绑定，然后再进行真实 A/B 多次重复实验。
