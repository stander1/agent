# v5.6 Read Lease / Access Escalation Lite 记录

日期：2026-06-22

## 1. 本轮目标

根据外部审计与二次复核文档，本轮继续补齐暂不依赖 AutoGen 的运行时治理缺口：

1. `Read Lease` 只有 active reader 计数，没有 TTL / heartbeat / fencing token / crash recovery。
2. `Cold Access` 只有直接冷读预算，没有 summary-first 的逐级访问入口。
3. runtime 的状态读取没有统一经过 Access Escalation 入口。

英文术语说明：

1. `Read Lease`：读租约。Agent 读取状态时先登记，GC 看到有活跃读者就不能物理删除。
2. `TTL`：有效期。租约超过有效期未续约，就会被自动回收。
3. `heartbeat`：心跳。读者定期刷新租约，表示自己还活着。
4. `fencing token`：隔离令牌。每次租约都有唯一 token，避免过期读者继续冒充有效读者。
5. `Access Escalation`：访问升级。先读摘要/证据视图，只有不够用时才升级读取 raw 冷数据。

## 2. Read Lease 升级

`LeaseRegistry` 从简单计数器升级为：

```text
ReadLeaseRecord
LeaseRegistry.acquire_read_lease()
LeaseRegistry.heartbeat()
LeaseRegistry.release_read_lease()
LeaseRegistry.recover_expired()
LeaseRegistry.active_fencing_tokens()
```

每个读租约记录：

```text
state_id
fencing_token
owner
acquired_at
last_heartbeat_at
ttl_seconds
```

现有 `with self.leases.read_lease(...)` 调用保持兼容，但上下文 now yield 一个 `ReadLeaseRecord`，Prompt View 渲染可以记录 `fencing_token` 和 `lease_ttl_seconds`。

## 3. Progressive Access

新增：

```text
AccessEscalationReport
StatePoolLite.request_progressive_access()
```

当前规则：

1. 先调用 Prompt View，默认不读取 raw 冷数据。
2. 如果状态已经 `evicted` 或 `deleted`，返回 tombstone fallback summary。
3. 如果 `need_raw=False`，直接返回 summary / evidence snippets / metadata。
4. 如果 `need_raw=True` 且状态在 cold tier 且存在 audit payload，则调用 `request_cold_access()`。
5. 如果冷读预算耗尽，保持 summary-only，不让系统崩溃。

## 4. Runtime 接入

`V0Runtime._build_prompt()` 中的状态读取从：

```text
render_prompt_view_with_report()
```

改为：

```text
request_progressive_access(need_raw=False)
```

这意味着 runtime_lite 的默认状态读取路径是：

```text
summary/evidence first
  -> optional cold access request
  -> metrics record
```

比赛版默认仍保持低开销，不自动把 raw 冷数据放回 prompt。后续若某个 Agent 明确需要原文，可将 `need_raw=True` 接入角色策略。

## 5. Metrics 影响

现有 `record_state_access()` 继续记录：

```text
raw_access_count
summary_access_count
evidence_snippet_access_count
access_escalation_count
read_lease_acquire_count
```

v5.6 后这些指标来自 Progressive Access 入口，不再只是 Prompt View 渲染的副产物。

## 7. 已解决与未解决

已解决：

1. Read Lease 具备 TTL。
2. Read Lease 具备 heartbeat。
3. Read Lease 具备 fencing token。
4. 过期租约可自动 recovery。
5. Cold Access 前新增 Progressive Access 入口。
6. runtime_lite 状态读取进入 summary-first access escalation 路径。

仍未解决：

1. Read Lease 仍是单进程内存实现，不是多进程/分布式租约。
2. heartbeat 由调用方主动触发，当前 runtime 的短读路径不需要后台心跳线程。
3. Access Escalation 仍是规则版，不是完整期望成本模型。
4. raw span resolver / prefetch scheduler / raw view cache 仍未实现。
5. AutoGen / LangGraph adapter 按用户要求暂缓。
