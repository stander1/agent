# v5.13i AutoGen 共享记忆桥接验证

## 1. 验证目标

此前 AgentLite 已能接管 AutoGen Team 入口、Agent 输入和 Core 通信，但 AutoGen Driver 只把输出写入 StatePool，尚未把框架输出接到 TLC-Memory 的候选、准入、持久化和跨任务检索链路。因此，AutoGen Studio 即使由 AgentLite 启动，也不会自动获得跨任务共享记忆。

本次补充属于既定 v5 跨框架适配主版本和 v5.13i AutoGen 工程增强，不新增独立创新方案。它复用已有的 v3.3 规则优先记忆准入机制。

## 2. 实现链路

```text
AutoGen Agent / Team 输出
  -> StatePool artifact_state
  -> State-to-Memory Promotion View
  -> MemoryCandidate
  -> rules-first Memory Admission
  -> admitted MemoryView
  -> 持久化 MemoryStore
  -> 后续 AutoGen Team 检索
  -> SHP memory_ref + 裁剪后的 MemoryView
  -> Team 实际任务输入
```

准入规则保持分层：

| 输出类型 | 候选状态 | 原因 |
|---|---|---|
| 单个 Agent 中间输出 | `pending`，即待审 | 防止草稿、局部结论和错误结果直接污染长期记忆 |
| Team 完整最终结果 | `admitted`，即已准入 | 置信度、重要性和覆盖度达到规则阈值后写入 MemoryView |

系统没有把 AutoGen 的全部聊天历史原样保存为长期记忆。原始产物仍由 StatePool 管理，记忆池保存的是带来源状态引用的裁剪结论。

## 3. 持久化与隔离

默认存储位置为：

```text
<data-dir>/shared_memory/autogen/<workspace-scope>/
```

检索需要同时满足：

1. 相同的 AgentLite `data-dir`；
2. 相同的工作区作用域，或相同的 `AGENTLITE_MEMORY_SCOPE`；
3. 相同的 AutoGen Team 成员签名。

AutoGen 共享记忆使用严格标签过滤，不只是相似度加权。因此，即使两个 Team 讨论相同主题，只要成员签名不同，也不会互相命中记忆。

`shadow-only` / `--rewrite off` 观察模式强制关闭共享记忆，避免原生观察组被历史记忆污染。

## 4. 真实 AutoGen 0.7.5 验证

验证命令：

```powershell
F:\software\anaconda\envs\agentlite-autogen\python.exe `
  .\examples\run_autogen_shared_memory_smoke.py `
  --python F:\software\anaconda\envs\agentlite-autogen\python.exe `
  --output-dir .\runs\autogen-shared-memory-validation-4
```

验证使用两个独立的 AgentLite 托管进程：

1. `seed` 进程运行普通 AutoGen `RoundRobinGroupChat`，产生一条明确的最终偏好结论；
2. `recall` 进程使用相同 data-dir 和 Team 成员再次运行普通 AutoGen 脚本；
3. 用户脚本只导入 AutoGen，不导入 AgentLite。

结果：

```text

recall_returncode_zero: true
```

记忆准入与读取指标：


其中 `127` 是一份 MemoryView 的长度；该 Team 有三个接收 Agent，因此端到端报告按实际 Prompt 暴露次数记录 `3 × 127 = 381`，影子审计事件不重复计费。

## 5. 用户使用方式

代码端和 AutoGen Studio 后端都使用正常接管命令，无需改 Agent 类：

```bash
agentlite autogen --data-dir ~/.agentlite -- python app.py

agentlite autogen --data-dir ~/.agentlite -- \
  autogenstudio ui --port 8081 --appdir runs/studio-agentlite-app
```

连续任务必须保持相同的 `data-dir` 和 Team 成员名称。需要人为隔离不同实验时，可以设置：

```bash
export AGENTLITE_MEMORY_SCOPE=studio-travel-exp-01
```

## 6. 当前边界

可以表述为：

```text
AgentLite 已能把真实 AutoGen Team 的最终结果经过规则优先准入写入持久化 MemoryStore，并在后续独立进程中将裁剪 MemoryView 自动注入同一 Team 的任务输入。
```

不能表述为：

```text
所有中间 Agent 输出都会直接进入长期记忆；
原生或观察模式也会读取 AgentLite 记忆；
更换 Team 成员名称后仍自动继承原 Team 记忆；
共享记忆本身能够修复错误的角色提示词、Team 策略或终止条件；
当前验证已经证明真实 LLM 的最终答案质量提高。
```

下一次 Studio 质量实验应使用修正后的角色提示词和终止条件，并连续运行 A1-A10，检查 `memory_hit_count`、`useful_memory_hit_count`、最终答案完整性和 provider token。

## 7. AutoGen Studio 消息序列兼容修复

真实 Studio 连续 Run 验证发现，Studio 后端不会把用户问题作为纯字符串传给 Team，而是通过 `construct_task()` 包装成 `Sequence[ChatMessage]`。原实现的 Team 入口重写只接受字符串，因此会记录：

```text
fallback_reason: unsupported_team_task_type
```

此时共享记忆可以完成检索，但无法写回本轮 Team 输入，导致后续 Run 的 Agent 仍然看不到前一轮已准入记忆。

修复后，Team 入口同时支持：

```text
str
list[TextMessage]
tuple[TextMessage, ...]
```

对于消息序列，AgentLite 只克隆并替换第一条文本消息，保留原消息类型、`source`、其余消息及附件，不把 Studio 的消息对象降级成字符串。无文本消息的序列仍保持原生传递并记录明确 fallback。

真实 AutoGen 0.7.5 双启动验证改为使用与 Studio 相同的 `list[TextMessage]` 输入形态，以下检查全部通过：

```text
seed final admitted: true
persistent snapshot written: true
recall memory hit: true
recall task contains memory marker: true
recall task contains seed fact: true
recall task was rewritten: true
```

Studio 前端仍会显示“不同 Run 不共享数据”的原生提示，因为 AgentLite 不修改 Studio 前端。AgentLite 是否生效应以 `autogen_memory_retrieval`、`memory_hit_count` 和实际注入的 MemoryView 为准。
