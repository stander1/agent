# v4.0 Cost Governance and Lifecycle Lite Results

## Positioning

v4.0 enters the original v4 mainline:

```text
CMJCC: Retry Budget and retry cost visibility
SHP-State: Read Lease-lite, GC-lite, tombstone, lineage protection
TLC-Memory: lifecycle-aware retrieval and Preflight Validation-lite
```

This version does not implement v6 features such as fencing tokens, full CSCC,
section-level dependency maps, or control-flow-aware GC. It implements the
competition-oriented lite guards required before v5 stress testing.

## Implemented Scope

### CMJCC-v4

- Added retry input budget control for Contract Guard format retry.
- Default limit: `MAX_FORMAT_RETRY_INPUT_TOKENS = 800`.
- Retry prompt is trimmed if it exceeds budget.
- Added retry budget metrics:
  - `retry_input_tokens`
  - `retry_budget_exhausted_count`
  - `context_pruned_retry_count`
  - `format_retry_success_count`

### SHP-State-v4

- Added in-memory `LeaseRegistry`.
- `render_prompt_view_with_report()` acquires and releases read leases around
  state payload reads.
- Added GC-lite:
  - cold states can be tombstoned;
  - states with active readers are only marked `cooling`;
  - tombstone JSON is retained instead of silent 404;
  - states promoted into memory lineage are protected from GC.
- Added access and GC metrics:
  - `read_lease_acquire_count`
  - `read_lease_blocked_gc_count`
  - `state_gc_count`
  - `state_tombstone_count`
  - `raw_access_count`
  - `summary_access_count`
  - `evidence_snippet_access_count`
  - `access_escalation_count`

### TLC-Memory-v4

- Added lifecycle-aware retrieval.
- Prompt View retrieval only allows `active` and `provisional_active` memory.
- `deprecated`, `deleted`, `superseded`, `unresolved_conflict`, and
  `pending_lifecycle_update` are blocked from normal Prompt View.
- Added `validate_read_set()` for Writer preflight.
- Added `transition_memory_status()` for lifecycle transition tests.
- Added preflight metrics:
  - `preflight_validation_count`
  - `preflight_block_count`
  - `stale_read_detected_count`
  - `memory_status_transition_count`

## Interpretation

The v4.0 smoke verifies the lifecycle/cost-control guards in the real LLM path:

- State reads are lease-protected and visible in metrics.
- Writer preflight runs before generation.
- Memory lifecycle rules can block stale or deprecated read sets.
- Retry cost is counted separately and constrained by budget.
- Normal prompt rendering uses summary/evidence snippets, not raw artifact
  expansion.
- A degraded fallback in A1-A2 did not crash the pipeline; it remained observable
  through `fallback_count`.

The GC smoke does not force deletion in the live run because recent state refs and
memory lineage are protected. Unit tests cover the required race condition:

```text
active read lease -> GC marks cooling, does not delete
lease released    -> GC writes tombstone and deletes payload
```

This completes the v4.0 lite guard layer needed before moving toward v5 adapter
and competition-delivery work.
