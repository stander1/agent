# v5.14k 类型化可靠性与真实状态接入

## 1. 阶段目标

v5.14j 已证明 Managed 轨道能显著降低 Provider Prompt Token 和端到端
协作 Token，但也暴露了四类通用可靠性缺陷：

1. 不同量纲的数值可能被放入同一种约束；
2. Reviewer 发现阻断问题后，修订清单仍可能被误当成最终产物；
3. 假设性或“预期返回”内容可能被提升为确认记忆；
4. 技术盲评可能把历史答案中的问题归因给当前答案。

此外，正式任务中的状态池只有通用文本制品，尚未证明真实
`retrieval_state` 和 `embedding_state` 接入。

## 2. 通用实现

### 2.1 数量类型化

`agent_runtime/reliability/quantities.py` 将数值解析为：

- `money`：金额；
- `time`：时间；
- `count`：计数；
- `ratio`：比例；
- `scalar`：没有明确单位的标量。

最终交付守卫只在同一语义子句和同一量纲内比较上限，避免把
“30 分钟”解释成“30 元”。

### 2.2 Reviewer 阻断闭环

最终交付守卫识别“需要 Writer 修订”“仅为审查意见”“尚未完成修正”
等未闭环信号。即使文本包含最终标题和终止标记，也不会把修订清单判为
合格成果。

这项修改不偷偷增加实验轮次或 Provider 调用。AutoGen 团队继续使用原有
终止条件和最大轮次：在轮次内完成修订后可交付；耗尽轮次仍不合格则明确
记录失败。

### 2.3 认识状态准入

记忆候选增加对事实确定性的约束：

- `observed`、`asserted`、`confirmed`、`verified` 可继续规则准入；
- `inferred`、`uncertain` 保留在候选池，状态为
  `pending_confirmation`；
- 所有事实都缺少确认依据时，候选整体为 `audit_only`，不生成正式
  MemoryView。

该规则适用于任意领域，不依赖 Agent 名称或具体题目。

### 2.4 当前答案证据归属

技术盲评的每条 finding 都必须提供可在当前答案中定位的原文证据。
如果证据只存在于 `previous_answer`，结构化输出校验失败并要求重新审查
当前答案。

### 2.5 真实非文本状态

AutoGen 驱动只提取框架真实输出中已经存在的：

- 查询向量 ID；
- chunk 或 source ID；
- 向量维度；
- 相似度分数和证据排序。

字段完整时生成 `embedding_state` 或 `retrieval_state`，并记录原输出摘要
哈希。没有真实引用时不生成状态，因此不会使用伪向量或虚构检索结果填充
指标。

## 3. 与创新方案的对应关系

- SHP-State：结构化状态只传递引用和裁剪视图；
- CCF：数值事实保留字段、量纲和语义身份；
- TLC-Memory：候选池、规则准入和正式记忆分层不变；
- Context-Pruned Retry：盲评格式或证据归属错误使用短上下文重审；
- 端到端成本：不要求每条注入消息都缩短，正式实验继续统计消息、视图、
  记忆读取、控制和重试 Token。

## 4. 边界

v5.14k 的确定性机制验收通过，只能证明代码路径满足设计约束；真实质量、
成本和状态生成数量仍必须通过新的完整 Provider 正式回归确认。正式回归
必须使用单一新提交重新运行，不能续接 v5.14j 的旧结果。
