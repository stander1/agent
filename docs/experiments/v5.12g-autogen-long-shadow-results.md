# v5.12g AutoGen Long-Context SHP Shadow Results

## 版本目标

v5.12g 延续 v5.12f 的“影子交接包”路线，但把短文本 smoke 扩展为长内容 AutoGen 原生任务，用于验证：

1. 用户脚本仍只导入 AutoGen，不导入 AgentLite。
2. AutoGen 原生消息和返回值不被改写。
3. AgentLite 旁路生成 SHP wire envelope，并通过 `state_ref` 指向 StatePool 中的冷层 artifact。
4. 在长内容场景下，对比原生长文本传输、SHP wire 包、以及接收方读取 Prompt View 后的端到端 token 成本。

## Token 结果

```text
native_output_text_tokens: 38227
shadow_wire_tokens: 1176
state_prompt_view_tokens: 709
shadow_wire_plus_prompt_view_tokens: 1885
shadow_audit_envelope_tokens: 2916
wire_token_delta_native_minus_wire: 37051
wire_plus_prompt_delta_native_minus_runtime: 36342
wire_reduction_ratio: 0.969236
wire_plus_prompt_view_reduction_ratio: 0.950689
prompt_view_count: 5
token_counter: tiktoken:cl100k_base 0.13.0
```

字段解释：

- `native_output_text_tokens`：AutoGen 原生输出文本 token。
- `shadow_wire_tokens`：紧凑 SHP wire 包 token，只代表未来跨 agent 数据面传输口径。
- `state_prompt_view_tokens`：接收方通过 `state_ref` 读取 StatePool 摘要 Prompt View 的 token。
- `shadow_wire_plus_prompt_view_tokens`：wire 包 + Prompt View 的端到端读取成本。
- `shadow_audit_envelope_tokens`：完整审计包 token，只用于本地 trace，不计入跨 agent 通信。

本次长内容 smoke 中，`shadow_wire_plus_prompt_view_tokens` 为 1885，明显低于原生长文本 38227，端到端摘要读取口径下降约 95.1%。

## 验证结论

v5.12g 证明了：在长内容 AutoGen 原生任务中，AgentLite 的透明 Driver 可以不改写 AutoGen 行为，旁路生成基于 `state_ref` 的 SHP wire 包，并在“wire 包 + Prompt View”口径下显著降低长正文协作传输成本。

这个结果比 v5.12f 更接近比赛中“非文本状态传递降低协作开销”的核心论证，因为它不只比较短文本控制头，而是把长 artifact 放入状态池，把跨 agent 传输改为 `state_ref` 加摘要视图。
