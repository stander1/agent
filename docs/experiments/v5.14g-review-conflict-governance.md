# v5.14g 动态审查冲突治理与数值归因修复

## 1. 来源

v5.14f 的正式规模实验已经证明 AgentLite 的 Provider Token 和端到端协作
Token 显著下降，但正式验收仍有 4 项失败：

- Managed A10 交付不完整；
- Managed A10 质量分低于终局门槛；
- Managed A10 有 2 个阻断问题；
- 正式报告记录了 2 次错误记忆命中。

Trace 复核表明，两次错误命中并非模型采用了旧预算，而是通用预算抽取器把
“两人”中的“两”识别为预算值 `2`。A10 的质量问题则来自另一个机制缺口：
具备审查能力的 Agent 已指出 active 结论违反硬约束，但该结论没有被软废弃，
审查结论也没有通过候选池进入共享记忆。

## 2. 通用修复

### 2.1 数值槽位归因

预算抽取改为：

1. 在预算标签后的有界窗口内优先寻找带货币前缀或后缀的金额；
2. `元/人民币/CNY/USD` 等金额优先于人数、天数、轮次等计数；
3. 无货币单位时只接受紧邻预算赋值连接词的数值；
4. `预算需要两人确认` 不生成预算 Claim。

该逻辑不包含 A/B 实验值。

### 2.2 动态审查权限

审查权限来自以下任一来源：

- 当前语义动作是 `REVIEW_OUTPUT`、`REVIEW_SCHEMA`、`VERIFY_CLAIM` 或
  `DIAGNOSE_FAILURE`；
- 动态能力画像包含 `validation`、`schema_review`、`failure_review` 或
  `final_deliverable_review`。

Agent 名称不参与权限判断。

### 2.3 定向软废弃

只有同时满足以下条件的 active 事实才被软废弃：

1. 输出来自具备审查权限的 Agent；
2. 输出包含明确阻断语义；
3. 阻断语句或相邻上下文能定位到该事实的结构化槽位和值。

系统不会因一条审查失败而清空全部记忆。未被点名的预算、偏好、证据等事实
继续保持 active。废弃采用 `soft_deprecate` 和补偿事件，不删除审计证据。

### 2.4 阻断结论入候选池

阻断结论被编译为 `slot.system.failure_pattern` 的 CCF v2 Claim，经
State-to-Memory Bridge、规则准入和 MemoryView 后供后续任务使用。它不会
绕过候选池直接写入长期记忆。

### 2.5 MemoryView 一致性

Memory 状态变更后，同一 MemoryView 立即刷新：

- deprecated/superseded Claim 从 active 列表移到 historical；
- `revision_guard` 只暴露 active/provisional Claim；
- 无 active Claim 的视图不再进入 Prompt View。

## 3. 验收边界

v5.14g 是确定性机制验收，不调用 Provider。它证明规则、生命周期和审计链按
设计工作，但不能证明 A10 真实质量已经恢复。下一阶段必须在相同冻结任务、
Agent、模型、轮次和评分口径下重跑 v5.14f 正式实验。
