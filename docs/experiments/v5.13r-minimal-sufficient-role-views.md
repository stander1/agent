# v5.13r 语义必要性与最小充分角色视图

## 1. 修正原因

v5.13q 已能在显式连续任务命中正式记忆时，让语义必要性覆盖纯 Token 门禁，但它仍可能将同一公共 MemoryView 放入 Planner、Writer、Reviewer 的输入。该做法恢复了上下文正确性，却可能产生重复读取和成本反弹，只解决了问题的第一层。

最终创新方案要求完整策略为：

```text
语义必要性优先
+ 最小充分上下文注入
+ 缺失字段受控补取
+ 端到端成本与交付质量核算
```

## 2. 通用实现

### 2.1 框架无关角色视图

新增 `agent_runtime.memory.context_views`，采用本地规则识别通用协作职责：

```text
planner：目标、候选项、偏好、约束、已确认决策
writer：目标、偏好、约束、决策、证据、交付要求、修订
reviewer：目标、约束、决策、证据、风险、交付要求、修订
general：无法识别职责时的保守通用视图
```

它按当前用户任务和字段类别从原 MemoryView 的事实单元中选择内容，保留 source_view、slot 和 claim 标识；不调用 LLM，不创造新事实，也不包含旅游、Question A 或固定候选项规则。

### 2.2 当前任务也生成角色视图

长用户任务不再完整复制给每个 Agent。原任务进入 StatePool，系统分别生成 Planner、Writer、Reviewer 的最小任务视图。重复事实单元会规则去重；AutoGen Studio 对用户展示的仍是原始任务。

### 2.3 AutoGen 接收者隔离

Team 改写包只携带带接收者标签的分区视图。每个 Agent 调用前，Driver 再水合为：

```text
当前任务角色视图
+ 该 Agent 的最小记忆视图
+ 最新上游 Agent 完整输出
+ 更早一条上游输出摘要
```

Planner 不会收到 Writer/Reviewer 的分区，Writer 和 Reviewer 也只读取自己的视图。Schema、消息克隆、协作组隔离和记忆准入门禁保持强制。

### 2.4 缺失字段补取

当用户显式引用前序结果、已准入 MemoryView 确实命中，并且最小视图缺少用户明确要求的字段时，系统通过 MemoryRef 的来源状态执行一次受限查询片段解析。默认最多读取两个来源状态、每个状态一个相关 chunk；该访问计为 evidence snippet escalation，不等同于默认 full raw。

## 3. 成本与质量口径

新增指标：

```text
current_task_source_tokens
current_task_role_view_tokens
current_task_role_view_saved_tokens
memory_source_view_tokens
minimal_role_view_tokens
role_view_saved_tokens
memory_field_fetch_count
memory_field_fetch_tokens
receiver_role_view_hydration_count
final_delivery_assessed_count
final_delivery_valid_count
final_delivery_invalid_count
final_delivery_valid_rate
```

端到端协作成本继续使用：

```text
direct_message_tokens
+ prompt_view_tokens
+ retrieved_memory_tokens
+ control_llm_tokens
+ retry_tokens
```

字段补取片段只有进入最终角色视图后才计入 Prompt 成本，不能同时作为另一份 LLM Token 重复相加。最终交付规则通过率用于守住基本可交付性；真实内容质量仍需原生组、观察组、接管组使用同一外部评分口径评测。

## 4. 验证结果

```text
最小角色视图单元测试：通过
AutoGen 共享记忆与接收者隔离测试：通过
全量测试：198 tests，全部通过
AutoGen Team benchmark：通过
完整 release gate：全部步骤通过
```

门禁曾发现把完整当前任务重新放回 Team 包装会导致 2071 Token 的任务改写为 3201 Token。实现随后改为当前任务角色视图，门禁重新通过；没有通过放宽 Token 门禁掩盖该问题。

## 5. 当前边界

1. 角色识别依赖 Agent 名称、职责说明中的通用词；无法识别时使用 general 视图。
2. 规则选择器不保证理解所有隐含指代；显式具名步骤和前序引用最可靠。
3. 最终交付规则校验不是外部 LLM 质量评分，两者必须分开报告。
4. MemoryView 可跨启动持久化，但来源状态的字段片段补取目前只在同一托管进程的连续任务链内保证。跨 AgentLite 进程重启后的旧状态原始片段展开，需要后续增加共享 StatePool 索引持久化。
