## 3. 失败任务

### 3.1 A2：旧交付物被误当作当前交付物

Managed 的 Planner 和 Writer 已处理 A2 候选比较，但 Reviewer 最终输出退回到
A1 的需求清单，匿名评分为 0。

Trace 证明 A2 的完整当前任务已进入 Planner、Writer、Reviewer 的输入，且
`current_task_units_preserved=true`。因此问题不是“当前问题没有传入模型”，而是：

1. 共享记忆再次强调了 A1 需求；
2. Reviewer 生成了过时交付物；
3. Final Delivery Guard 只检查结构、审查语气和数值上限，没有验证输出是否完成
   当前任务；
4. 终止条件把该过时成果判为有效并提前结束。

这说明现有“当前任务保真”只覆盖输入视图，不覆盖最终输出语义。

### 3.2 A10：不同预算语义被错误合并

Managed 的 A10 匿名评分为 4。主要错误包括：

- 冻结住宿费用应为 760 元，输出被改为 360 元；
- 冻结核心活动费用应为 180 元，输出被改为 100 元；
- 分项之和为 2000 元，却写成 2020 元；
- 决策日志把 A4 的预算约束错误改成“总计不超过 200 元”。

根因是通用 Claim 抽取把以下不同事实都映射到同一个语义身份：

```text
slot_id = slot.project.requirement
scope = constraint.budget
```

被错误合并的值包括：

```text
3000 元：总预算上限
2320 元：阶段估算总额
2600 元：后续总预算上限
200 元：伴手礼专项预算
```

在 A10 Reviewer 输出阶段，MemoryView 把 200 选为 active value，Memory Adoption
Guard 又把原文中的一处 3000 自动替换成 200，直接制造了“总计不超过 200 元”的
错误。这不是模型单独产生的错误，而是 CCF 语义身份过粗和规则修复共同造成的
运行时缺陷。

### 3.3 B10：相同事实被误判为新旧冲突

B10 的 Writer 实际生成过 6374 字完整手册，但最终交付只剩 531 字内部控制包：

```text
AGENTLITE_MEMORY_CONFLICT v1
```

Trace 中同一个事实同时出现在 active 和 historical：

```text
slot.runtime.config/config.alert_id = alert_071
```

结构化归因没有先排除“新旧值完全相同”的情况，于是将其判为 `mixed`。守卫随后
发现不存在可替换的不同历史值，记录 `historical_value_missing`，并用内部冲突包
覆盖正常 Agent 输出。Writer 和 Reviewer 多次被同一误报覆盖，最终达到 9 turn
上限。

因此，`Maximum number of turns 9 reached` 是结果，不是根因。单纯增加轮次只会让
错误冲突包继续循环。

## 4. 观测口径缺口

正式报告中的 `model_visible_protocol_marker_count=0` 只统计输入重写阶段的协议标记，
没有统计 Memory Adoption Guard 改写后的 Agent 输出。因此 B10 已向模型和最终结果
暴露 `AGENTLITE_MEMORY_CONFLICT`，汇总指标仍显示 0。

后续必须把输入、Agent 输出和最终交付三个表面的协议泄漏统一计数。

弥补 CCF 身份错误、记忆采用误报和最终交付错配，因此总体仍未通过。

## 6. 下一阶段修复边界

下一阶段应命名为 `v5.14i CCF Identity and Guard Containment`，只修复通用机制：

1. 将预算上限、估算总额和专项预算映射为不同的稳定语义范围；
2. 从结构化预算表中保留带实体或费用类别的数值事实；
3. active 与 historical 值相同的 Claim 不得计为冲突；
4. 规则修复必须覆盖全部已匹配冲突，不能“只替换一处就宣告安全”；
5. 内部冲突控制包不得成为模型可见消息或最终交付物；
6. Final Delivery Guard 增加当前任务交付物保真检查，防止旧成果提前终止；
7. 协议泄漏指标覆盖输入、Agent 输出和最终交付三个表面。

这些修复不认识 A/B 任务，不添加旅行或安全审计专用规则。验收先使用通用合成
回归证明机制，再重新运行冻结的 v5.14h 正式任务。
