# v5.12n AutoGen Rewrite Fallback Matrix 实验记录

## 版本定位

`v5.12n` 继续做真实改写的安全硬化，不扩大真实改写范围。它把 `v5.12m` 的单个失败样例扩展为失败矩阵，用来证明多个常见失败场景都能被稳定分桶，并且不会修改 AutoGen 原生消息。

```text
fallback matrix：回退矩阵。表示一次实验覆盖多种回退原因。
fallback bucket：回退分桶。表示把底层原因归并成可统计的大类。
```

## 实现内容

- AutoGen Driver phase 更新为 `v5.12n`。
- 新增 `examples/autogen_rewrite_fallback_matrix_smoke.py`。
- 新增 `examples/run_autogen_rewrite_fallback_matrix_smoke.py`。
- 新增 `_text_message_content`，让空 `TextMessage(content="")` 在进入状态池前归入 `empty_text_payload`。
- 保留 `v5.12m` 的 `fallback_buckets` / `fallback_bucket_counts` 事件字段。

## 可表述结论

AgentLite 的 AutoGen 真实改写链路已经具备更完整的安全回退证据：空输入、空文本、短文本成本门控失败、非 TextMessage 类型这四类场景都会保留原生消息，并记录可统计的 fallback bucket。这样可以向评审说明系统不是“强行改写”，而是带有可回滚守卫的渐进式跨框架运行时层。

## 仍不能表述为

```text
已经支持 HandoffMessage / ToolCall 的真实改写；
已经真实替换 AutoGen Team 层广播策略；
已经接管 AutoGen Studio / 网页端；
已经完成真实 LLM AutoGen 任务的质量、延迟、token 综合评估。
```

## 下一步建议

下一步可以进入真实改写类型扩展前的最后准备：把失败矩阵纳入固定回归命令，并设计 `HandoffMessage` / `ToolCall` 真实改写的最小安全条件。只有当条件清楚后，再进入对应消息类型的真实改写实现。
