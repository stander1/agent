# v5.13o 不可变实验归档与精确用量绑定

## 1. 问题根源

旧实验链路有三个独立风险：

1. `code_app.py` 启动时会清空同名 `llm_usage.jsonl`，重复使用输出目录会覆盖旧证据；
2. `agentlite report ... --session-id latest` 按目录中的最新 Session 取数，不保证它就是当前实验产生的 Session；
3. 外部 `llm_usage_summary.json` 只有 Token 总数，没有 `run_id` 和 `session_id`，因此可以被错误拼接到另一次运行。

这不是 Token 算法问题，而是实验身份和证据生命周期没有形成闭环。

## 2. 新归档协议

代码端实验目录现在按以下顺序形成：

```text
agentlite_session_binding.json       AgentLite 启动器独占创建
experiment_run.json                 实验程序独占创建
llm_usage.jsonl                     逐次 Provider 调用，携带 run_id/session_id
llm_usage_summary.json              Provider 汇总和绑定对象
sequence_result.json                完整任务、消息和交付结果
experiment_result.json              实验产物哈希与完成状态
agentlite_data/sessions/<session>   本次 Session 的自包含快照
agentlite_session_report.json       自动生成的精确 Session 报告
agentlite_session_report.md         自动生成的可读报告
agentlite_session_result.json       绑定校验、Session 目录摘要和报告哈希
```

文件使用独占创建。目录中只要存在旧证据，新运行就会失败，不再静默清空或覆盖。

## 3. 自动绑定规则

报告生成前必须同时满足：

1. `experiment_run.json`、`experiment_result.json` 和 Provider 汇总的 `run_id` 一致；
2. AgentLite 启动绑定、实验清单、实验结果和 Provider 汇总的 `session_id` 一致；
3. Provider 汇总文件哈希与实验结果中冻结的哈希一致；
4. Session 路径与 `data_dir/sessions/session_id` 一致；
5. 归档中的 Session 快照存在，并且重新计算后的文件数、字节数和目录哈希与冻结结果一致；
6. 已自动生成的 Session 报告哈希没有变化。

任意一项不一致，CLI 会返回非零状态，不会用 `latest` 猜测，也不会生成看似正常的混合报告。

## 4. 正式三组命令

```bash
export EXP_ID="$(date +%Y%m%d-%H%M%S)"
export RUN_ROOT="runs/ordinary-developer/v5.13o-${EXP_ID}"
export TRACE_ROOT=".agentlite-exp/v5.13o-${EXP_ID}"
export APP="experiments/ordinary-developer-autogen/code_app.py"
export SEQ="experiments/ordinary-developer-autogen/question_A_sequence.json"
export CFG="experiments/ordinary-developer-autogen/agent_config.json"
mkdir -p "$RUN_ROOT" "$TRACE_ROOT"

python "$APP" \
  --question-sequence-file "$SEQ" \
  --agent-config "$CFG" \
  --temperature 0 \
  --max-turns 6 \
  --experiment-mode native \
  --output-dir "$RUN_ROOT/native"

agentlite autogen \
  --data-dir "$TRACE_ROOT/observed" \
  --experiment-dir "$RUN_ROOT/observed" \
  --rewrite off \
  --broadcast-mode shadow-only \
  -- python "$APP" \
    --question-sequence-file "$SEQ" \
    --agent-config "$CFG" \
    --temperature 0 \
    --max-turns 6 \
    --experiment-mode observed \
    --output-dir "$RUN_ROOT/observed"

export AGENTLITE_MEMORY_SCOPE="v5.13o-A-${EXP_ID}"
agentlite autogen \
  --data-dir "$TRACE_ROOT/managed" \
  --experiment-dir "$RUN_ROOT/managed" \
  -- python "$APP" \
    --question-sequence-file "$SEQ" \
    --agent-config "$CFG" \
    --temperature 0 \
    --max-turns 6 \
    --experiment-mode managed \
    --output-dir "$RUN_ROOT/managed"
```

`--experiment-dir` 必须与目标程序的 `--output-dir` 相同。两者不同会立即失败，防止 Session 绑定写在一个目录而 Provider 用量落到另一个目录。

三组完成后直接比较：

```bash
python experiments/ordinary-developer-autogen/compare_stateful_runs.py \
  --native-dir "$RUN_ROOT/native" \
  --observed-dir "$RUN_ROOT/observed" \
  --managed-dir "$RUN_ROOT/managed" \
  --output-dir "$RUN_ROOT/comparison"
```

比较器默认验证三组归档身份、Provider 哈希和两组 AgentLite Session 绑定。旧版本数据只能显式增加 `--allow-legacy-unbound`，并会被标记为未验证证据。

## 6. 当前边界

本轮解决的是代码端“一次程序运行对应一次实验归档”。任意普通应用只要按标准文件写出带绑定对象的 `llm_usage_summary.json`，都可以使用同一校验机制。

AutoGen Studio 后端进程中可以包含多个网页 Run，一个进程级 Session 不能直接等价为一个实验任务。因此 Studio 仍使用现有 Session 追踪；后续需要增加 Studio Run ID 与 Provider 调用的逐 Run 关联，不能用本轮代码端归档数据代替。
