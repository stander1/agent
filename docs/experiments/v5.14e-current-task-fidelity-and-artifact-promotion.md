# v5.14e 当前任务保真与成果提升

## 证据结论

v5.14d 真实实验已经达到 Provider Token 和端到端协作 Token 的降幅目标，
但 B 组质量明显下降。归档 trace 证明这不是记忆池读取慢或模型能力不足，
而是两个通用运行时缺陷叠加：

1. 当前用户任务与历史上下文一起进入最小角色视图，结构化字段被裁掉；
2. Reviewer 的验收摘要未被识别为“仅审批”，被错误当作最终正文。

A 组出现 15 次记忆查询、0 次命中、0 次注入。该链路行为本身正确，旧验收器
要求“只要查询就必须注入”属于口径错误。

## 通用修复

### 当前任务精确保真

当前用户输入被标记为最高优先级区域。运行时先按语义单元解析，再将这些单元
作为强制保留项进入每个动态能力视图。历史消息与已准入记忆仍按接收者能力、
语义动作和所需字段进行裁剪。

当最小视图不能完整保留当前任务时，运行时选择原始任务文本，而不是继续追求
单条消息缩短。每个接收者都会记录 `current_task_units_preserved`，会话报告
汇总 `current_task_fidelity_failure_count`。

该机制不依赖 Planner、Writer、Reviewer 名称，不包含 A/B 题编号、旅游地名、
审计样例值或固定字段。

### 最终成果提升

最终交付解析器使用“审查过程描述、被验收对象、是否要求修订、是否声明已整合
为完整终稿”等语义判断 Reviewer 输出。若 Reviewer 只是批准前序成果，最终
正文提升自已经存在且通过交付守卫的前序产物；若 Reviewer 自己给出完整终稿，
则保留 Reviewer 成果。

### 无命中语义

记忆链路验收改为：

```text
query > 0 and hit == 0  -> injected 必须为 0
query > 0 and hit > 0   -> injected 必须大于 0
```

因此系统不会为了展示“共享记忆生效”而向 Agent 注入无关内容。

## 成本边界

当前任务保真可能使某一条消息无法缩短，这是有意的质量优先策略。正式结论仍按
端到端口径比较：

```text
direct_message_tokens
+ prompt_view_tokens
+ retrieved_memory_tokens
+ control_llm_tokens
+ retry_tokens
```

Provider Token、端到端协作 Token、完整交付数和双盲质量分必须同时过门禁，
不能用单条消息的缩短掩盖质量下降。
