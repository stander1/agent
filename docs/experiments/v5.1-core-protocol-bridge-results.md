# v5.1 核心协议与状态到记忆桥接补齐记录

日期：2026-06-22

## 1. 本轮目标

根据 `docs/competition/工程校验-二次复核-外部审计问题核对.md`，本轮先处理不依赖 AutoGen 的 P0/P1 架构缺口：

1. SHP 不再只是 runtime 内部临时 dict，而是有显式 envelope 结构。
2. State-to-Memory 不再散落在 `runtime.py` 中，而是抽成独立 Bridge Lite。
3. Runtime 写长期记忆时，不再绕过候选池和 Admission。
4. degraded fallback 不能伪装成正常长期记忆。

AutoGen / LangGraph 等跨框架适配本轮不做，等核心接口稳定后再接。

## 2. 新增模块

### 2.1 `agent_runtime/protocol/shp.py`

新增：

- `SHPHeader`
- `SHPControl`
- `SHPEnvelope`
- `build_handoff_envelope()`

当前 SHPEnvelope 结构：

```json
{
  "header": {
    "shp_id": "...",
    "protocol_version": "shp.v1-lite",
    "task_id": "...",
    "round_id": 1,
    "sender": "retriever",
    "receiver": "writer",
    "msg_type": "agent_output",
    "created_at": "..."
  },
  "control": {
    "action": "retriever_completed",
    "readiness": "ready",
    "allowed_next_step": "continue",
    "access_policy": "prompt_view_first",
    "capability_hint": ["writer"],
    "parameters": {}
  },
  "summary": "...",
  "state_refs": [],
  "memory_refs": [],
  "metrics": {}
}
```

这解决的是：

- 外部审计 D-07：SHP 协议包规范化不足。

仍未解决的是：

- 16 种消息类型；
- 完整 Capability Router；
- Readiness Barrier 状态机；
- 跨框架 message adapter。

### 2.2 `agent_runtime/bridge/state_memory_bridge.py`

新增：

- `PromotionViewRenderer`
- `MemoryPromotionCompiler`
- `SemanticValidatorLite`
- `StateToMemoryBridgeLite`

当前 Bridge Lite 路径：

```text
runtime state refs
  → PromotionViewDraft
  → PromotionCandidate
  → SemanticValidatorLite
  → MemoryStoreLite.write_memory_candidate_with_report()
  → Memory Admission
  → admitted-only MemoryObject / ClaimCard / MemoryView
```

这解决的是：

- 外部审计 D-02：State-to-Memory Semantic Bridge 完全缺失的问题，当前已补为 Lite 版本。
- “raw state 直接进入 memory pool”的风险，当前 runtime 写记忆统一经过 candidate/admission。

仍未解决的是：

- 不同 state_type 的完整 Promotion View 模板；
- Memory Promotion Compiler 的复杂语义蒸馏；
- Semantic Validator 的冲突、时效性、新颖性检查；
- Batch Compaction；
- Conflict Resolver。

## 3. Runtime 接入变化

### 3.1 `_build_shp_message()`

原来：

```text
runtime.py 内部拼简单 JSON dict。
```

现在：

```text
runtime.py 调用 build_handoff_envelope()，输出 SHPEnvelope JSON。
```

`RuntimeMessage` 外层仍保留 sender / receiver / state_refs / memory_refs，因此 trace 和监控解析的基础字段不受影响。

### 3.2 `_write_runtime_memory()`

原来：

```text
有 contract_guard 时走 write_memory_candidate_with_report()
没有 contract_guard 时直接 write_memory_with_report()
```

现在：

```text
全部走 StateToMemoryBridgeLite.promote()
```

这意味着：

1. 所有长期记忆写入都要先变成候选。
2. 所有候选都要经过 SemanticValidatorLite。
3. 所有候选都要经过 Memory Admission Lite。
4. degraded fallback 会被降为 audit_only，不写入正式长期记忆。

## 5. 当前状态

已解决：

1. SHP 有了显式 envelope。
2. State-to-Memory Bridge 从 runtime 内部逻辑变成独立模块。
3. Runtime 记忆写入统一经过候选池和 Admission。
4. degraded fallback 不会进入正式长期记忆。

还未解决：

1. Typed Artifact Digest 仍是通用摘要。
2. Batch Compaction 仍未实现。
3. Conflict Resolver 仍未实现。
4. SchemaRegistryLite / CanonicalClaimLite 仍需进一步结构化。
5. State GC 仍是 Lite，没有 quota / retry loop / 两阶段 tombstone。
6. AutoGen 适配暂缓。

## 6. 下一步建议

下一步建议进入：

```text
v5.2 Typed Artifact Digest 与非文本状态增强
```

优先实现：

1. `TypedArtifactDigestBuilder-lite`
2. code / json / markdown / log / table 类型识别
3. `retrieval_state` 增加 embedding metadata
4. 最小 `embedding_state`

理由：

这一步直接回应外部审计中“非文本状态和类型感知摘要不够硬”的问题，也能增强比赛答辩时的可展示证据。
