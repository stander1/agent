# v5.14y Active Fact and Terminal Delivery Acceptance

v5.14y is a mechanism acceptance derived from the failed v5.14x formal run.
It does not change the formal task set, agent prompts, model, output length, or
quality thresholds.

The release hardens four domain-neutral boundaries:

1. Budget facts require sufficient local evidence before they can become a
   global upper bound. Component allocations, reserves, numeric note headings,
   and ambiguous amounts are not promoted as caps.
2. Historical decision-log facts stay available in the original artifact but
   are excluded from the active claim view and current numeric delivery check.
3. A review may contain historical rejection findings and then explicitly
   approve the latest submitted artifact. Revision requirements occurring
   after the terminal approval remain blocking.
4. Missing task-required evidence with a user-defined fallback produces a
   complete degraded artifact containing the fallback decision, missing source,
   uncertainty, and allowed next step.

The implementation contains no Question A/B branch, business-entity literal,
or fixed-agent-role requirement. The openEuler acceptance is deterministic and
does not consume Provider tokens.
