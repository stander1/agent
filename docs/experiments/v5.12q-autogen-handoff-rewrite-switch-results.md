# v5.12q AutoGen Handoff Rewrite Switch 实验记录

## 版本定位

`v5.12q` 是 HandoffMessage 真实改写的受控开关版本。

switch：开关。意思是能力已经存在，但默认关闭。只有显式设置 `AGENTLITE_AUTOGEN_HANDOFF_REWRITE=1`，并且 Handoff typed rewrite candidate 通过全部安全门控时，系统才会真实替换 AutoGen `HandoffMessage.content`。

## 实现内容

- AutoGen Driver phase 更新为 `v5.12q`。
- 新增环境变量：`AGENTLITE_AUTOGEN_HANDOFF_REWRITE`。
- `driver_details` 暴露：
  - `handoff_rewrite_enabled`
  - `handoff_rewrite_env`
- 默认关闭时：
  - 生成 `typed_rewrite_candidate`
  - 不修改 AutoGen 原生 HandoffMessage
  - 记录 `handoff_typed_rewrite_candidate_dry_run_only`
- 开启时：
  - 要求 candidate 满足全部安全条件
  - 克隆 HandoffMessage，仅替换 `content`
  - 保留 `source`、`target`、`id`、`metadata`、`context`
  - 记录 `mutation_applied=true`

## 可表述结论

AgentLite 已经支持受控的 AutoGen HandoffMessage content 真实改写。它不是默认开启，而是在显式开关打开、候选改写语义安全、SHP schema 有效、Prompt View 可用、token 确实降低时，才替换 HandoffMessage 的 content。

这一步证明系统已经从“只做影子候选”推进到“可控真实接管 Handoff 内容层”。

## 仍不能表述为

```text
已经支持 ToolCallSummaryMessage 真实改写；
已经真实替换 AutoGen Team 层广播策略；
已经接管 AutoGen Studio / 网页端；
所有 Handoff 场景都能安全真实改写。
```

## 下一步建议

下一步可以进入 `v5.12r`：扩展 Handoff rewrite 压测矩阵。

建议至少覆盖：

```text
1. 多个 HandoffMessage 同时进入 agent；
2. HandoffMessage 带非空 context；
3. candidate token 不降低时必须回退；
4. schema / prompt_view 缺失时必须回退；
5. 开关关闭时必须保持原生消息。
```

通过这些矩阵后，再考虑 ToolCallSummaryMessage 的真实改写。
