# v5.13m 时序视图、事实依据与终止收口

## 1. 本轮问题

`v5.13k` 的 A1-A3 接管组真实实验曾把 A3 判为成功，但最终结果只选择了目的地，仍要求团队继续生成完整行程。进一步修复后，`v5.13l` 已能向下游 Agent 提供当前任务和最新上游完整成果，但真实实验又暴露出两个问题：

1. Reviewer 已经修正预算并给出完整成果时，守卫没有识别“整合后的当前阶段最终成果”边界，导致 Team 多运行一个周期。
2. 多出的周期中，Planner 把不存在于用户原始请求中的“膝盖不好”写成“用户最新确认”，后续 Writer 和 Reviewer 据此静默更换目的地。

这两个问题都属于通用运行时语义可靠性，不是 Question A 的领域评分问题。

## 2. 根因

### 2.1 时序视图丢失最新成果

旧 Prompt View 从按时间排列的消息批次头部截取固定字符。当前任务和最新 Writer 成果通常位于批次尾部，因此 Reviewer 可能收到旧轮次内容。相同压缩内容还会被复制到每一条输入消息，既造成上下文重复，也使 Token 统计失真。

### 2.2 最终成果边界词覆盖不完整

Reviewer 的第一份 A3 输出包含：

```text
### 整合后的当前阶段最终成果
...
FINAL_ANSWER_READY
```

守卫只识别“最终方案、最终答案、最终交付物”等边界，没有把“成果”作为通用交付名词，因此把已经修正的完整成果误当成仍需继续的审查稿。

### 2.3 Agent 断言缺少原始用户依据

共享记忆和压缩上下文可以包含 Agent 推断，但旧守卫没有区分“Agent 假设”和“用户明确确认”。当模型把推断写成直接引语并声称是用户确认时，错误内容仍可能终止并进入长期记忆。

## 3. 通用修复

### 3.1 Chronology-aware Prompt View

Agent 输入改写现在按以下优先级构建单一 Prompt View：

1. 当前原始用户任务，完整保留；
2. 原始用户请求历史，作为事实依据；
3. 最新上游 Agent 消息，完整保留；
4. 再前一条上游消息，仅保留首尾摘要。

改写后只生成一条输入消息，不再把同一压缩内容复制到整个消息列表。完整原始内容仍保留在 StatePool 审计记录中。

### 3.2 明确最终成果边界

通用 FinalDeliveryGuard 增加“成果”边界，能够识别“最终可交付成果”和“整合后的当前阶段最终成果”。Reviewer 实验提示词同时统一为：合格或完成必要修正后，第一行写 `## 最终可交付成果`，正文只保留面向用户的完整交付物。

只有审查意见、修订清单或要求其他 Agent 继续工作的文本，即使带有完成标记，也仍然不能终止或进入长期记忆。

### 3.3 原始用户事实依据守卫

Driver 和终止器保存有界的原始用户任务历史。若最终候选使用“您最新确认”“用户明确指出”等表达，并直接引用一项不存在于原始用户请求中的事实，则记录：

```text
ungrounded_user_confirmation_claim
```

该候选不能成为成功交付，也不能进入长期记忆。规则不认识旅游地点、预算或 Question A，只核对“声称来自用户的直接引语”是否真的存在于用户输入中。

该实验验证了时序 Prompt View 能把完整 A2 成果传给 A3，但 A3 的最后一轮引入了无依据的“膝盖不好”事实，因此 3 / 3 不能作为真实质量成功率。

### 4.2 使用 v5.13m 守卫回放原始输出

| 任务 | v5.13l 原报告 | v5.13m 离线判断 | 说明 |
|---|---|---|---|
| A1 | 成功 | 成功 | 无新增事实依据问题 |
| A2 | 成功 | 成功 | 无新增事实依据问题 |
| A3 最后一轮 | 成功 | 拒绝 | 检出无依据用户确认 |
| A3 第一轮 Reviewer | 未终止 | 接受 | 已包含预算修正后的完整成果 |

因此，如果 v5.13m 在相同模型轨迹上运行，会在 A3 第一轮 Reviewer 的完整修正成果处结束，不会进入产生错误“膝盖约束”的下一周期。

### 4.3 v5.13m 在线复验中发现并修复规则误报

首次在线复验中，守卫把“待确认项”中的“确认”和后续引号标题组合成“用户已确认的直接引语”，导致 A1 三轮 Reviewer 输出均被错误拒绝。该实验在 A1 结束后主动中止，没有继续消耗 A2/A3 Token。

正则随后收紧为只匹配紧邻的明确断言，例如“您的最新确认（‘…’）”和“用户明确指出：‘…’”。新增反例测试后，旧 A1 三份 Reviewer 输出离线回放均从错误拒绝恢复为有效。该修复不放宽真正的无依据直接引语检查。

质量核验结果：

1. A1、A2、A3 均以 `## 最终可交付成果` 开头，并由 Reviewer 在首个周期结束；
2. A3 从 A2 的三个候选中继续选择莫干山，没有静默引入新目的地；
3. 没有再次出现无来源的健康限制或伪造用户直接引语；
4. A3 包含完整三日安排，预算表五项合计 2,800 元，低于 3,000 元硬上限；
5. 交通费用说明中的示例拆分仍不够严谨，说明纯提示词不能保证所有算术细节。正式旅游应用应给领域 Agent 配计算器或结构化预算工具，而不应在 AgentLite 通用运行时写入旅行规则。

新增测试覆盖：

1. 当前任务、历史原始请求和最新上游成果的时序优先级；
2. 改写后单消息输入和 Token 下降门禁；
3. “整合后的当前阶段最终成果”可以结束；
4. 无依据的用户确认不能结束；
5. 无依据的最终候选不能进入长期记忆。
6. “待确认项”和“请回复确认”不会被误判为用户已经确认的直接引语。

## 6. 当前证据边界

本轮已经完成 v5.13m MiMo A1-A3 接管组在线复验，但没有重新运行同版本原生组和观察组，也没有执行独立 LLM 盲评。因此：

1. 51,572 LLM Token 和 11.11% 实际传输节省可作为本次接管组实测值；
2. 与 v5.13l 的差异可用于说明修复前后无效轮次变化，但不替代同版本三组公平对照；
3. 3 / 3 是协议和人工核验结果，不应表述为独立裁判给出的满分质量；
4. 共享记忆本轮命中 8、注入 5，但有效采用仍为 0、待评估为 5，不能据此宣称记忆已经提升质量。
