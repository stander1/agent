# v5.12x AutoGen Team Benchmark Results

`v5.12x` 在 `v5.12w` Team rewrite 边界矩阵之后，补充真实对照实验：
同一个只导入 AutoGen 的用户程序分别以原生方式和 AgentLite 托管方式运行。

目标不是评测某个业务问题的模型能力，而是验证接入方式：

- 原生 AutoGen：`RoundRobinGroupChat.run_stream(task=...)` 会把完整长 task 分发给 Team；
- AgentLite 托管 AutoGen：用户代码不导入 AgentLite，但启动器注入 Driver，Team 入口 task 被替换为紧凑的 `AGENTLITE_TEAM_REAL_REWRITE v1`；
- 质量口径：用确定性 AutoGen agent 输出检查最终交付是否仍覆盖架构路线、runtime hooks、StatePool、Prompt View、SHP、schema、fallback、metrics、token 等必需项。

## Interpretation

这轮实验说明：

1. 用户程序不导入 AgentLite，仍可被托管启动器透明接管；
2. 原生 AutoGen 组确实把完整长 task 作为 Team 首条消息传递；
3. 托管组在 Team 入口看到的是 `AGENTLITE_TEAM_REAL_REWRITE v1`，并携带 `StatePool refs + receiver Prompt Views`；
4. 原生 marker 在托管首条消息中为 0，说明不是“把原文包一层继续传”，而是把长正文移入 StatePool 后传紧凑引用；
5. 最终交付质量分没有下降，说明这次 rewrite 验证没有以牺牲交付完整性换取 token 下降。

仍需保守表述：

- 该实验覆盖 AutoGen Python 代码端的 `RoundRobinGroupChat.run_stream(task: str)`；
- 尚未覆盖 AutoGen Studio / 网页端；
- 尚未覆盖所有 AutoGen Team 实现和所有 task 类型；
- 该实验是确定性 benchmark，不是高并发真实 LLM 业务压测。
