# v5.4 State Lifecycle / GC / Readiness / Cold Access 记录

日期：2026-06-22

## 1. 本轮目标

根据 `docs/competition/工程校验-二次复核-外部审计问题核对.md`，本轮补齐 SHP-State 和 CMJCC 中不依赖 AutoGen 的运行时治理缺口：

1. State lifecycle 只有字符串，没有状态机 API。
2. State GC 只有最基础冷状态删除，没有 quota-based eviction。
3. Tombstone 不是两阶段回收。
4. Retry loop 没有压缩 summary。
5. Cold Access Manager / Access Escalation 没有最小实现。
6. Readiness Barrier 没有落地。

## 3. Quota-based GC 与两阶段 Tombstone

新增：

```text
StateQuotaConfig
StatePoolLite.collect_garbage()
StatePoolLite.sweep_tombstones()
```

现在 GC 分两阶段：

1. `collect_garbage()`：逻辑驱逐，将状态标记为 `evicted`，写 tombstone，但不立刻删除 payload。
2. `sweep_tombstones()`：物理清理 payload，将状态标记为 `deleted`。

这样可以避免下游 Agent 正在读取时被同步删盘，也保留 fallback summary 供 Prompt View 使用。

## 4. Retry Loop Summary

新增：

```text
StatePoolLite.write_retry_loop_summary()
```

它把多次失败/修复尝试压缩成一个 `retry_loop_summary` 状态，避免失败循环产生大量完整状态。

## 5. Cold Access Manager Lite

新增：

```text
ColdAccessBudget
ColdAccessReport
StatePoolLite.request_cold_access()
```

当前规则：

1. 每个 task 有最大 cold read 次数。
2. 每个 phase 有最大 cold bytes。
3. 没有 audit payload 或预算超限时拒绝读取。
4. 成功读取时返回 payload 和预算剩余。

这不是完整 Cold Access Manager，但已经形成可测试的冷数据访问预算入口。

## 6. Readiness Barrier Lite

新增：

```text
agent_runtime/core/readiness.py
ReadinessBarrierLite
ReadinessReport
```

Runtime 在构建 SHPEnvelope 时会写入：

```text
control.readiness
control.allowed_next_step
metrics.readiness_reasons
```

当前规则：

1. 没有 state_refs：`blocked`。
2. 包含 failure_state 或 degraded 标记：`degraded`，只允许 review/retry。
3. 状态齐全：`ready`。

## 8. 已解决与未解决

已解决：

1. State lifecycle API 落地。
2. Quota-based GC Lite 落地。
3. Tombstone 两阶段回收落地。
4. Retry Loop Summary Lite 落地。
5. Cold Access Manager Lite 落地。
6. Readiness Barrier Lite 接入 SHPEnvelope。

仍未解决：

1. Read Lease 仍是单进程内存版，没有 TTL / heartbeat / fencing token。
2. GC 仍是 Lite，不是最终方案完整 9 层 GC。
3. Cold Access 没有 raw span resolver / prefetch scheduler / raw view cache。
4. Readiness Barrier 当前是规则版，没有复杂信息充分性评分。
5. AutoGen 接入按用户要求暂缓。
