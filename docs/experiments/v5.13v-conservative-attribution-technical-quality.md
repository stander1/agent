# v5.13v 保守记忆归因、归一化成本与技术质量评审

## 1. 问题来源

v5.13u 已经记录 MemoryView 到下游输出的采用证据，但独立复核发现两类口径仍然偏乐观：

1. 当前任务已经明确给出的事实，可能因为与记忆事实措辞不同而没有被排除，继而被误计为记忆贡献。
2. 三组的实际 LLM 调用轮次不同，直接比较总 Token 会同时混入运行时效果和额外协作轮次。
3. 原主盲评偏重任务完成、上下文和可读性，未能稳定识别 SQL 方言、配置单位和生命周期顺序等技术错误，产生满分上限效应。

## 2. 保守记忆归因

每次实际记忆注入记录：

- `current_task_source`：当前任务来自团队级任务文本还是单次调用 Prompt；
- `current_task_fingerprint`：当前任务归一化后的短指纹；
- `current_task_duplicate_fact_count`：记忆中已经由当前任务直接提供、因此被排除的事实数；
- `matched_fact_fingerprints`：排除当前任务后，下游输出仍采用的事实指纹；
- `attribution_margins`：输出支持分减去当前任务基线支持分。

规则仍然优先，不增加控制 LLM。只有满足下列条件之一才记录为有效采用：

1. 输出明确引用 Memory ID 或 MemoryView ID；
2. 事实确实进入了该 Agent 的最小角色视图，当前任务支持分低于阈值，输出支持分达到阈值，且归因差值为正。

该逻辑不读取 Question A/D，不检查旅游、数据库或其他业务关键词，也不依赖 Planner、Writer、Reviewer 等角色名。

## 3. 成本双口径

实验同时保留：

1. **原始 Provider 总成本**：三组所有真实调用的 Prompt、Completion、重试和总 Token。
2. **相同逻辑调用归一化成本**：按 `task_id + agent + 同一任务中该 Agent 的调用序号` 对齐，只比较三组共同存在的调用。

额外轮次不会被删除，而是作为 `unmatched_call_count` 单独展示。这样既不掩盖重试或协作轮次差异，也能观察相同调用位置的上下文压缩效果。

## 4. 双重匿名质量评审

主盲评保持原职责：任务完成、上下文保留、正确性与一致性、清晰度与可执行性。

新增独立技术盲评，专门检查：

- 命令、SQL、代码和配置能否执行；
- 单位与参数解释是否正确；
- 并发模型、生命周期、清理和恢复顺序是否自洽；
- 是否混用技术方言、包含破坏性操作或给出无证据保证；
- 是否遗漏连续任务已经确定的硬约束。

每个技术问题必须包含候选答案中的短证据、具体问题和通用修正方向。技术问题按 `critical/high/medium/low` 分级；高危或致命问题使交付不可用，任何明确问题都会把技术分限制在 10 分以下。

最终合并分取主盲评分与技术盲评分的较低值。两套评分均在揭示 native、observed、managed 映射前冻结。评审 Token 属于实验评测成本，不计入运行时协作成本，并保存在独立评分文件中。

## 5. openEuler 验收

入口：

```bash
bash experiments/v5.13v-conservative-evidence-quality/run_openeuler.sh
```

除 v5.13u 的全部门禁外，新增三项硬检查：

1. 当前任务重复事实确实被排除，剩余归因事实具有正归因差值；
2. 三组均完成独立技术盲评；
3. 相同逻辑调用归一化成本存在且可追溯。

## 6. 结论边界

归一化调用能降低额外轮次这一混杂因素，但单次运行仍会受到模型采样和网络波动影响。最终比赛数据仍应采用多个独立实验编号重复运行，并同时报告原始总成本、归一化成本、质量区间和失败样本，而不是只报告一次最优百分比。
