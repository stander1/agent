# v5.13u 透传分类与记忆采用证据

## 1. 修改依据

v5.13t openEuler 实验已证明动态能力画像、角色视图不膨胀和端到端通信成本下降，但旧报告把 53 次“保留原生消息”统一写成 fallback（回退）。逐条核对后，其中 48 次是没有文本字段的 AutoGen 控制消息，5 次是成本门禁主动保留原生消息，真实错误回退为 0。

同一实验中，记忆检索与注入已经发生，但 `useful_memory_hit_count`（有效记忆命中数）仍为 0，因为运行时尚未记录 MemoryView 到下游输出的采用证据。

## 2. 通用实现

### 2.1 改写结果分类

每个真实改写审计事件保留旧兼容字段，同时新增：

- `rewrite_eligible`：该消息是否具有可改写内容；
- `passthrough_classification`：透传或改写结果类型；
- `error_fallback_required`：是否属于真实错误回退。

分类为：

1. `rewrite_applied`：真实改写成功；
2. `ineligible_control_passthrough`：控制消息没有可改写文本，正常透传；
3. `cost_guard_passthrough`：候选没有降低成本，主动保留原生内容；
4. `policy_guard_passthrough`：受类型、环境或协议策略保护而透传；
5. `error_fallback`：有可改写内容，但结构或可靠性校验失败。

分类只依据消息内容能力、Token 门禁和通用协议守卫，不识别任务领域或 Agent 角色名称。

### 2.2 MemoryView 采用证据

运行时只跟踪实际进入 Agent Prompt View 的记忆引用。下游输出完成后，规则引擎执行：

1. 从 MemoryView 提取原子事实；
2. 只保留实际进入该 Agent 最小角色视图的事实，完整 MemoryView 中未注入的内容不能计为采用；
3. 排除当前用户任务已经直接给出的相同事实；
4. 使用数字一致性、连续字符锚点和字符覆盖验证输出是否采用事实；
5. 写入 `autogen_memory_adoption` Trace，保存 MemoryRef、事实指纹、匹配分数和归因方式；
6. 只有取得证据才增加 MemoryObject 的 `useful_hit_count`；
7. 没有证据的注入保持 `unassessed`，不会被自动算作有效，也不会被误判为错误记忆；
8. 记忆槽位兜底推断改为依据 requirement、evidence、failure、final 等语义标签，不再依据 writer、reviewer 或 memory_manager 角色名。

该机制不调用额外 LLM，不固定 Planner、Writer、Reviewer，也不包含 Question A 的地点、预算或行程规则。

## 3. 新增核心指标

- `rewrite_ineligible_control_passthrough_count`；
- `rewrite_cost_guard_passthrough_count`；
- `rewrite_policy_guard_passthrough_count`；
- `rewrite_error_fallback_count`；
- `rewrite_error_fallback_rate`；
- `memory_adoption_event_count`；
- `memory_supported_output_count`；
- `useful_memory_hit_count`；
- `unassessed_memory_hit_count`。

`rewrite_fallback_event_count` 继续保留用于读取旧归档，但它只表示“没有改写并保留原生内容”的总次数，不能再解释为系统故障。

## 4. 验收口径

v5.13u 继续复用 v5.13s/v5.13t 的三组任务、Agent 配置、Provider 和匿名质量评分，只新增证据门禁：

1. 无文本控制消息必须进入正常透传分类；
2. 真实错误回退必须为 0；
3. 至少一条实际注入记忆取得下游采用证据；
4. `useful + wrong + unassessed = memory_injected`；
5. 每条采用事件必须可以追溯到 MemoryRef 和事实指纹。

执行入口：

```bash
bash experiments/v5.13u-evidence-attribution-acceptance/run_openeuler.sh
```

## 5. 边界

规则证据只能证明可追溯采用，不能证明所有隐式语义影响。对没有足够证据的记忆保持 `unassessed` 是刻意的保守设计。若未来引入语义判定器，其模型 Token、重试和延迟必须进入端到端成本核算。
