# v5.13p AutoGen Studio Run 级绑定

## 1. 根因

AutoGen Studio 0.4.2.2 的后端进程可以连续服务多个网页 Run。Studio 数据库将它们表示为：

```text
team.id <- session.team_id
session.id <- run.session_id
run.id <- message.run_id
```

旧版 AgentLite 只有一个进程级 `launch_*` Session。它能证明 Studio 后端已被接管，却会把同一后端中的 A1-A10 合并统计，无法回答“某一次网页提问用了多少 Token、触发了哪些改写、读写了哪些状态”。

AutoGen Studio 的 `WebSocketManager.start_stream(run_id, ...)` 在调用 `team.run_stream()` 前，已经通过 `RunContext.populate_context(run_id)` 设置了原生 Run 身份。v5.13p 复用这条官方上下文，不解析 UI 文本，也不修改 Studio。

## 2. 新身份层级

```text
AgentLite process session: launch_<uuid>
  framework Run: autogenstudio:<Studio run.id>
    Team / Agent / Core / model-client / state / memory / rewrite events
```

Trace 新增公共字段：

```json
{
  "framework_run_id": "autogenstudio:22",
  "framework_run_source": "autogenstudio_run_context",
  "studio_run_id": "22",
  "studio_session_id": "13",
  "studio_team_id": "16"
}
```

`ContextVar` 保证异步并发任务继承各自 Run；没有使用进程级全局“当前 Run”。Studio 的 SQLite 只以 `query_only` 模式读取 ID、状态和任务摘要，不读取 Team 内的模型密钥，也不写入数据库。

## 3. 生命周期与报告

每个 Run 产生：

```text
autogen_framework_run_started
autogen_framework_run_finished
autogen_driver/runs/<bounded_id>/run.json
```

物理目录名最长 16 字符；较长的代码端 Run ID 使用短前缀加稳定 SHA-256 摘要，避免 Windows 深目录触发路径长度限制。完整 `framework_run_id` 仍保存在清单和 Trace 中。

单 Run 报告命令：

```bash
agentlite report autogen-run \
  --data-dir <agentlite-data-dir> \
  --session-id <launch-session-or-latest> \
  --run-id <autogenstudio:id-or-latest> \
  --format json|markdown|csv \
  --output <path>
```

报告只筛选同一 `framework_run_id` 的 Trace。若标准 AutoGen model client 暴露 usage，则 LLM Prompt、Completion 和总 Token 自动进入该 Run；若没有 usage，不用整个 Studio 进程的 Provider 总量补齐。

## 4. 监控变化

监控新增：

```text
GET /api/framework-runs
GET /api/sessions/<AgentLite session>/runs/<framework Run>/snapshot
```

一个 Studio 后端存在 Run 级数据时，任务列表显示每个 Run，不再重复显示进程聚合项。点击某一任务后，工作流、Agent、状态、记忆和 Token 面板都只使用该 Run 的事件。

## 5. 本机验证

真实 AutoGen 0.7.5 双 Run smoke：

```text
target_returncode_zero: true
agentlite_active: true
driver_phase_current: true
two_native_studio_run_ids: true
two_run_start_events: true
two_run_finish_events: true
two_completed_manifests: true
nested_events_bound: true
```

同一进程的两个 Run：

```text
autogenstudio:101: 118 trace events
autogenstudio:102: 118 trace events
```

完整发行门禁结果：

```text
10 / 10 steps passed
189 unit tests passed
compileall passed
git diff --check passed
```

测试使用 `UserProxyAgent`，不访问外部 LLM，因此 LLM Token 为 0；它验证的是身份传播而非成本收益。真实 Studio 模型调用将通过已有 `autogen_model_client_usage` hook 按相同 Run 字段归属。

## 6. 当前边界

1. 已验证 AutoGen Studio 0.4.2.2 的 `RunContext` 契约和本机取回数据库结构；未知未来版本若移除该契约，会降级为进程级观测；
2. `--appdir` 自动识别覆盖直接的 `autogenstudio ...` 和 `python -m autogenstudio ...` 启动；Shell 字符串二次封装需要显式暴露直接命令；
3. 本版本尚未在 openEuler 虚拟机上跑真实 Studio A1-A10，新门禁先用无网络双 Run smoke 验证；
4. 本版本不声称降低了 LLM 生成 Token，只解决逐 Run 归属、报告和监控的证据边界。
