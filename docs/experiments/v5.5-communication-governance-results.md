# v5.5 Communication Governance Lite 记录

日期：2026-06-22

## 1. 本轮目标

根据 `docs/competition/工程校验-二次复核-外部审计问题核对.md`，本轮补齐暂不依赖 AutoGen 的动态通信治理缺口：

1. 16 种 SHP 消息类型没有工程定义。
2. Capability Profile Manager 未实现。
3. Capability Router / Communication Gate 没有进入 runtime。
4. 控制预算只有指标统计，没有规则版控制器。

这里的英文术语含义如下：

1. `Capability Profile`：能力画像，记录某个 Agent 能处理什么状态、适合接收什么消息。
2. `Capability Router`：能力路由器，根据状态类型、就绪状态和 Agent 能力选择下一跳。
3. `Communication Gate`：通信门控，判断一次交接是允许继续、降级审查，还是阻断。
4. `Control Budget`：控制预算，限制路由/门控这类控制逻辑自身无限膨胀。

## 2. SHP Message Types

新增：

```text
agent_runtime/protocol/message_types.py
```

定义 16 种比赛版消息类型：

```text
agent_output
state_ref_handoff
memory_ref_handoff
retrieval_state
embedding_state
artifact_state
failure_state
retry_request
retry_loop_summary
cold_read_request
cold_read_response
readiness_report
capability_advertisement
route_decision
memory_promotion
final_deliverable
```

`build_handoff_envelope()` 现在会校验 `msg_type`，未知消息类型会直接拒绝，避免 SHP 协议包退化成任意 JSON。

## 3. Capability Profile / Router / Gate

新增：

```text
agent_runtime/core/communication.py
```

包含：

```text
CapabilityProfile
CapabilityProfileManagerLite
CapabilityRouterLite
CommunicationGateLite
ControlBudgetLite
```

当前规则版路由示例：

1. `retriever` 生成 `retrieval_state` / `embedding_state` 后，优先路由给 `writer`。
2. `writer` 生成 `artifact_state` 后，优先路由给 `reviewer`。
3. 出现 `failure_state` 后，路由给 `reviewer`，并将交接状态降级为 `degraded`。
4. `reviewer` 输出后，路由到 `runtime`，消息类型为 `final_deliverable`。
5. readiness 为 `blocked` 时，路由到 `runtime` 并阻断下游继续消耗 token。

## 4. Runtime 接入

`V0Runtime` 初始化时新增：

```text
CapabilityProfileManagerLite
CapabilityRouterLite
CommunicationGateLite
ControlBudgetLite
```

`_build_shp_message()` 的执行顺序变为：

```text
ReadinessBarrierLite
  -> CapabilityRouterLite
  -> ControlBudgetLite
  -> CommunicationGateLite
  -> SHPEnvelope
```

SHP 包中新增或强化：

```text
header.msg_type
header.receiver
control.readiness
control.allowed_next_step
control.capability_hint
metrics.route_decision
metrics.communication_gate
metrics.control_budget
```

这让 SHP 不再只是“携带引用的消息”，而开始具备可解释的路由和门控依据。

## 5. Metrics

`TaskMetricRow` 新增：

```text
control_decision_count
route_override_count
communication_gate_block_count
communication_gate_degraded_count
control_budget_exhausted_count
```

这些指标用于回答：

1. 控制模块有没有参与决策；
2. 多少次路由偏离固定线性链路；
3. 多少次交接因为 readiness 或预算问题被阻断；
4. 多少次交接进入 degraded review/retry 路径。

## 7. 已解决与未解决

已解决：

1. SHP 16 类消息类型有工程定义和校验。
2. Capability Profile Manager Lite 落地。
3. Capability Router Lite 接入 SHP 构建路径。
4. Communication Gate Lite 接入 SHP 构建路径。
5. Control Budget Lite 有可测试的阻断机制。
6. 动态通信治理指标进入 metrics。

仍未解决：

1. 这仍是规则版，不是学习型 Capability Router。
2. 当前路由结果进入 SHP 包，但 runtime 主循环仍按既定 Agent 链执行；完整动态跳过/插入 Agent 可作为后续增强。
3. AutoGen / LangGraph 等框架 adapter 按用户要求暂缓。
4. 多进程环境下的跨框架路由同步未实现。
