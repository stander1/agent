# v5.12f AutoGen SHP Shadow Handoff Results

## 版本目标

v5.12f 的目标是验证：在用户的 AutoGen 代码不显式导入 AgentLite、AutoGen 原生消息和返回值不被改写的前提下，AgentLite Driver 能否根据 AutoGen Message Codec 的解码结果和 StatePool `state_ref`，旁路生成 SHP handoff envelope。

这里的 `shadow handoff` 指“影子交接包”：它只写入 AgentLite trace，用于验证未来低开销数据面是否可行；本版本不使用该包驱动 AutoGen 的真实调度，也不替换 AutoGen Team 的原生广播策略。

## 已实现内容

- 新增 `agent_runtime/drivers/autogen_shp.py`，负责从 AutoGen 解码消息推断影子接收方、消息类型摘要和 handoff 目标。
- AutoGen Driver 在 `record_call_end` 中复用 `CollaborationKernel.build_handoff` 生成 SHP envelope，因此影子包仍经过 readiness、capability router、communication gate 和 control budget。
- 只有存在语义载荷的输出才写入 StatePool 并生成 SHP 影子包；空的底层 runtime 生命周期事件只保留 trace，不污染状态池。
- trace 同时记录两层包：
  - `shadow_envelope`：完整审计包，包含 route/gate/budget 等本地解释信息。
  - `shadow_wire_envelope`：紧凑 wire 包，代表未来跨 agent 数据面实际传输口径。
- token 对比使用紧凑 wire 包，不把本地审计字段误算为通信成本。

## Token 口径

本次最小 smoke 的原生输出文本非常短，因此它不是通信 token 降幅实验，只用于验证协议生成链路。

```text
native_output_text_tokens: 161
shp_shadow_envelope_tokens: 971
shp_shadow_audit_envelope_tokens: 2163
token_delta_native_minus_shp: -810
```

字段解释：

- `native_output_text_tokens`：AutoGen 原生输出文本 token。
- `shp_shadow_envelope_tokens`：紧凑 wire 影子包 token，代表未来数据面传输口径。
- `shp_shadow_audit_envelope_tokens`：完整审计包 token，仅用于本地 trace，不应计入跨 agent 通信。
- `token_delta_native_minus_shp`：原生文本 token 减去紧凑 SHP 包 token；本次为负数，原因是 smoke 文本太短，协议头和 state_ref 固定开销大于短文本本身。

## 验证结论

v5.12f 证明了 AutoGen Python 代码端已经具备透明旁路生成 SHP handoff envelope 的能力：

1. 用户脚本仍只导入 AutoGen，不导入 AgentLite。
2. AutoGen 原生返回值保持不变。
3. AgentLite 能从真实 AutoGen 调用中提取语义输出，写入 StatePool，并生成 `shp.v1-lite` 影子包。
4. 每个影子包包含 `state_ref`，而不是把完整产物正文直接塞进跨 agent 消息。
5. 影子包经过通信门控，并在 trace 中保留 gate 结果。
