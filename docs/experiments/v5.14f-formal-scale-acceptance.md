# v5.14f A1-A10/B1-B10 正式规模验收

## 1. 阶段目标

v5.14e 已在 A1-A3/B1-B3 预检上同时通过成本、质量、最终成果和当前任务保真门禁。
v5.14f 不继续修改生产运行时，而是把同一套机制扩展到两个十轮连续任务链，回答：

1. 连续十轮后 Provider 实际 Token 是否仍至少降低 15%；
2. 端到端协作 Token 是否仍至少降低 15%；
3. Managed 双盲质量和完整交付是否不劣于 Native；
4. A10/B10 是否形成完整终局成果，而非审批说明或阶段摘要；
5. 共享记忆在长任务链中是否真实命中、注入且没有错误命中；
6. 当前任务保真、协议隐藏、路由净化和错误 fallback 是否在长链中继续成立。

本阶段只做一次完整规模运行。它证明证据管线和机制可在 20 个连续任务上工作，
但不用于估计不同运行之间的方差或置信区间；多次独立重复应在本门禁通过后单独执行。

## 2. 冻结输入

A 组保留旅行规划、预算收紧、健康限制、天气变化和终局手册等十轮语义，但补齐：

- 两人从上海出发；
- 3000 元是两人全部费用总上限；
- 三个候选地的交通、住宿、活动和路况来自冻结的本地合成快照；
- A8 把总上限收紧到 2600 元，A9 再从其中预留 200 元伴手礼。

这些补充用于消除预检中模型自行假设出发地、预算口径和候选资料的问题。三组看到
完全相同的输入，不在 `agent_runtime` 中增加任何旅游规则。

B 组冻结 B1-B10 的本地合成告警、网络观察、载荷映射、账本路径、线索废弃、
实体聚类、控制预算和合规规则。Agent 只能引用给出的合成证据，不得补造真实目标。

## 3. 预注册门禁

沿用 v5.14b 的五项基础门禁：

| 门禁 | 阈值 |
| --- | ---: |
| Managed Provider Token 降幅 | 至少 15% |
| Managed 端到端协作 Token 降幅 | 至少 15% |
| Managed 总体质量非劣边界 | Native - 0.3 |
| Managed 完整交付差值 | 不低于 Native |
| 改写错误 fallback | 0 |

新增正式规模门禁：

| 门禁 | 阈值 |
| --- | ---: |
| 每组任务数 | 20 |
| A10/B10 Managed 双盲分数 | 至少 7 |
| A10/B10 相对 Native | 不低于 Native - 1 |
| A10/B10 阻断级问题 | 0 |
| 记忆命中、注入、有效命中 | 均至少 1 |
| 错误记忆命中 | 0 |
| 当前任务保真失败 | 0 |
| 模型可见协议标记 | 0 |
| 路由元数据误入 StatePool | 0 |

阈值全部在 Provider 调用前写入
`experiments/v5.14f-formal-scale-acceptance/preregistration.json`。

## 4. 运行链

`run_openeuler.sh` 通过显式环境变量复用 v5.14b 的成熟证据管线：

```text
冻结输入并计算 SHA-256
  -> A: Native / Observed / Managed
  -> A: 绑定校验 / 双重匿名质量评分 / AgentLite 报告
  -> B: Native / Observed / Managed
  -> B: 绑定校验 / 双重匿名质量评分 / AgentLite 报告
  -> 基础成本-质量验收
  -> v5.14e 当前任务与最终成果验收
  -> v5.14f 正式规模终局验收
  -> 归档运行目录、trace 和校验和
```

基础 runner 新增的输入覆盖能力只属于实验编排，不改变 Native、Observed 或 Managed
的执行语义；旧版不设置环境变量时仍使用原三任务预检文件。

## 5. 状态类型边界

B2 和 B7 明确要求 `retrieval_state` 与 `embedding_state`，这是为了检查创新方案要求的
非文本状态场景。但验收器只读取真实 StatePool 的 `state_type_counts`：

- 任务文字出现某个类型，不等于运行时已生成该类型；
- 未生成的类型必须显示为 0；
- v5.14f 把缺失类型列为诊断项，不把它伪装成已实现；
- 本阶段的正式门禁聚焦已经通过预检的成本、质量、记忆和保真机制；
- 三类真实状态的生成、StateRef 传递和角色视图消费需要独立工程阶段和故障注入验收。

## 6. 解释边界

- 这是一次完整规模实验，不是统计重复实验；
- 评审模型 Token 单独记录，不进入运行时协作成本；
- 不限制 completion 长度，不减少 AutoGen 轮次；
- A/B Agent 提示词属于实验配置，生产运行时不固定角色名称；
- 正式验收失败也保留完整归档，不能看结果后修改阈值并重新解释同一证据。
