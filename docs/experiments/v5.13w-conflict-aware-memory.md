# v5.13w 版本冲突感知记忆与污染归因

## 1. 问题来源

MemoryStore 可以把旧 Claim 标记为 `superseded`，并且只检索新 Claim；但 AutoGen Agent 自身可能仍保留跨任务原生历史。只注入新值而不声明版本优先级时，模型仍可能从原生历史恢复旧值。此前的正向采用归因还会把“采用了部分当前事实”的污染输出记为有效命中。

## 2. 通用解决方法

每个存在历史 Claim 的 MemoryView 在渲染时附加紧凑 `revision_guard`：

```text
policy=use_active_claims_only
resolution=resolved
active_claims=<current claim ids>
superseded_claim_count=<count>
```

守卫不重复注入旧值，只声明当前有效 Claim 的优先级，并要求原生消息历史中的冲突旧值仅供审计。动态能力视图把守卫作为必选控制单元，因此任何 Agent 名称和能力画像都能继承该规则。

## 3. 采用与污染四分类

输出完成后执行规则优先归因：

- `useful`：采用当前有效事实，没有采用冲突旧事实；
- `wrong`：采用冲突旧事实，没有采用当前有效事实；
- `mixed`：当前有效事实和冲突旧事实同时出现；
- `unassessed`：没有足够证据确认采用或污染。

冲突检测只在历史事实和当前事实共享概念锚点、但结构化标量或数值不同的情况下触发。明确使用“不是旧值”“not the old value”等否定表达时，不计为污染。旧 Claim 原文仅用于输出后的本地审计，不进入 Agent Prompt。

## 4. 可观测性

新增字段：

```text
mixed_memory_hit_count
revision_guard_present
historical_claim_count
matched_historical_fact_count
historical_output_match_scores
```

MemoryStore 持久化 `useful_hit_count`、`wrong_hit_count` 和 `mixed_hit_count`。追踪、会话报告与监控统一满足：

```text
memory_injected_count =
  useful_memory_hit_count
+ wrong_memory_hit_count
+ mixed_memory_hit_count
+ unassessed_memory_hit_count
```

## 5. 边界

该机制解决“已准入的新旧 Claim 与框架原生历史发生冲突”的问题，不删除 AutoGen 自己的历史，也不猜测没有结构化差异的自由文本是否冲突。当前负向检测故意保持保守，以避免把引用旧值并明确否定的正确输出判成错误。

代码不包含 Question A/D 的目的地、预算或固定交付规则；实验用数据库参数只是验收夹具，不进入 `agent_runtime`。
