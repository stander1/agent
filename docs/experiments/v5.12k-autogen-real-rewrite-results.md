# v5.12k AutoGen TextMessage 输入真实改写实验记录

## 版本定位

`v5.12k` 是 AutoGen 透明托管链路中的第一个小范围真实改写版本。它仍不直接替换 AutoGen Team 层的广播调度，而是在更窄的 agent 输入层启用真实改写：

```text
Team 层：继续记录广播替换计划，并安全回退；
Agent 输入层：仅当 on_messages / on_messages_stream 收到简单 TextMessage 序列时，尝试真实替换消息内容。
```

这里的“真实替换”指原始 `TextMessage.content` 会在调用原生 AutoGen agent 方法前被替换为紧凑的 AgentLite 内容，其中包含 SHP wire 包和 Prompt View。原始长正文会写入 StatePool。

## 实现内容

- AutoGen Driver phase 更新为 `v5.12k`。
- `AGENTLITE_AUTOGEN_BROADCAST_MODE=real-rewrite` 不再只做全局回退。
- 新增 `autogen_agent_input_real_rewrite` trace 事件。
- 在 `agentchat_agent.on_messages` / `on_messages_stream` wrapper 调用原始方法前，执行安全改写。
- 仅支持简单 `TextMessage` 序列：
  - 非文本消息直接回退；
  - 空消息直接回退；
  - 无法复制消息对象直接回退；
  - `state_ref` 缺失直接回退；
  - Prompt View 缺失直接回退；
  - SHP wire schema 不合法直接回退；
  - 改写后 token 不低于原文直接回退。
- Team 层 `autogen_broadcast_replacement_shadow` 在 `real-rewrite` 模式下仍记录：
  - `fallback_keep_native_autogen_broadcast`
  - `team_level_real_rewrite_not_enabled_in_v5_12k`

## 可表述结论

AgentLite 已经能够在真实 AutoGen Python 代码端、托管启动且目标脚本不导入 AgentLite 的情况下，对简单 `TextMessage` 输入执行小范围真实改写。原始长文本进入 StatePool，agent 实际收到的是包含 SHP wire 和 Prompt View 的紧凑内容。

本次实验中，三个 agent 的输入共从 `17124` tokens 降到 `1073` tokens，且 `fallback_required_count=0`、`real_message_mutation_count=3`。这说明真实改写链路已经可在受限场景下跑通。

## 仍不能表述为

```text
已经替换 AutoGen Team 层的广播策略；
已经支持 HandoffMessage / ToolCall 的真实改写；
已经接管 AutoGen Studio / 网页端；
已经完成真实 LLM AutoGen 任务的质量、延迟、token 综合评估；
已经证明所有 AutoGen Team 类型都可以无修改替换。
```

## 下一步建议

`v5.12l` 建议不要立刻扩大到工具调用，而是先补真实改写的可观测性和回归保护：

```text
1. 给 real-rewrite 增加更细的安全指标：rewrite_attempt_count、rewrite_applied_count、rewrite_fallback_count；
2. 增加 rewritten content 的结构校验；
3. 增加 shadow-only / dry-run / real-rewrite 三模式对照报告；
4. 增加一个自定义 EchoAgent smoke，直接证明 agent 看到的是 rewritten content；
5. 再考虑 HandoffMessage / ToolCall 的真实改写。
```
