# v4.1 无人工输出上限 A/B 实验结果

日期：2026-06-21

## 实验目的

本轮实验验证两项修正后的效果：

1. 删除 `max_completion_tokens` 人工输出上限，不再用截断 LLM 输出模拟低开销通信。
2. 最终交付物显式选择 `writer/reviewer` 的完整答案，不再让 `memory_manager` 摘要参与最终交付口径。

低开销协同只通过 SHP 控制包、`state_ref`、Prompt View、Memory View 与状态池读取裁剪体现。

## 结论

删除人工输出上限后，格式稳定性和最终交付完整性显著改善：

- A/B 两组 runtime_lite 的 `fallback_count` 均降为 0。
- A10/B10 最终 schema 均完整覆盖。
- `contract_retry_count` 降为 0，说明此前大量 fallback 主要来自输出被截断导致的控制头未闭合。
- 最终交付口径已统一为 `reviewer`，`memory_manager` 只负责记忆沉淀。

代价是 runtime_lite 的 LLM 总 token 和耗时相对 v4.0 上升，因为模型现在会输出完整正文；但相对无运行时优化的 baseline，runtime_lite 仍显著降低端到端协作 token：

- A 组 end_to_end_collaboration_tokens 降低 98.1%。
- B 组 end_to_end_collaboration_tokens 降低 98.3%。

因此，v4.1 更符合原始创新方案：允许 Agent 完整生成结果，同时通过状态池引用、Prompt View 裁剪和记忆视图控制 Agent 间通信开销。
