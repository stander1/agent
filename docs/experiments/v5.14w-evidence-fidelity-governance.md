# v5.14w Evidence Fidelity Governance

## 正式证据触发原因

v5.14v 的真实 Provider 回归暴露出两类通用问题：

1. 同一句中同时出现预算估算、预算上限或修订关系时，句级关键词可能把
   不同金额合并为同一语义事实；带千位分隔符的金额还可能被拆成多个数值；
2. 当前任务明确引用一个必需文件、文件内容实际未提供，并规定证据不足时
   必须输出保守状态，但 Agent 仍可能声称使用该文件并给出强结论。

前者会产生错误记忆命中和额外修复调用，后者会降低交付正确性并污染后续
连续任务。

## 通用修复

- 预算事实按局部语义片段解析为估算、上限、分项和修订目标，不再让整句
  任意一个上限词污染全部金额；
- 千位分隔符在分句前规范化，`2,600` 保持为一个数值；
- 修订表达只把目标值作为当前有效值，来源值保留在修订血缘中；
- 必需证据预检同时要求：任务引用受支持的文件、文件不在上下文或工作区、
  用户明确给出证据不足时的回退值；
- 满足三项条件时，角色视图只注入缺失文件名和用户给出的回退值；
- 输出若声称读取缺失文件或给出冲突强结论，则保留 AutoGen 原生消息类型，
  将内容替换为保守回退，并记录可审计守卫事件。

## 不变边界

AgentLite 不解析领域规则、不猜测文件内容、不发明回退值，也不依赖
Question A/B、业务实体或 planner/writer/reviewer 角色名。文件内容已在
消息中显式提供或文件确实存在于目标工作区时，守卫不启用。Schema、协作组
隔离、记忆准入和端到端成本核算保持有效。

## 验收

`experiments/v5.14w-evidence-fidelity-governance/run_openeuler.sh` 在
openEuler 上运行定向回归、机制验收、编译和不可变证据归档。通过后再进入
真实 Provider 正式回归，既有阈值不作调整。
