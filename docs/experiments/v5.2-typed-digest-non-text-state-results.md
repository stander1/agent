# v5.2 Typed Artifact Digest 与非文本状态增强记录

日期：2026-06-22

## 1. 本轮目标

根据 `docs/competition/工程校验-二次复核-外部审计问题核对.md`，本轮解决两项不依赖 AutoGen 的缺口：

1. Typed Artifact Digest 只是通用摘要，不是类型感知摘要。
2. 非文本状态中的 embedding/vector 证据不足。

## 2. Typed Artifact Digest Lite

新增模块：

```text
agent_runtime/reliability/artifact_digest.py
```

`contract_guard.build_artifact_digest()` 现在调用 `build_typed_artifact_digest()`。

当前支持的 artifact 类型：

| 类型 | 摘要内容 |
|---|---|
| `python_code` | imports、class、function signature、entrypoint、parse_status |
| `json` | top_level_type、top_keys、field_types、row_count |
| `terminal_log` | line_count、exit_code、error_patterns、tail |
| `csv_table` | column_names、column_count、sample_row_count、sample_rows |
| `markdown` | heading_outline、decision_lines、section_count |
| `natural_language` | key_points、summary、content_hash |

所有 digest 仍保留旧字段：

```text
artifact_type
detected_headings
summary
content_hash
content_chars
```

因此不会破坏已有 Contract Guard、Memory Admission 和 Retry Prompt。

## 3. 非文本状态增强

新增模块：

```text
agent_runtime/state/non_text.py
```

新增 deterministic embedding metadata：

```text
query_embedding_id
chunk_embedding_ids
vector_dim
embedding_model
vector_store_ref
similarity_scores
score_map
```

当前为 deterministic stub，不接真实向量库，目的是先让比赛版具备可展示、可追踪、低开销的非文本状态结构。后续可以把 `vector_store_ref` 接到真实 embedding backend。

## 4. Runtime 接入变化

RetrieverAgent 现在会写入两个状态：

1. `embedding_state`
   - 保存 query/chunk embedding 引用、vector_dim、similarity_scores、vector_store_ref。
2. `retrieval_state`
   - 保存 chunk_ids、source_ids、score_map、evidence_rank。
   - 同时携带 query_embedding_id、chunk_embedding_ids、embedding_state_id。

`retrieval_state` 的 Prompt View 现在会显示：

```text
query_embedding=...
vector_dim=384
embedding_state=...
```

这解决了“非文本状态传递是不是只是传数据库 ID”的风险。

## 6. 已解决与未解决

已解决：

1. Typed Artifact Digest 从通用摘要升级为类型感知摘要 Lite。
2. retrieval_state 增加 embedding metadata。
3. runtime 能写入最小 embedding_state。
4. Prompt View 能展示 query embedding、vector_dim 和 embedding_state 引用。

仍未解决：

1. 真实 vector backend 未接入。
2. Batch Compaction 未实现。
3. Conflict Resolver 未实现。
4. SchemaRegistryLite / CanonicalClaimLite 仍需结构化。
5. State Lifecycle / GC / Readiness Barrier 仍是后续任务。

v5.3 Memory Compaction 与 Conflict Resolver
