# v5.13j 最终交付、共享记忆与成本口径修复

日期：2026-07-17

## 修复目标

本次修复针对 A1-A10 连续任务实验暴露出的三条连锁问题：

1. Reviewer 的审查意见只要附带 `FINAL_ANSWER_READY` 就会被误判为完整交付；
2. 被误判的审查意见会以高置信度进入长期共享记忆；
3. 影子压缩估算、真实改写成本和 Provider Token 被混在同一节省结论中。

这些问题均属于既定 Contract Guard、Context-Pruned Retry、规则优先记忆准入和 CSCC 成本闸门的工程缺口，不新增创新方案。

## 已完成修复

| 问题 | 修复后行为 |
|---|---|
| 只检查 Reviewer 和末行标记 | 标记只生成最终候选；规则语义闸门继续检查正文是否为可直接交付的产物。 |
| 审查意见误触发终止 | 包含“请 Planner/Writer 继续修订”等纯审查文本时，终止器拒绝停机，AutoGen 继续后续回合。 |
| 达到最大回合仍不完整 | 实验程序由同一个 Reviewer 执行一次短上下文修复，只保留当前问题、最新 Writer 草案和缺陷原因。 |
| 二次修复仍失败 | 记录 `delivery_status=degraded_fallback`，`delivery_valid=false`，不再伪装成功。 |
| Team 最终消息全部入长期记忆 | 先经过最终交付校验；不合格输出进入候选池后由规则拒绝，正文仍保留在 StatePool 供审计。 |
| 旅行任务全部覆盖同一槽位 | 拆为需求约束、目的地决策、行程、预算、天气风险、餐饮约束、决策日志和最终手册槽位。 |
| 命中即算有效 | 拆分为命中、注入、有效采用、错误命中和待评估；没有下游证据时有效采用保持为 0。 |
| 有记忆引用就绕过成本闸门 | 删除绕过逻辑；短消息加上 Prompt View 和记忆扇出后更贵时保留原生消息。 |
| 影子估算算入真实收益 | `actual_*` 只统计真实改写或真实回退，`shadow_*` 只表示理论潜力。 |

## 最终交付状态

- `validated_final_artifact`：规则校验通过，可作为用户交付物和长期记忆候选。
- `degraded_fallback`：正文为空、过短、仍是审查意见或缺少当前任务必要结构。
- `semantic_retry_count`：因语义交付失败触发的短上下文 Reviewer 修复次数，当前上限为 1。

任务规则覆盖 A 组的需求约束、三个候选、三天逐日安排、可核算预算、雨天备选、不吃辣、伴手礼和决策日志。规则只做交付下限检查，不评价文风和方案优劣；最终质量仍需盲评。

## 记忆指标口径

- `memory_hit_count`：检索器返回的记忆条数。
- `memory_injected_count`：实际进入 Prompt View 的记忆条数。
- `useful_memory_hit_count`：存在下游采用证据的记忆条数；不能再由命中数自动赋值。
- `wrong_memory_hit_count`：被判定为错误、过时或无关的记忆条数。
- `unassessed_memory_hit_count`：已经注入，但尚无有效或错误证据的记忆条数。
- `unique_retrieved_memory_tokens`：每个检索视图只计一次。
- `fanout_retrieved_memory_tokens`：向多个 Agent 展开后的总读取量。

旧版 Trace 没有注入和待评估字段。重新解析旧日志时，系统会保留可确认的“已注入”事实，但把旧的 `useful=hit` 降级为 `unassessed`。

## 成本指标口径

- `actual_native_transport_tokens`：真实改写审计覆盖范围内的原生传输成本。
- `actual_agentlite_transport_tokens`：真实应用改写后的成本；若改写回退，则按原生成本计入。
- `actual_transport_token_savings_ratio`：上述两者的真实差额比例。
- `shadow_potential_savings_ratio`：未实际替换消息的影子方案理论潜力。
- `llm_total_tokens`：Provider 返回的真实模型输入和输出 Token，必须单独展示。

使用新解析器重放 2026-07-17 接管组旧 Trace 后：

| 指标 | 复算结果 |
|---|---:|
| 真实原生传输基准 | 206,986 |
| 真实 AgentLite 传输成本 | 218,840 |
| 真实传输变化 | +5.73% |
| 影子原生候选成本 | 638,981 |
| 影子压缩候选成本 | 110,559 |
| 影子理论节省 | 82.70% |

这说明旧报告的约 82% 只应解释为理论压缩潜力，不能解释为真实端到端收益。

## 尚未由本次修复证明的事项

- `useful_memory_hit_count` 现在不再虚增，但要获得正值仍需下游引用或 Reviewer 采用证据。
- AutoGen Core 尚有未支持的消息内容字段；对应真实 Core 输出改写成功率需要单独继续提升。
- 一次短上下文修复产生的额外 Provider Token 会被计入任务总成本，不得从报告中扣除。
