# v5.12r AutoGen Handoff Rewrite Matrix 实验记录

## 版本定位

`v5.12r` 是 HandoffMessage 真实改写后的压测矩阵版本。

matrix：矩阵。这里的意思不是只跑一个“能成功改写”的样例，而是把应该改写、必须回退、必须保留原生语义的场景放在同一组测试中，证明 AgentLite 的底层接管不是粗暴替换 AutoGen 消息。

## 新增内容

- 新增 `examples/autogen_handoff_rewrite_matrix_smoke.py`。
- 新增 `examples/run_autogen_handoff_rewrite_matrix_smoke.py`。
- AutoGen Driver phase 更新为 `v5.12r`。
- 保留 `AGENTLITE_AUTOGEN_HANDOFF_REWRITE` 显式开关。
- 增加五类 Handoff 边界场景：
  - 开关关闭时保留原生 Handoff；
  - 单条长 Handoff 在安全门通过时改写；
  - 短内容 Handoff 因 token 不降低而回退；
  - 多条 Handoff 同时进入 agent 时保留原生；
  - 带 `context` 的 Handoff 在保留上下文字段后改写。

## 场景解释

关闭模式：

```text
handoff_rewrite_enabled: false
rewrite_event_count: 1
rewrite_applied_count: 0
rewrite_fallback_count: 1
candidate_event_count: 1
candidate_mutation_applied_count: 0
```

说明：即使候选安全且 token 降低，只要开关关闭，系统也只审计、不改写。

开启模式：

```text
handoff_rewrite_enabled: true
rewrite_event_count: 4
rewrite_applied_count: 2
rewrite_fallback_count: 2
candidate_event_count: 3
candidate_mutation_applied_count: 2
```

说明：四个 Handoff 调用中，只有单条长 Handoff 和带 context 的长 Handoff 被真实改写。短内容 Handoff 虽然语义字段可保留，但 `token_reduced=false`，因此不能改写。多 Handoff 输入无法形成单条 typed candidate，因此保留原生消息。

## 可表述结论

AgentLite 已经支持受控的 AutoGen `HandoffMessage.content` 改写，并且通过矩阵验证了“只在安全且有成本收益时改写”的边界：

- 开关关闭时不改写；
- 单条长 Handoff 可改写；
- 短内容不降成本时不改写；
- 多 Handoff 暂不改写；
- 带 context 的 Handoff 只有在 context 保留后才改写。

这与创新方案中的 Contract Guard、SHP-State、SHP-Control、CSCC 成本门控一致。
