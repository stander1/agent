# v5.12i AutoGen Team 广播替换影子计划实验记录

## 版本定位

`v5.12i` 仍属于 AutoGen 透明托管接入链路，不真实替换 AutoGen Team 的广播策略。该版本目标是在影子模式下回答一个更接近后续工程落地的问题：

```text
如果以后要把 AutoGen Team 的原生长文本广播替换成 AgentLite 的 SHP-State 传输，
每个接收方会收到什么 wire 包？
每个接收方需要读取多少 Prompt View？
这个替代计划在 token 口径上是否仍然低于原生广播？
```

## 实现内容

- 新增 `plan_shadow_broadcast()`，按 AutoGen Team 参与者生成 per-receiver SHP 计划。
- AutoGen Driver 从真实 `RoundRobinGroupChat` 实例中提取 `_participant_names`。
- Driver 在 `run_stream` 层记录 `autogen_team_input_state`，把 Team 输入任务写入 StatePool。
- Driver 在 `run_stream` 层记录 `autogen_broadcast_replacement_shadow`，生成每个接收方的 SHP wire 包和 Prompt View 成本。
- 为避免 `run()` 转调 `run_stream()` 带来的双计，广播替换影子计划只在 `run_stream` 层记录。
- 新增 `examples/autogen_broadcast_shadow_smoke.py`，目标脚本只导入 AutoGen，不导入 AgentLite。
- 新增 `examples/run_autogen_broadcast_shadow_smoke.py`，托管启动并生成实验报告。

## 可表述结论

AgentLite 已经能够在不修改 AutoGen 用户脚本、不改变 AutoGen 原生返回值的情况下，观察真实 `RoundRobinGroupChat` 的参与者列表，并为每个接收方生成候选 SHP 替代传输计划。

在本次三 Agent smoke 中，原生全文广播估算口径为 `42858` tokens，per-receiver `SHP wire + Prompt View` 为 `2368` tokens，下降约 `94.5%`。这说明后续如果进入真实广播替换，替换方向具备可验证的成本收益。

## 仍不能表述为

```text
已经真实替换 AutoGen Team 的广播策略；
已经改变 AutoGen agent 间的实际传输内容；
已经接管 AutoGen Studio / 网页端；
已经完成真实 LLM AutoGen 任务的质量、延迟、token 综合评估；
已经证明所有 AutoGen Team 类型都可以无修改替换。
```

## 下一步建议

`v5.12j` 可以继续保持透明托管边界，补“真实替换前的安全阀”：

```text
1. 给广播替换计划增加 feature flag，例如 AGENTLITE_AUTOGEN_SHADOW_BROADCAST=1；
2. 把 shadow-only、dry-run-rewrite、real-rewrite 三种模式在配置层拆开；
3. 增加回滚条件：schema 不合法、Prompt View 缺失、接收方不明确时自动退回 AutoGen 原生广播；
4. 先实现 dry-run-rewrite 的可审计 diff，不急于改真实消息。
```
