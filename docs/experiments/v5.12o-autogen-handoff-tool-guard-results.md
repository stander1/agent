# v5.12o AutoGen Handoff / ToolCall Rewrite Guard 实验记录

## 版本定位

`v5.12o` 不是扩大真实改写范围，而是补上 HandoffMessage / ToolCallSummaryMessage 的最小安全守卫。

这里的守卫含义是：当 AutoGen 消息带有控制语义时，系统先记录“为什么不能直接改写”，并保持原生消息不变。只有当后续实现能够证明 target、tool_call_id、result lineage 等字段不会丢失时，才允许进入真实改写。

## 实现内容

- AutoGen Driver phase 更新为 `v5.12o`。
- 新增 `autogen_non_text_real_rewrite_guard.v1` 安全审计结构。
- 非 TextMessage 回退时保留 `non_text_message_present`，同时补充更细的原因：
  - `handoff_rewrite_requires_target_preservation`
  - `tool_rewrite_requires_call_lineage`
  - `tool_rewrite_requires_result_lineage`
- 新增 fallback bucket：
  - `handoff_control_guard`
  - `tool_lineage_guard`
- 新增 smoke：
  - `examples/autogen_handoff_tool_rewrite_guard_smoke.py`
  - `examples/run_autogen_handoff_tool_rewrite_guard_smoke.py`

## 可表述结论

AgentLite 现在可以在 `real-rewrite` 模式下区分简单 TextMessage 与带控制语义的 AutoGen 消息。简单 TextMessage 仍可真实改写；HandoffMessage / ToolCallSummaryMessage 会保留原生消息，并记录具体安全条件，证明系统不会为了降低 token 破坏 AutoGen 的路由目标或工具调用链路。

## 仍不能表述为

```text
已经支持 HandoffMessage / ToolCall 的真实改写；
已经真实替换 AutoGen Team 层广播策略；
已经接管 AutoGen Studio / 网页端；
已经完成真实 LLM AutoGen 任务的质量、延迟、token 综合评估。
```

## 下一步建议

下一步可以进入 `v5.12p`：先选择 HandoffMessage 或 ToolCallSummaryMessage 中更容易证明语义保持的一类，设计 typed rewrite candidate。

建议优先从 HandoffMessage 开始，因为它的关键控制字段相对少，主要是 `source`、`target`、`content` 和可选 `context`。ToolCallSummaryMessage 需要同时维护 `tool_calls.id` 与 `results.call_id` 的链路，风险更高。
