# v5.13q 连续任务必要记忆门禁修复

## 1. 真实故障证据

openEuler AutoGen Studio A1-A3 Trace 显示：

```text
A2 Team final admission_status: admitted
A3 Team memory_hit_count: 1
A3 retrieved_memory_tokens: 739
A3 native_task_tokens: 37
A3 rewritten_task_tokens: 2241
A3 fallback_reasons:
  team_task_token_not_reduced
  token_not_reduced
A3 memory_injected_count: 0
```

A3 命中的 MemoryView 已包含 A2 的三个候选目的地和既有旅行偏好，但 Team、Planner、Writer 和 Reviewer 的候选注入都被纯 Token 门禁回退。最终 Planner 和 Writer 错误地声称缺少 A2 列表。根因不是记忆池、检索、Run 绑定或旧 Studio 记录，而是系统把完成任务所必需的历史事实当成了可选压缩候选。

Trace 还显示 A1 Team final 未通过最终交付校验，因此 A1 没有进入长期记忆；v5.13q 不放宽这条准入规则。未验证结果仍只能停留在候选池，不能因连续性需求绕过记忆治理。

## 2. 通用修复

新增本地、规则优先的连续任务依赖识别：

```text
中文：引用刚才、上一轮、已有结果、具名步骤，以及继续、修订、保留既有方案等表达；
英文：previous/prior/earlier/above result，continue/revise/refine/update 等表达；
具名引用：基于 B7、using step R12 等通用任务标识。
```

该规则不包含旅行、Question A、候选目的地或任何固定业务字段。只有同时满足以下条件时才覆盖成本门禁：

1. 当前请求明确依赖既有上下文；
2. 严格协作组检索确实返回已准入 MemoryView；
3. 剩余阻断原因只是 `token_not_reduced` 或 `team_task_token_not_reduced`。

连续性识别只检查用户任务文本；Planner、Writer、Reviewer 的角色说明或过程叙述不会单独触发覆盖，避免把自包含任务误判成连续任务。

Schema 校验、StateRef、Prompt View、接收者完整性和消息克隆门禁保持强制；存在任一结构错误时仍回退原生消息。

## 3. 成本口径

必要上下文可能让当前短消息的 Token 增加。系统不得把这种情况记成节省。新增指标：

```text
continuity_required_event_count
continuity_cost_override_count
continuity_memory_injection_count
```

原生传输成本、Prompt View、记忆读取和端到端协作 Token 继续按实际值计量；如果为了恢复语义连续性导致本轮 Token 增加，`token_savings` 可以为负数。正确性优先不等于隐藏成本。

## 4. 回归覆盖

回归测试覆盖：

1. 跨启动持久记忆被短连续指令读取；
2. Team 入口在纯成本失败时注入必要记忆；
3. 单 Agent 输入采用相同语义优先策略；
4. 自包含任务不触发连续性标记；
5. 不同 Team 的严格协作组隔离保持有效；
6. 报告能够区分普通改写、成本回退和连续性覆盖。

## 5. 当前边界

本版本解决确定性的显式连续性表达，不声称理解所有隐含指代。没有检索命中时不会伪造历史，也不会把 pending/rejected 候选提升为正式记忆。真实 Studio A1-A10 仍需在 openEuler 使用全新 AgentLite 数据目录和记忆作用域重新验收。
