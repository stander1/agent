# v5.14b 真实 AutoGen 公平成本-质量预检

## 1. 阶段定位

v5.14a 证明了真实 AutoGen 消息链中，已过期记忆事实可以在到达下游 Agent 前被精确修复
或保守阻断，但它使用一行故障输出，不适合证明低开销。v5.14b 回到比赛核心问题：

```text
在正常长度的连续协作任务中，
AgentLite 能否在不降低交付质量的前提下，
同时降低 Provider 实际 Token 和端到端协作 Token？
```

本阶段先运行 A1-A3/B1-B3 预检。它只建设实验和验收基础设施，不修改
`agent_runtime` 生产机制。预检通过后才扩展到 A1-A10/B1-B10。

## 2. 为什么先做预检

正式双领域十轮实验需要大量真实 Provider 调用。若运行结束后才发现下列问题，证据和
Token 都会浪费：

- Native、Observed、Managed 任务或 Agent 配置不一致；
- AgentLite session 与 Provider usage 没有不可变绑定；
- 质量候选在解盲前没有冻结；
- 只记录 Agent 间消息 Token，没有记录记忆读取和控制成本；
- 只看传输 Token 下降，忽略实际 Provider Token 上升；
- Reviewer 审查意见被误当成最终用户交付；
- Observed 组实际修改了消息；
- B 组引用不存在的本地文件，模型只能编造检索结果。

因此 v5.14b 先用每个领域三轮任务验证完整证据管线。

## 3. 公平实验组

| 组别 | 启动方式 | 数据面行为 | 用途 |
|---|---|---|---|
| Native | 直接运行 AutoGen | 原生消息 | 主对照 |
| Observed | `agentlite autogen --rewrite off` | 只采集，不改写 | 生成波动与钩子影响诊断 |
| Managed | `agentlite autogen --rewrite all` | 实际改写、状态引用、共享记忆 | 主方法 |

三组固定：

```text
Provider model: mimo-v2.5
temperature: 0
max_turns: 9
同一场景任务、Agent 配置和执行顺序完全一致
不限制 completion Token
```

每个场景的 Managed 组使用独立 `AGENTLITE_MEMORY_SCOPE`，A/B 之间不能共享记忆。

## 4. 两个领域

### 4.1 A1-A3 旅行规划

使用普通开发者实验中已经固定的旅行需求、候选目的地和初版行程，以及旅行领域专业
Planner、Writer、Reviewer。

### 4.2 B1-B3 合成安全审计

使用新的防御性合成审计专家 Team：

- B1：告警硬约束和首个 lookup key；
- B2：本地网络观测快照与 `retrieval_state` 摘要；
- B3：本地 payload 映射与 `artifact_state` 摘要。

B2/B3 的本地资料快照直接写入用户任务，三组输入一致。实验不再声称读取实际不存在的
CSV/JSON 文件，也不要求模型生成攻击或解密代码。

这些领域提示词只属于 `experiments/`，不进入生产运行时。AgentLite 仍通过动态能力画像、
任务动作、协作组和 MemoryView 工作，不识别 Question A/B。

## 5. 预注册成本口径

### 5.1 Provider 实际成本

直接使用模型响应 usage：

```text
provider_llm_total_tokens =
  provider_prompt_tokens
+ provider_completion_tokens
```

该指标反映实际账单。Native、Observed、Managed 分别统计。

### 5.2 端到端协作成本

使用 Managed trace：

```text
end_to_end_collaboration_tokens =
  direct_message_tokens
+ prompt_view_tokens
+ retrieved_memory_tokens
+ control_llm_tokens
+ retry_tokens
```

同时记录 Managed 相同输出对应的 `native_baseline_tokens`。这组口径用于判断真实改写是否
降低消息传输和上下文重建成本，不能替代 Provider 实际账单。

### 5.3 评审成本

综合质量裁判和技术裁判的 Provider usage 单独保存：

```text
included_in_runtime_collaboration_cost = false
```

评审模型不参与被测系统协作，因此不能混入 Native/Managed 运行成本。

### 5.4 非文本状态证据

Managed 报告从真实 StatePool 快照统计：

```text
state_count
state_type_counts
payload_kind_counts
structured_non_text_count
contains_embedding_refs_count
total_size_bytes
```

预检要求至少实际产生 `artifact_state` 和 `structured_non_text` 载荷。报告会分别列出
`artifact_state`、`retrieval_state`、`embedding_state` 等真实数量；没有产生的类型保持
为 0，不能根据题目中出现了这些单词就推断系统已经生成相应状态。预检不强制要求每个场景
都生成 embedding 或 retrieval 状态，因为这取决于真实工具和消息路径；正式 B 组实验应
另外设计真实 Retriever/Embedding 工具调用来验证这两类状态。

## 6. 质量口径

比较器先随机化候选并生成稳定匿名轨道。映射文件在两个裁判结果写入前不读取。

```text
primary score:
  任务完成度 + 上下文保持 + 正确性一致性 + 清晰可执行性

technical score:
  约束忠实度 + 技术正确性 + 内部一致性 + 可执行性

final score = min(primary score, technical score)
```

只评价 Reviewer 已验收并输出的完整最终正文。仅有审查意见、拒绝或半截内容不能取得完整
交付。

## 7. Provider 调用前冻结的目标

`preregistration.json` 固定：

```text
Managed Provider 总 Token 相对 Native 降低 >= 15%
Managed 端到端协作 Token 降低 >= 15%
Managed 综合质量 >= Native - 0.3/10
Managed 完整交付数 >= Native
rewrite_error_fallback_count = 0
```

报告分别给出：

- `evidence_pipeline_passed`：证据是否完整可信；
- `preliminary_targets_met`：成本、质量和可靠性是否达标；
- `ready_for_formal_run`：两者同时通过。

失败证据仍会打包。不能看到结果后修改同一实验的阈值。

## 8. 预检通过后的下一步

只有 `ready_for_formal_run=true` 时，才进入正式实验：

1. A1-A10 旅行连续修订；
2. B1-B10 合成安全审计、证据修订和控制预算；
3. 至少两次独立重复；
4. 报告均值、离散程度、逐任务成本和逐任务质量；
5. 对未达标指标做消融实验，不能直接改主实验口径。

如果预检中 Provider Token 仍上升，下一步优先定位 MemoryView 重复注入、角色视图长度、
历史消息残留和额外 LLM 轮次，不通过缩短最终输出规避问题。
