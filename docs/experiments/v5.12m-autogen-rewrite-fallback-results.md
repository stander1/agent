# v5.12m AutoGen Rewrite Fallback 分桶实验记录

## 版本定位

`v5.12m` 是 `v5.12l` 之后的真实改写安全硬化版本。它不扩大真实改写范围，而是补充失败分桶和失败样例 smoke，证明不满足改写条件时会安全回退到 AutoGen 原生消息。

```text
fallback：回退。表示系统发现当前消息不适合真实改写，于是保留 AutoGen 原生消息继续执行。
fallback_reason：回退细原因，例如 non_text_message_present。
fallback_bucket：回退原因所属的大类，例如 unsupported_message_type。
```

## 实现内容

- AutoGen Driver phase 更新为 `v5.12m`。
- `autogen_agent_input_real_rewrite` 事件新增：
  - `fallback_buckets`
  - `fallback_bucket_counts`
- 新增失败原因到分桶的稳定映射：
  - `non_text_message_present` -> `unsupported_message_type`
  - `token_not_reduced` -> `cost_gate_failed`
  - `prompt_view_missing` -> `prompt_view_unavailable`
  - `missing_state_refs` -> `state_ref_unavailable`
  - `schema_invalid` -> `schema_guard_failed`
- 新增 `examples/autogen_rewrite_fallback_smoke.py`。
- 新增 `examples/run_autogen_rewrite_fallback_smoke.py`。
- 扩展 `summarize_agent_real_rewrite_events`，汇总 fallback bucket。

## 可表述结论

AgentLite 现在不仅能在简单 `TextMessage` 场景下进行真实改写，也能在遇到当前不支持的消息类型时安全回退，并把失败类型记录为可统计的分桶指标。这个结果增强了跨框架透明托管的可回滚性：系统不会为了追求改写而破坏 AutoGen 原生执行。

## 仍不能表述为

```text
已经支持 HandoffMessage / ToolCall 的真实改写；
已经真实替换 AutoGen Team 层广播策略；
已经接管 AutoGen Studio / 网页端；
已经完成真实 LLM AutoGen 任务的质量、延迟、token 综合评估。
```

## 下一步建议

下一步可以进入 `v5.12n`：在不扩大真实改写范围的前提下，补更多失败样例，例如空消息、短消息 token 不降反升、Prompt View 缺失模拟。这样能把“可回滚透明托管”的证据做得更扎实，然后再考虑 HandoffMessage / ToolCall 的真实改写。
