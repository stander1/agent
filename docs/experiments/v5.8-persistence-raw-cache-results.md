# v5.8 Memory Persistence / Raw View Cache Lite 记录

日期：2026-06-22

## 1. 本轮目标

继续补齐外部审计中非 AutoGen 的剩余工程缺口：

1. `MemoryStoreLite` 纯内存，重启后丢失。
2. Cold Access 缺少 raw view cache，重复冷读会反复触盘。

英文术语说明：

1. `warm persistence`：温层持久化。不是完整数据库，但会把记忆对象、视图、引用等写到文件，避免完全停留在内存。
2. `raw view cache`：原文视图缓存。第一次从 cold audit payload 读原文，后续同状态读取走缓存，减少重复 I/O。

## 2. MemoryStore Warm Persistence

`MemoryStoreLite` 新增可选参数：

```text
storage_dir: Path | None
```

当配置 `storage_dir` 时，以下操作会写出：

```text
memory_store_snapshot.json
```

触发点：

1. 写入记忆。
2. 记忆状态转换。
3. replacement chain 更新。
4. batch compaction。
5. claim 状态同步导致旧记忆 tombstone。

快照包含：

```text
memories
claim_cards
memory_views
promotion_views
memory_candidates
claim_candidates
memory_references
compaction_log
```

这不是 openGauss 后端，但已经把 `MemoryStoreLite` 从纯内存推进到比赛版 warm persistence。

## 3. Raw View Cache

`StatePoolLite` 新增：

```text
self._raw_view_cache
ColdAccessReport.cache_hit
```

`request_cold_access()` 的行为：

1. 第一次 cold read：从 audit payload 文件读取，并写入 raw view cache。
2. 第二次同状态 cold read：命中 cache。
3. cache hit 仍然计入 cold read count 和 cold bytes，避免绕过成本统计。

## 5. 已解决与未解决

已解决：

1. MemoryStore 不再只能纯内存运行，可配置 warm snapshot。
2. snapshot 包含记忆、claim、view、promotion、reference、compaction log。
3. Cold Access 有 raw view cache。
4. cache hit 不绕过预算统计。

仍未解决：

1. 没有实现 SQLite/openGauss 正式后端。
2. 没有实现快照反向恢复到 MemoryStore 的加载流程。
3. raw span resolver 和 prefetch scheduler 仍保留为研究增强版。
4. openEuler/openGauss 实测仍需后续单独做环境验证。
