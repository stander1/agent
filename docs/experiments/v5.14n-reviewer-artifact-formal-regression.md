# v5.14n Reviewer 成果连续性正式回归

## 1. 为什么需要这一阶段

v5.14m 的确定性机制验收已经证明运行时能够拒绝伪装成终稿的修订清单、
按 Reviewer 引用晋升前序成果，并提取明确结论。但该结果不调用真实
Provider，不能证明完整连续任务中的质量和成本已经恢复。

v5.14n 因此只改变实验冻结的 Agent 配置，三组均使用相同新配置，其他
任务、模型、温度、轮次、评分和阈值继承 v5.14l。这样能把质量变化归因
于成果所有权协议和运行时机制，而不是给接管组额外提示或额外轮次。

旧验收中的 `v514h_agent_profiles_are_reused_exactly` 在本阶段被明确废止，
因为继续要求旧 Agent 配置会与本次预注册的新配置冲突。替代门禁分别
校验 v5.14m 源配置哈希和运行目录冻结副本哈希，且三组仍共用同一份
配置，因此没有放宽公平性。

## 2. 成果所有权口径

```text
业务 Agent 生成完整成果
Reviewer 不通过 -> 返回修订清单，继续原协作轮次
Reviewer 通过 -> 引用批准上一份成果
运行时校验原成果 -> 晋升原成果作为最终正文
```

`final_resolution_kind=prior_artifact_approved` 表示发生了引用晋升；
`final_artifact_origin_source` 记录原成果所有者。Reviewer 审批文本保留在
消息轨迹中用于审计，但不进入最终正文。

## 3. 新增证据

- 每个场景的引用晋升次数；
- Reviewer 直接替代业务成果次数；
- 成果所有权错标次数；
- 审批意见误作最终正文次数；
- `decision.*` 类型化明确决策记忆数量；
- 原有双盲质量、完整交付、Provider Token、端到端协作 Token、状态和
  记忆治理指标。

## 4. 解释边界

本阶段仍是一次完整正式回归，只验证机制在真实 Provider 下的可行性和
单次门禁结果，不声称统计显著性。若通过，下一步应重复独立运行并报告
均值、标准差和置信区间，而不是继续增加 A/B 专用规则。
