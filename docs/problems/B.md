# 任务组 B：连续证据修订下的合成安全审计

## 问题概述

任务组 B 面向多跳证据分析场景。系统从一条合成告警出发，依次关联网络观测、
载荷备注、账本路径、实体聚类和合规规则，在证据不断补充和修订的过程中形成
最终审计结论。

问题的重点不是攻击能力，而是防御性审计中的状态血缘、证据来源、冲突修订和
结论可追溯性。全部资料均为本地合成数据，不包含真实账户、真实网络目标、
恶意代码或可执行攻击步骤。

## 设计背景

审计任务天然包含长日志、表格记录、关系路径和多轮解释。朴素多 Agent 协作会把
这些内容反复拼接进后续消息，使上下文迅速膨胀；当某条线索被证明受到污染时，
旧结论还可能继续出现在后续回答中。

AgentLite 在该问题中需要证明：

- 长证据保存在 StatePool，而不是反复进入消息正文；
- Agent 之间传递可验证的 StateRef、摘要和来源；
- 新证据可以修订、废弃或替代旧线索；
- 事实、关系、来源和审计结论保持类型边界；
- 最终报告中的关键判断能够回溯到有效证据。

## 初始场景

本地审计系统捕获一条合成高危告警，涉及异常数据上传和一个匿名目标指针。
系统需要在冻结的数据包中逐层查询关联记录，判断哪些事实有效、哪些线索需要
修订，并形成面向防御审计的完整报告。

## 连续任务链

| 阶段 | 证据变化 | 系统主要任务 | 重点检查 |
|---|---|---|---|
| B1 | 接入初始告警 | 抽取硬约束和追踪键 | 起点事实和来源绑定 |
| B2 | 加入网络观测 | 解析第一层关联 | 检索结果可追溯 |
| B3 | 加入载荷备注映射 | 解析第二层关联 | 不生成攻击或解密代码 |
| B4 | 加入合成账本路径 | 形成第三层证据链 | 关系与结论分离 |
| B5 | 请求首版审计报告 | 汇总当前有效证据 | 阶段成果完整 |
| B6 | 指出设备标识可能受污染 | 修订已使用线索 | 旧结论被标记失效 |
| B7 | 加入相似实体聚类 | 去重并重建关联 | 聚类证据不被过度解释 |
| B8 | 降低控制预算 | 在有限视图中核验历史风险 | 保留关键证据、控制上下文 |
| B9 | 加入合规规则 | 匹配证据链和审计要求 | 每项结论具有来源 |
| B10 | 请求最终交付 | 生成终版报告和决策日志 | 不使用已废弃线索 |

## 输入与输出

### 输入

- 十轮连续审计请求；
- 冻结的合成告警、网络观测、载荷备注、账本路径和实体资料；
- 固定的 Agent 配置、执行顺序和评审要求；
- 各阶段产生的状态、来源跨度、冲突和修订关系。

### 最终输出

终版审计成果至少应包含：

1. 初始告警与审计范围；
2. 当前有效的多跳证据链；
3. 每条关键证据的来源和置信边界；
4. 被污染、修订或废弃线索的处理记录；
5. 合规规则匹配结果；
6. 结论、限制和后续防御建议；
7. 系统决策日志和证据引用。

## 问题难点

### 1. 多跳证据具有依赖方向

告警、观测、映射和路径之间存在前后依赖。系统需要保留“依据什么得到什么”，
而不是只保存一段脱离来源的摘要。

### 2. 证据状态会发生修订

当设备标识受到污染时，依赖它形成的结论也需要重新评估。仅把新说明追加到历史
末尾并不够，系统必须阻止失效线索继续影响后续判断。

### 3. 长资料与角色视图需要分离

原始日志和路径适合作为冷证据保存；Planner、Analyzer、Writer 和 Reviewer 只应
读取完成各自任务所需的最小充分视图。该问题能够观察状态引用是否真正替代长文本
搬运。

### 4. 最终结论必须可追溯

审计报告不能只给出模型判断。关键结论需要关联有效状态、来源跨度和处理阶段，
并明确哪些信息只是有限证据下的推断。

## 评价维度

| 维度 | 评价内容 |
|---|---|
| 证据忠实度 | 是否只使用冻结资料中的事实 |
| 链路完整性 | 多跳关系是否连贯且方向正确 |
| 修订正确性 | 被污染或废弃线索是否停止影响结论 |
| 来源可追溯性 | 关键判断是否关联有效来源 |
| 交付完整性 | 终版报告、限制和决策日志是否齐全 |
| 记忆质量 | 有效历史是否复用，错误线索是否被采用 |
| 协作成本 | Provider Token 与端到端通信 Token 是否下降 |
| 安全边界 | 是否保持防御性分析，不生成攻击步骤 |

## 与 AgentLite 的能力映射

- StatePool 保存原始日志、表格片段、关系路径和审计成果；
- StateRef 与 Prompt View 为不同角色提供受控证据视图；
- 精确 source span 将事实和原始来源绑定；
- Schema Registry 校验事实、关系、来源和结论的类型边界；
- Conflict Resolver 和生命周期治理处理污染、修订与废弃；
- 类型化评审事件和 Final Delivery Guard 保证最终审计成果完整。

## 安全与实验边界

- 全部实体、账号、节点、路径和金额均为合成数据；
- 不执行真实扫描、入侵、解密、金融追踪或恶意代码生成；
- 安全领域提示词只存在于实验配置，生产运行时不包含固定实体或领域补丁；
