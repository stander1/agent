# 任务组 A：连续约束下的个性化旅行规划

## 问题概述

任务组 A 面向“需求会持续变化”的真实规划场景。用户不是一次性给出全部条件，
而是在多轮协作中逐步补充同行人状况、天气、预算和饮食需求。多智能体系统需要
持续维护有效约束，协调规划、撰写与复核，并最终交付一份完整、可执行的旅行手册。

这不是单轮旅游问答，而是一个十阶段的连续决策问题。它用于检验多智能体运行时
能否在历史不断增长时保留关键信息、淘汰旧方案、控制上下文成本，并避免在最终
交付中遗漏后加入的约束。

## 设计背景

传统多 Agent 协作通常把用户请求和所有历史输出重复发送给后续角色。随着任务推进，
上下文会不断增长，同一偏好、候选方案和预算表被多次传输。模型既要重新阅读大量
历史，又可能误用已经失效的预算或路线。

AgentLite 的目标不是学习旅游知识，而是在不改变业务问题的情况下：

- 将完整方案和表格保存在 StatePool；
- 用 StateRef 和接收方视图传递必要上下文；
- 将稳定偏好写入受治理记忆；
- 将预算、天气等变化表达为可追溯修订；
- 在最终交付前检查当前约束和成果完整性。

## 初始场景

两名用户计划一次三天两晚的短途旅行，偏好自然风景、轻徒步和当地美食，
希望避开拥挤的商业景点，并对每日步行强度和夜间活动有要求。系统基于冻结的
本地合成资料完成目的地筛选和行程设计，不依赖实时网页或不可复现的外部数据。

## 连续任务链

| 阶段 | 用户需求变化 | 系统主要任务 | 重点检查 |
|---|---|---|---|
| A1 | 提出旅行目标和基础偏好 | 抽取软偏好与硬约束 | 约束结构化、来源明确 |
| A2 | 请求筛选候选目的地 | 比较适配度并说明取舍 | 只使用冻结资料 |
| A3 | 请求生成初版行程 | 编排三天两晚路线 | 时间、强度与偏好一致 |
| A4 | 要求核算预算和时间 | 形成可检查的成本明细 | 总额与分项口径一致 |
| A5 | 请求首版旅行手册 | 汇总路线、预算和风险 | 形成完整阶段成果 |
| A6 | 同行人新增晕车限制 | 调整交通和出发安排 | 新限制替代不适用方案 |
| A7 | 第二天天气发生变化 | 生成室内或低风险备选 | 不沿用失效户外安排 |
| A8 | 总预算收紧 | 重排住宿、交通和活动 | 使用最新预算上限 |
| A9 | 新增饮食和伴手礼需求 | 调整餐饮与预算预留 | 新需求不破坏硬约束 |
| A10 | 请求最终交付 | 生成终版手册和修订说明 | 覆盖所有当前有效约束 |

## 输入与输出

### 输入

- 十轮连续的用户请求；
- 冻结的候选目的地、交通、住宿、活动和天气资料；
- Planner、Writer、Reviewer 的固定角色配置；
- 各阶段已经产生的状态、记忆和修订关系。

### 最终输出

终版旅行手册至少应包含：

1. 目的地选择及理由；
2. 三天两晚逐日行程；
3. 交通、住宿、餐饮、活动与伴手礼预算；
4. 同行人健康限制的处理方式；
5. 天气变化下的替代方案；
6. 关键风险和执行提示；
7. 从初版到终版的主要修订说明。

## 问题难点

### 1. 软偏好与硬约束并存

“喜欢自然风景”属于可权衡偏好，“总预算不得超过上限”属于硬约束。系统需要
区分二者，不能为了满足偏好而突破预算，也不能把所有要求都当作同一优先级。

### 2. 约束具有时间和修订关系

预算收紧、天气变化和同行人状况会使早期方案失效。系统不仅要记住新事实，还要
知道它替代了什么，防止旧路线或旧预算继续进入后续答案。

### 3. 中间成果大于消息正文

完整行程、预算表和候选比较适合存为结构化状态，而不适合在每个 Agent 之间反复
发送。该问题可以直接观察 StateRef 和接收方视图是否减少重复上下文。

### 4. 最终交付需要跨阶段整合

A10 不是简单总结最后一轮，而是要把十轮中的有效事实重新组合成可执行成果。
任何遗漏预算、天气替代方案或健康限制的答案都不算完整交付。

## 评价维度

| 维度 | 评价内容 |
|---|---|
| 约束忠实度 | 是否使用最新预算、天气、健康和饮食条件 |
| 方案正确性 | 行程、时间与预算是否自洽 |
| 修订能力 | 是否停止使用已被替代的旧方案 |
| 交付完整性 | 终版手册是否覆盖全部必需部分 |
| 记忆质量 | 有效偏好是否复用，错误或过期事实是否被采用 |
| 协作成本 | Provider Token 与端到端通信 Token 是否下降 |
| 可追溯性 | 关键决策能否定位到输入、状态或修订来源 |

## 与 AgentLite 的能力映射

- StatePool 保存候选比较、行程和预算等完整成果；
- Prompt View 为不同角色提供最小充分上下文；
- MemoryView 复用稳定偏好和已经确认的硬约束；
- CanonicalClaimCandidate 表达预算、时间、否定和修订关系；
- Conflict Resolver 处理新旧方案冲突；
- Final Delivery Guard 检查终版手册是否完整交付。

## 实验边界

- 所有地点、价格和天气均为本地合成资料，不构成真实旅行建议；
- 旅游领域提示词只存在于实验配置，生产运行时不包含旅游词表或专用规则；
- 展示版描述问题设计，逐轮原始提示、状态示例和执行要求保存在
